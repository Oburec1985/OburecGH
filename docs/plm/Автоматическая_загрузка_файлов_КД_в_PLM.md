# Автоматическая загрузка файлов КД из папки в Appius-PLM

## 1. Назначение документа

Документ описывает рекомендуемый процесс разработки внешней обработки 1С, которая:

1. читает сценарий загрузки;
2. находит файлы конструкторской документации в папке на компьютере пользователя;
3. определяет соответствующий объект или документ в Appius-PLM;
4. передаёт файл с клиентского компьютера на сервер 1С;
5. создаёт либо обновляет файловое представление в PLM;
6. формирует журнал выполнения.

Документ составлен после анализа обработки `plm_ИмпортИзВнешнихИсточников.epf`.

## 2. Что подтверждено анализом исходной обработки

EPF была распакована в исходные BSL-модули. В ней реализованы следующие пригодные для повторного использования приёмы:

- чтение первого листа Excel через `COMОбъект("Excel.Application")`;
- чтение всех занятых строк и колонок листа;
- использование уровня группировки строки Excel (`OutlineLevel`) как уровня иерархии;
- перенос прочитанных данных в `ТабличныйДокумент`;
- преобразование табличного документа в `ТаблицаЗначений`;
- передача таблицы между клиентом и сервером через временное хранилище;
- поиск существующих элементов PLM по значениям параметров;
- создание элементов PLM через `Обработки.plm_СозданиеОбъектов`;
- работа со структурой изделия через XDTO-модель PLM;
- обработка ошибок создания объектов внутри транзакции.

Важное ограничение: исследованная обработка импортирует состав изделия и элементы КТС. В ней нет кода помещения двоичного файла КД в файловое хранилище PLM. Поэтому точное имя штатной процедуры Appius-PLM для создания версии файла необходимо определить в конфигурации конкретной установленной версии PLM.

## 3. Рекомендуемая архитектура

Логику следует разделить на пять независимых частей:

1. **Чтение сценария** — получает строки Excel и проверяет обязательные поля.
2. **Поиск файлов** — выполняется на клиенте, потому что папка находится на ПК пользователя.
3. **Сопоставление** — извлекает обозначение/ревизию из имени файла и находит объект PLM.
4. **Передача и запись** — клиент помещает файл во временное хранилище, сервер записывает его в PLM.
5. **Журналирование** — сохраняет результат каждой строки и каждого файла.

Нельзя объединять обход папки, поиск объекта PLM и запись файла в одну большую процедуру. Это затруднит повторный запуск, тестирование и диагностику.

## 4. Формат Excel-сценария

Для автоматической загрузки удобнее использовать одну строку на одно правило поиска.

| Колонка | Обязательная | Назначение | Пример |
|---|---:|---|---|
| `Включено` | да | Выполнять правило | `Да` |
| `Папка` | да | Полный путь на ПК пользователя | `D:\КД\На загрузку` |
| `Маска` | да | Маска файлов | `*.pdf` |
| `Рекурсивно` | да | Просматривать вложенные папки | `Да` |
| `ВидЭлемента` | да | Вид элемента/документа PLM | `Документ` |
| `ШаблонИмени` | да | Правило разбора имени файла | `{Обозначение}_{Ревизия}.pdf` |
| `ДействиеПриПовторе` | да | `Пропустить`, `НоваяВерсия`, `Заменить` | `НоваяВерсия` |
| `СоздаватьЕслиНет` | да | Разрешить создание объекта PLM | `Нет` |
| `ТипФайла` | нет | Тип представления/формата в PLM | `PDF` |
| `Комментарий` | нет | Комментарий к загрузке | `Автозагрузка КД` |

Рекомендуется не хранить в Excel пароли, имена серверов, строки подключения и внутренние идентификаторы пользователей.

### Вариант без Excel

Если сценарий не должен регулярно редактироваться инженером, надёжнее хранить настройки в регистре сведений 1С, а Excel использовать только для первоначального импорта. Это устраняет зависимость серверного задания от установленного Microsoft Excel.

## 5. Ограничение фонового режима

Регламентное задание на сервере 1С не видит произвольную локальную папку рабочего компьютера пользователя. Поэтому возможны два режима:

### Интерактивный запуск

Папка находится на ПК пользователя. Клиентская часть обработки перечисляет файлы и по одному передаёт их во временное хранилище 1С. Это наиболее близкий вариант к исследованной EPF.

### Полностью автоматический запуск

Файлы должны находиться в каталоге, доступном серверу 1С: сетевой папке UNC, серверном каталоге обмена либо специальном файловом сервисе. У учётной записи службы сервера 1С должны быть права чтения. Подключённый сетевой диск пользователя использовать нельзя; следует задавать UNC-путь вида `\\server\share\folder`.

Если требуется автоматическая обработка именно локальной папки ПК, нужен отдельный локальный агент, который отправляет файлы в 1С по HTTP-сервису. Одной серверной обработкой 1С это надёжно не решается.

## 6. Алгоритм обработки

### Шаг 1. Прочитать и проверить сценарий

- открыть книгу только для чтения;
- читать явно указанный лист, а не всегда `Sheets(1)`;
- проверить наличие обязательных заголовков;
- нормализовать логические значения и пути;
- проверить допустимость маски и политики повторов;
- закрывать книгу и Excel в блоке гарантированной очистки даже после ошибки.

Для нового модуля желательно отказаться от COM и читать `.xlsx` средствами табличного документа 1С, если формат и версия платформы это позволяют. COM требует установленного Excel и плохо подходит для фонового выполнения.

### Шаг 2. Найти файлы

- проверить существование папки;
- перечислить файлы по маске;
- при необходимости рекурсивно пройти вложенные папки;
- исключить временные файлы (`~$...`), нулевой размер и запрещённые расширения;
- отсортировать список, чтобы повторные запуски имели предсказуемый порядок.

### Шаг 3. Разобрать имя файла

Разбор имени должен быть отдельной функцией, возвращающей структуру:

```bsl
Новый Структура("Обозначение,Ревизия,Расширение", Обозначение, Ревизия, Расширение)
```

Не следует искать объект PLM по произвольному совпадению нескольких строк, как это делает исходная обработка для свойств. Для КД нужен однозначный ключ, например:

`Вид документа + Обозначение + Ревизия`.

Если найдено больше одного объекта, файл нельзя загружать автоматически: строка должна получить статус `Неоднозначное соответствие`.

### Шаг 4. Найти или создать объект PLM

Поиск выполняется на сервере запросом к данным PLM. Возможные результаты:

- найден ровно один объект — продолжить;
- объект не найден и создание запрещено — записать ошибку;
- объект не найден и создание разрешено — создать штатным API `plm_СозданиеОбъектов`;
- найдено несколько объектов — остановить обработку этого файла.

Создание объектов следует выполнять только через публичные процедуры Appius-PLM. Прямая запись в таблицы или непубличные регистры делает решение несовместимым с обновлениями PLM.

### Шаг 5. Проверить повторную загрузку

До передачи большого файла следует проверить, загружался ли он ранее. Практичный ключ идемпотентности:

`Ссылка объекта PLM + имя файла + размер + SHA-256`.

Политики:

- `Пропустить` — существующий идентичный файл не менять;
- `НоваяВерсия` — создать новую версию файлового представления;
- `Заменить` — применять только если это разрешено бизнес-процессом и правами PLM.

По умолчанию рекомендуется `Пропустить` для полного совпадения хеша и `НоваяВерсия` для изменившегося содержимого.

### Шаг 6. Передать файл клиент→сервер

Подтверждённый в исходной EPF шаблон передачи:

```bsl
&НаКлиенте
Процедура ПередатьФайлНаСервер(ПолноеИмяФайла, ДанныеСтроки)
    Адрес = "";
    ПоместитьФайл(Адрес, ПолноеИмяФайла, , Ложь);
    ЗаписатьФайлВPLMНаСервере(Адрес, ДанныеСтроки);
КонецПроцедуры

&НаСервере
Процедура ЗаписатьФайлВPLMНаСервере(Адрес, ДанныеСтроки)
    ДвоичныеДанные = ПолучитьИзВременногоХранилища(Адрес);
    // Здесь вызывается штатный API файлового хранилища вашей версии Appius-PLM.
КонецПроцедуры
```

Для новой платформы следует рассмотреть асинхронный API помещения файлов, чтобы интерфейс не зависал на больших объёмах.

### Шаг 7. Записать файл в PLM

Перед реализацией требуется найти в конфигурации Appius-PLM штатную процедуру, которая выполняет все необходимые действия:

- создаёт файловое представление или версию;
- записывает имя и расширение;
- сохраняет двоичные данные;
- связывает файл с объектом КД;
- устанавливает автора и дату;
- запускает предусмотренные PLM проверки и события.

Искать нужно по вызовам из стандартной формы ручного добавления файла в PLM. Удобная последовательность исследования:

1. открыть форму, которой пользователь вручную добавляет файл;
2. найти обработчик команды выбора/добавления файла;
3. проследить клиентский вызов до серверной экспортной процедуры;
4. определить обязательные параметры и возвращаемый результат;
5. проверить, создаётся ли новая версия либо изменяется текущая;
6. использовать тот же публичный вызов в автоматической обработке.

Точное имя этой процедуры нельзя достоверно получить из `plm_ИмпортИзВнешнихИсточников.epf`: файлового импорта в ней нет.

### Шаг 8. Зафиксировать результат

Для каждого файла журнал должен содержать:

- дату и время;
- правило сценария;
- полный исходный путь;
- размер и SHA-256;
- найденный объект PLM;
- созданную версию/представление;
- результат (`Загружен`, `Пропущен`, `Ошибка`);
- текст ошибки.

После успешной загрузки файл можно переместить в каталог `Обработано`, но только если это явно включено в настройках. Ошибочные файлы рекомендуется перемещать в `Ошибка` вместе с текстовым протоколом. Удалять исходные файлы автоматически не следует.

## 7. Каркас процедур обработки

```bsl
&НаКлиенте
Процедура ВыполнитьЗагрузку(Команда)
    Правила = ПрочитатьСценарийНаКлиенте(ПутьКСценарию);
    ОшибкиСценария = ПроверитьСценарий(Правила);
    Если ОшибкиСценария.Количество() > 0 Тогда
        ПоказатьОшибки(ОшибкиСценария);
        Возврат;
    КонецЕсли;

    Для Каждого Правило Из Правила Цикл
        Для Каждого ПутьКФайлу Из НайтиФайлыПоПравилу(Правило) Цикл
            ОбработатьОдинФайл(ПутьКФайлу, Правило);
        КонецЦикла;
    КонецЦикла;
КонецПроцедуры

&НаКлиенте
Процедура ОбработатьОдинФайл(ПутьКФайлу, Правило)
    Метаданные = РазобратьИмяФайла(ПутьКФайлу, Правило.ШаблонИмени);
    Проверка = ПроверитьНазначениеНаСервере(Метаданные, Правило);

    Если Не Проверка.МожноЗагружать Тогда
        ЗаписатьРезультат(ПутьКФайлу, Проверка.Статус, Проверка.Ошибка);
        Возврат;
    КонецЕсли;

    Адрес = "";
    ПоместитьФайл(Адрес, ПутьКФайлу, , Ложь);
    Результат = ЗагрузитьВPLMНаСервере(Адрес, Проверка.СсылкаPLM, Метаданные, Правило);
    ЗаписатьРезультат(ПутьКФайлу, Результат.Статус, Результат.Ошибка);
КонецПроцедуры
```

Функции `ПроверитьНазначениеНаСервере()` и `ЗагрузитьВPLMНаСервере()` должны выполнять только серверные операции. Функции обхода локальной папки и выбора файла должны оставаться клиентскими.

## 8. Транзакции и обработка ошибок

- один файл — одна короткая транзакция;
- двоичные данные нужно получить до начала транзакции;
- не следует держать транзакцию во время чтения Excel или обхода папки;
- ошибка одного файла не должна отменять уже успешно загруженные файлы;
- в `Исключение` обязательно выполнять `ОтменитьТранзакцию()`;
- пользователю показывать краткую ошибку, а в журнал сохранять подробное описание;
- после ошибки нужно удалять временные данные и продолжать со следующим файлом, если ошибка не системная.

## 9. Права и безопасность

Обработка должна проверять:

- право чтения исходной папки;
- право создания/изменения нужного вида объекта PLM;
- право добавления версии файла;
- допустимые расширения и максимальный размер;
- отсутствие обхода разрешённого корневого каталога через `..`;
- отсутствие исполняемых файлов, если они не разрешены политикой предприятия.

Не следует выполнять загрузку под полными правами только для обхода ошибок доступа. Нужна отдельная роль с минимально необходимыми правами.

## 10. План разработки

1. В тестовой базе определить штатный вызов ручного добавления файла Appius-PLM.
2. Утвердить ключ сопоставления файла и объекта КД.
3. Утвердить Excel-шаблон и политику повторов.
4. Реализовать чтение и валидацию сценария.
5. Реализовать поиск файлов и разбор имени без записи в PLM (`Пробный запуск`).
6. Реализовать однозначный поиск объектов PLM.
7. Подключить штатный API добавления файла.
8. Добавить идемпотентность, транзакции и журнал.
9. Протестировать на копии базы.
10. После приёмки настроить интерактивный либо серверный автоматический запуск.

## 11. Приёмочные тесты

Минимальный набор:

- папка отсутствует;
- папка пуста;
- файл не соответствует шаблону имени;
- объект PLM не найден;
- найдено два объекта;
- загружается новый файл;
- повторно загружается тот же файл;
- загружается изменённый файл с тем же именем;
- нет прав на объект PLM;
- нет прав на папку;
- файл занят другой программой;
- файл больше допустимого размера;
- обрыв связи клиент–сервер;
- ошибка одного файла не останавливает пакет;
- повторный запуск после частичного выполнения не создаёт дубликаты.

## 12. Что требуется уточнить перед написанием рабочего кода

Для готовой EPF необходимы четыре решения владельца системы:

1. версия Appius-PLM и конфигурации 1С;
2. где именно в PLM должен храниться файл: представление элемента, документ, версия/ревизия или присоединённый файл;
3. правило связи имени файла с объектом КД;
4. режим запуска: вручную с ПК пользователя, по расписанию с сервера 1С либо через локальный агент.

После этого можно заменить отмеченный в каркасе вызов штатного файлового API на конкретную процедуру и реализовать рабочую обработку.
