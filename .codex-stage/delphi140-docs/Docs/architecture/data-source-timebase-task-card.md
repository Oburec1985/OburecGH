# Техническое задание: короткий пример источников данных и единая временная база

## 1. Назначение

Доработать проект `Recorder/Devices/MIC-140` как компактный, рабочий и
расширяемый пример взаимодействия приложения с источниками измерительных
данных. Пример должен показывать полный путь без зависимости формы от типа
прибора:

```text
Bus -> Factory -> Dev -> DataSource -> Tag -> TDataVector -> Consumer
```

Основная задача доработки — сохранить уже созданные общие интерфейсы, добавить
единый контракт блока и временной базы для MIC-140, MIC-185 и будущих
источников, а приборные особенности оставить внутри соответствующего `Dev`.

Требуется совместимость временной семантики с оригинальным Recorder и WinПОС.
Нельзя вводить собственную схему смещений, даже если она выглядит логически
верной: записанные файлы должны обрабатываться так же, как файлы оригинального
Recorder.

## 2. Исходное состояние

В проекте уже есть нужный каркас, который следует развивать:

- `TCustomDevice` — общий жизненный цикл и строковые свойства;
- `IDataSource` / `TCustomDataSource` — источник и лениво запускаемый worker;
- `IMeasurementDataSource` — нейтральный интерфейс измерительного источника;
- `ITag` / `IBlockAccess` — публичный сигнал и чтение блоков;
- `TDataVector` / `TFifo` / `TFrame` — единственное кольцевое хранилище;
- `TDeviceBus`, `TDeviceFactory`, `TDeviceManager` — поиск, создание и владение;
- реализации MIC-140 и MIC-185 находятся только в своих каталогах `device`.

Подтверждённое расхождение: `TMIC140DataSource.DeviceDataBlock` вычисляет UTC
через `Now` и строит синтетический `fNextDeviceTime`, а MIC-185 DataSource также
назначает UTC по времени callback. Время доставки TCP-пакета или вызова callback
не является временем первого отсчёта и может использоваться только для
диагностики задержки.

## 3. Границы работы

### 3.1. Входит в работу

1. Общий тип блока измерений и метаданных времени.
2. Общий преобразователь аппаратного счётчика в непрерывную шкалу сессии.
3. Единая корреляция DeviceTime и UTS для всех приборов.
4. Работа без UTS по семантике оригинального Recorder.
5. Передача готового времени от `Dev` к `DataSource`, без расчётов в форме.
6. Короткий пример использования общих интерфейсов.
7. Тестовый источник без физического прибора и консольные тесты времени.
8. Документация контракта и сценария расширения новым устройством.

### 3.2. Не входит в первую реализацию

- изменение команд и формата протоколов MIC-140/MIC-185;
- перенос COM/ATL/MFC-кода оригинального Recorder;
- новый буфер истории рядом с `TDataVector`;
- переработка графиков, записи и всех форм одновременно;
- публикация внутренних служебных каналов как пользовательских тегов;
- вычисление времени по моменту прихода пакета, середине сетевого запроса или
  произвольной формуле времени ПК;
- пересоздание `Dev` или `DataSource` при обычном изменении настроек.

## 4. Требуемая архитектура

### 4.1. Общий блок захвата

Добавить `device/uAcquisitionTimebase.pas` либо разделить тип блока и mapper на
два небольших модуля, если один модуль перестанет помещаться на одном экране.
Минимальный контракт:

```pascal
type
  TAcqTimeMeta = record
    SessionGen: UInt64;
    Sequence: UInt64;
    RawFirstCounter: Cardinal;
    FirstTimeSec: Double;
    FirstUTSTime: Double;
    UTSValid: Boolean;
    Discontinuity: Boolean;
    State: Cardinal;
  end;

  TAcqBlock = record
    ChannelCount: Integer;
    SampleCount: Integer;
    SampleRateHz: Double;
    ChannelSampleCounts: TArray<Integer>;
    ChannelFirstTimesSec: TArray<Double>;
    ChannelSampleRatesHz: TArray<Double>;
    Time: TAcqTimeMeta;
    Values: TArray<TArray<Double>>;
  end;
```

Имена допустимо привести к соглашениям проекта. Семантика полей обязательна:

| Поле | Смысл |
| --- | --- |
| `Time.FirstTimeSec` | DeviceTime первого отсчёта общего блока |
| `Time.FirstUTSTime`, `UTSValid` | абсолютное время первого отсчёта и признак его валидности |
| `Time.SessionGen`, `Sequence` | поколение сессии и монотонный номер блока в ней |
| `Time.RawFirstCounter` | исходный младший аппаратный счётчик для диагностики и теста unwrap |
| `Time.Discontinuity`, `State` | разрыв временной оси и состояние данных |
| `SampleRateHz` | общая частота, если она одинакова у каналов |
| `ChannelSampleCounts` | фактическое число отсчётов каждого канала |
| `ChannelFirstTimesSec` | время первого отсчёта с учётом фазового сдвига канала |
| `ChannelSampleRatesHz` | поканальная частота при неодинаковых режимах |
| `Values` | значения после аппаратной ГХ и компенсации, но до канальной ГХ тега |

Пустой поканальный массив означает использование общего поля. Если числа
отсчётов каналов различаются, `SampleCount` равен 0, а
`ChannelSampleCounts` является обязательным источником истины. Непустой
поканальный массив обязан иметь длину `ChannelCount`; это проверяется до
публикации. Нужны короткие функции `GetChannelSampleCount`, `GetChannelRate`,
`GetChannelFirstTime`, `GetSampleTime`, а также явные `Prepare`, `Clear` и
`Copy`. `GetSampleTime` вычисляется как:

```text
ChannelFirstTime + SampleIndex / ChannelRate
```

Образцом семантики, но не источником для слепого копирования, служит
`RecorderLnx/Device/uRecorderAcquisitionTypes.pas`.

Владение должно быть однозначным: `Dev` владеет и переиспользует массивы блока;
callback `Dev -> DataSource` синхронный, а view блока действителен только до
возврата из callback. `DataSource` не сохраняет ссылки на `Values` и выполняет
ровно одно блочное копирование в принадлежащее тегу кольцо `TDataVector`.
Consumer получает snapshot через `IBlockAccess` и не удерживает внутренний
массив producer.

### 4.2. Ответственность слоёв

| Слой | Обязанность | Запрещено |
| --- | --- | --- |
| `Bus` | найти endpoint и вернуть `TFoundDeviceInfo` | Connect, Configure |
| `Factory` | создать подходящие `Dev` и `DataSource` | приборный I/O |
| `Dev` | протокол, декодирование, аппаратное время, физические преобразования | VCL, поиск тегов |
| `DataSource` | принять готовый блок и опубликовать его в заранее связанные теги | `Now`, синтетическая временная ось, приборные cast из UI |
| `Tag` | канальная ГХ, оценки и единый `TDataVector` | второй буфер истории |
| Consumer | читать блоки по cursor/generation | доступ к внутренним массивам `Dev` |
| Controller | выполнить линейный сценарий приложения | декодировать пакеты или считать время |
| Form | ввод, команды controller, отображение интерфейсов | `uMIC140Dev`, `uMIC185Dev`, приборные ветки |

`IDataSource.GetDevice` пока оставить для совместимости, но форма и visual-код
не должны им пользоваться. Новые данные состояния выдавать через общий
интерфейс/снимок диагностики, а не через downcast.

### 4.3. Жизненный цикл

Единственная допустимая последовательность:

```text
Discover -> Connect -> Initialize -> Test/Refresh -> Configure
         -> Start -> Stop -> Disconnect
```

- `Connect` создаёт одну постоянную транспортную сессию.
- `Initialize` выполняется один раз на поколение соединения.
- `Configure` идемпотентно применяет только изменённую конфигурацию.
- `Start` и `Stop` не вызывают повторно `Initialize` и неизменённый `Configure`.
- изменение Fs, диапазона или периода обновления выполняется на существующих
  объектах: `Stop -> SetProperties -> CalcProps -> Configure -> Start`.
- `Reset` закрывает старую сессию и начинает полный жизненный цикл.
- ожидаемые ошибки возвращаются как `TDeviceResult`, а не exception.

Размер логического блока пересчитывается до запуска:

```text
BlockSamples = Round(Fs * UpdatePeriodMs / 1000)
```

Перед `Configure` результат обязан быть целым с допустимой для выбранного
режима точностью, больше нуля и не больше заранее подготовленной capacity.
Если устройство поддерживает сочетание Fs/period с дробным числом отсчётов,
политика накопления дробного остатка должна быть отдельной общей стратегией с
тестом долговременного темпа; молчаливое округление каждого блока запрещено.

## 5. Единая временная база

### 5.1. Общие правила

1. `DeviceTime` блока — время его первого отсчёта, а не последнего отсчёта и не
   момент callback.
2. Для счётчика в заголовке, указывающего позицию после блока:

   ```text
   FirstSample = HeaderSampleCount - SamplesInBlock
   FirstTimeSec = FirstSample / Fs
   ```

3. 32-битный аппаратный счётчик разворачивается в 64-битный в пределах одной
   сессии. Переполнение отличать от сброса/разрыва.
4. Потеря пакета или сброс счётчика создаёт discontinuity. Источник не должен
   незаметно склеивать разрыв синтетическим `nextTime`.
5. Разные приборы используют один общий mapper и одинаковую семантику полей.
6. Timestamp приёма пакета сохраняется только в диагностике и метриках latency.

### 5.2. Канальные фазовые сдвиги

Если АЦП опрашивает каналы последовательно, `ChannelFirstTimesSec` обязан
учитывать порядок активного канала. Для MIC-185 использовать формулу и порядок,
подтверждённые оригинальной реализацией:

```text
channelOffset = sampleTime * activeChannelOrder - midADC - 75 us
sampleTime = (GndCommut + 10) + (ChnCommut + 10) + 2 * 2^Avg + 10
```

Единицы промежуточных величин привести к секундам в одном именованном helper.
Запрещено размазывать эту формулу по decoder, DataSource и writer.

### 5.3. Работа с UTS

Для опорной точки UTS:

```text
Xuts = (Sev_CLK - Start_CLK) / CLK
Yuts = абсолютное время UTS, секунд
AbsoluteTime(sample) = Yuts + (DeviceTime(sample) - Xuts)
```

Корреляция принадлежит общему session timebase. Отдельный UTS callback обновляет
опорную точку; обычный измерительный блок получает `FirstUTSTime` только если
корреляция валидна. Невалидное UTS-время представлять одним документированным
sentinel/флагом, а не числом, которое можно принять за 1970 год.

### 5.4. Работа без UTS

Без UTS `Start`/`DeviceTime` вычисляется только по аппаратному счётчику первого
отсчёта и поканальному фазовому сдвигу:

```text
Start = FirstSampleCounter / Fs + ChannelOffset
```

`Start = 0` является допустимым значением, если счётчик и сдвиг равны нулю.
Время команды записи ПК, время callback и момент прихода TCP-пакета не являются
источником `Start`.

Календарные `Date`/`Time` кадра являются метаданными открытия записи. Они не
прибавляются к `Start`. Для MERA-файла:

- обычный канал хранит относительный `Start` первого отсчёта;
- UTS хранит X явно в своём XY-представлении и не требует собственного `Start`;
- `UTS_Channel` связывает относительную шкалу сигнала с абсолютной UTS-шкалой.

Эта формула подтверждена для исследованного пути MIC-185. Перед переносом на
MIC-140 его аппаратный счётчик и фазовую модель требуется подтвердить первичными
исходниками оригинального Recorder; отсутствие такого подтверждения является
research gate и блокирует изменение MIC-140 timebase.

## 6. MIC-140: служебные каналы и физический тракт

Для термокомпенсации TIn должны считываться и обрабатываться независимо от того,
созданы ли для них пользовательские теги:

1. При `Configure` определить layout, прямые индексы и аппаратные ГХ всех TIn.
2. При каждом готовом блоке сначала обновить валидную температуру холодного спая.
3. Затем преобразовать основные AIn.
4. Публиковать только настроенные пользовательские теги; скрытые TIn-теги не
   создавать.
5. Если в текущем блоке нет валидного TIn, не использовать молча устаревшее
   значение; выставить диагностическое состояние канала.
6. При включении термокомпенсации без аппаратной ГХ TIn показать предупреждение
   и предложить прочитать ГХ из памяти модуля.

Обязательный порядок преобразований:

```text
код АЦП -> аппаратная ГХ -> компенсация -> канальная ГХ -> Tag
```

Флаг использования аппаратной ГХ относится к тегу. Источник владеет фактическим
режимом и единицами аппаратного канала. При `Auto` выключение аппаратной ГХ
переводит отображение в коды, включение — в физические единицы источника.
На первом этапе требуется оформить отдельный pipeline/adapter contract: тег
передаёт выбранный режим аппаратной ГХ в заранее подготовленный тракт, но не
пересоздаёт `Dev`/`DataSource` и не ищет ГХ в runtime. Это сохраняет порядок
`hardware GX -> compensation -> channel GX` и устраняет двойное применение ГХ.

## 7. Производительность и память

- Все блоки, поканальные массивы, кольца, связи тегов, ГХ и коэффициенты
  подготавливаются при `Configure` или изменении конфигурации.
- В steady state допускается ноль управляемых выделений памяти на блок.
- В цикле запрещены `SetLength`, создание объектов, поиск тегов/ГХ по строке,
  разбор property и форматирование подробного лога.
- Данные обрабатываются логическими блоками, а не сетевыми пакетами и не
  отдельными отсчётами.
- На границе producer -> tag допускается одно блочное копирование в
  принадлежащее `TDataVector` кольцо. Дополнительная история запрещена.
- Уведомление сообщает о новом generation/sequence и не несёт копию массива.
- При отсутствии данных worker ждёт; UI обновляет только видимые изменившиеся
  компоненты.
- Сетевой I/O и тяжёлая обработка выполняются вне общей критической секции.
- Логирование в runtime: ошибки, смена состояния, начало/конец разрыва и редкие
  итоги; не логировать каждый пакет или блок в штатном режиме.

Обязательные счётчики: `received`, `decoded`, `published`, `dropped`, `overrun`,
`discontinuity`, а для диагностики времени — packet latency и возраст UTS anchor.

## 8. Короткий пример приложения

Добавить `Examples/DataSource` без второй реализации core:

```text
Examples/DataSource/
  DataSourceExample.dpr
  uAcqController.pas
  FrmDataSourceExample.pas/.dfm  (или console view без VCL)
  README.md
```

`uAcqController` — единственная композиционная точка с короткими методами:

```text
Search -> Select -> ConnectAndPrepare -> ApplyProps -> Play -> Stop -> Close
```

Он использует существующие `TDeviceManager`, фабрики и общие интерфейсы.
Форма получает `IMeasurementDataSource`, `ITag` и `TDeviceResult`. В `uses` формы
не должно быть `uMIC140Dev`, `uMIC185Dev`, `uMIC140Types` или `uMIC185Types`.

Сценарий примера:

1. Зарегистрировать шину и фабрики MIC-140/MIC-185.
2. Найти устройства и выбрать `TFoundDeviceInfo`.
3. Создать `Dev` через manager/factory.
4. Выполнить `Connect -> Initialize -> Refresh`.
5. Передать `Fs`, диапазон и период через имена из `uDevProps`, проверить весь
   набор и вызвать `Configure`.
6. Создать `IDataSource` через фабрику и получить
   `IMeasurementDataSource`.
7. Запустить `Play`, читать generation тега, копировать snapshot только при его
   изменении.
8. Выполнить `Stop`, затем выключить UI timer, освободить source, вызвать
   `Disconnect` и освободить manager.

Для запуска без стенда нужна `TFakeMeasurementDataSource`, реализующая те же
интерфейсы и публикующая детерминированные блоки с известными DeviceTime/UTS.
Она используется только примером и тестами, а production-код не должен иметь
веток `if fake`.

## 9. План реализации атомарными этапами

1. **Контракт.** Добавить тип блока, timebase API и unit-тесты без подключения
   к приборам.
2. **MIC-185 decoder.** Передать raw first/end counter и готовые метаданные;
   проверить wrap, gap и phase offset. DataSource перестаёт использовать `Now`.
3. **UTS.** Добавить общий anchor/correlation и тесты на задержку прихода UTS.
4. **Режим без UTS.** Реализовать исходную точку записи по правилам оригинального
   Recorder и проверить сохранённый `Start`.
5. **MIC-140 decoder.** Перевести блоки на тот же контракт, не меняя команды
   протокола и порядок физической обработки.
6. **Служебные TIn.** Обеспечить внутреннее чтение/ГХ/компенсацию без публикации
   лишних тегов.
7. **Короткий пример.** Добавить controller, fake source и нейтральный UI.
8. **Интеграция.** Подключить writer/consumer, документацию и выполнить
   межприборную проверку.

Каждый этап — отдельная проверяемая правка. Нельзя одновременно менять
протокол, lifecycle, буферы, ГХ и UI, если это не минимальные изменения одного
контракта.

## 10. Проверки и критерии приёмки

### 10.1. Без аппаратуры

| Проверка | Критерий |
| --- | --- |
| Общий UI | одинаково работает с fake, MIC-140 и MIC-185 через фабрику и интерфейсы, без device cast |
| Lifecycle | два `Play/Stop`: `Connect=1`, `Initialize=1`, `Configure=1`, `Start=2`, `Stop=2` |
| Reconfigure | `ApplyProps` меняет существующие объекты; `Dev` и `DataSource` не пересоздаются |
| Размер блока | при 100 Гц и 200 мс получено 20 отсчётов |
| Время блока | время соответствует первому отсчёту; callback delay не меняет результат |
| Wrap | переход 32-битного счётчика разворачивается без скачка назад |
| Gap/reset | разрыв помечен и не склеен с предыдущим блоком |
| UTS | известный anchor даёт ожидаемое абсолютное время с точностью до 0,5 отсчёта |
| Без UTS | `Start` численно совпадает с эталонным файлом оригинального Recorder для тех же counters/phase, включая законный `Start=0` |
| Канальная фаза | сдвиг соответствует активному порядку каналов |
| Несколько приборов | ошибка одного источника не останавливает остальные |
| Consumer | без нового generation нет копирования и перерисовки |
| Память | после 100 блоков прогрева следующие 1000 блоков дают allocations/block = 0 по FastMM FullDebugMode/профилировщику; breakpoint/counter подтверждает, что runtime-ветви `SetLength` не исполнялись |
| TIn | термокомпенсация одинакова с публичными TIn-тегами и без них; скрытые теги не появились |
| Ошибки | timeout/offline возвращают `TDeviceResult`, приложение не падает на ожидаемом exception |

### 10.2. С аппаратурой

1. MIC-140 и MIC-185 отдельно: `Search -> Connect -> Read -> Configure -> Play`.
2. Два прибора с разной задержкой запуска: сравнить относительное положение
   первых отсчётов с оригинальным Recorder.
3. Запись с UTS и без UTS: сравнить `Date`, `Time`, `Start`, UTS X/Y и
   `UTS_Channel` в MERA-файлах.
4. MIC-140: проверить термокомпенсацию при отсутствии публичных TIn-тегов,
   при наличии/отсутствии аппаратной ГХ и при пропадании TIn.
5. Изменить Fs/диапазон без пересоздания объектов и повторить `Play`.
6. Отключить один прибор во время работы; остальные продолжают сбор.

### 10.3. Сборка и ревью

- forced build Win32 и Win64 в Delphi 2020, exit code 0;
- отдельный console test timebase без сети;
- тест example с fake source;
- аппаратные тесты не подменять безаппаратными;
- обязательные независимые вердикты: `ARCHITECTURE`, `RUNTIME`, `LOGGING`,
  `COMPLIANCE`, `QA`;
- после каждого этапа обновлять `iteration-log.md`.

Для `Reconfigure` отдельно проверить счётчики: после первого запуска и одного
изменения свойств `Connect=1`, `Initialize=1`, `Configure=2`; идентичности `Dev`
и `DataSource` сохранены, capacity и размер блока пересчитаны. Повторная передача
неизменённого набора свойств не вызывает `Configure` и сетевых записей.
