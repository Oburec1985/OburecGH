# Спектральный график возвращался к MemTag после OK

## Симптом

В настройках спектрального графика пользователь добавлял входной канал, но
после подтверждения компонент снова отображал `MemTag`.

## Подтверждённая причина

`TRecorderSpectrumSettingsDialog.StoreToComponent` очищал только `TagNames`.
Массив `TagIds` сохранял прежние значения, если число строк не менялось. После
выбора нового имени на том же индексе оставался ID старого `MemTag`, а
`ResolveTagAt` штатно отдаёт приоритет стабильному ID и восстанавливал MemTag.

Подпись списка дополнительно содержит частоту (`Имя (57600 Hz)`), поэтому она
не должна использоваться как идентификатор связи.

## Исправление

- Перед записью списка очищаются и имена, и ID.
- Каждая строка сохраняется через `SetTagRefAt` как согласованная пара
  `TagId + TagName`; частота остаётся только отображаемой подписью.
- Проверка дубликатов сравнивает реальные имена тегов, а не форматированный
  текст строки.
- Список доступных каналов строится из входных привязок
  `SpectrumConfigs`, поэтому обычные теги, не добавленные в спектральный
  алгоритм, в него не попадают.

## Проверка

Forced-сборка `RecorderLnx.lpi` от 23.09.2026 завершена с exit code 0;
`git diff --check` для изменённого диалога ошибок не обнаружил.
