# Recorder command ImageList: устаревший exe содержал 74 вместо 77

## Симптом

При запуске RecorderLnx открывался аварийный диалог: `ImageList contains 74
icons; expected at least 77`, с предложением продолжить с риском повреждения
данных или завершить программу.

## Первичная причина

- `CRecorderCommandImageCount = 77`, а индексы новых 3D-команд — 74..76.
- Ранее `UI/uMainForm.lfm` действительно содержал 74 изображения.
- `uRcIconIds.pas` объявляет индексы `CIcon3dRotateX..Z = 74..76` и общий
  `CRecorderCommandImageCount = 77`.
- `FormCreate` проверял встроенный список, в котором было 74 элемента вместо
  требуемых 77.
- Полная регенерация раньше перезаписывала пользовательскую иконку MeraBase
  на индексе 73, поэтому её вызов на старте был правильно запрещён.

## Исправление ресурса и генератора

Контракт индексов расширили до 77 без синхронного обновления LFM. Генератор
исправлен так, чтобы обходить зарезервированный index 73, а штатный
`Tools/EmbedCommandImages` записал 77 элементов в `UI/uMainForm.lfm`. Startup
сохраняет строгую проверку и не изменяет ресурс во время работы.

`Replace3dToolbarIcons` теперь обходит зарезервированный индекс 73, поэтому
генерация не портит пользовательскую иконку MeraBase. `Tools/EmbedCommandImages`
записал актуальный список в LFM; проверка также выполняет только на копиях
ресурсов и выводит фактический счётчик до/после.

## Повторная проверка 2026-10-14

- Обе формы (`UI/uMainForm.lfm` и дублирующий `uMainForm.lfm`) загрузились через
  LCL с фактическим Count=77; генерация оставила Count=77.
- LCL smoke: `PASS: ImageList 74 -> 77; icon 73 preserved`.
- Полная forced-сборка с выходом `RecorderLnx-smoke.exe` прошла: 214061 строк,
  exit code 0. Стандартный `RecorderLnx.exe` не удалось перелинковать, потому что
  он занят работающим процессом PID 11256 (Windows error 5).
- Открытие smoke exe не проверено: рядом уже работает RecorderLnx, поэтому
  запуск второго экземпляра завершился с кодом 0 без создания отдельного окна.

## Остаточный риск

Текущий процесс/установленная копия может оставаться старым бинарником с 74
иконками. Чтобы проверить GUI отдельным окном и обновить штатный EXE, сначала
нужно закрыть уже запущенный процесс; мы его не завершали, чтобы не прерывать
работу пользователя.

## Повторное появление диалога

После нового снимка подтверждено, что активный процесс запущен из
`lib/x86_64-win64/RecorderLnx.exe`; на момент проверки этот файл был собран
раньше отдельной проверочной сборки. Текущий `UI/uMainForm.lfm` уже содержит
ресурс на 77 изображений, а проверочный smoke по-прежнему проходит с
результатом `ImageList 74 -> 77; icon 73 preserved`.

Для устранения неопределённости принудительно собран свежий
`lib/x86_64-win64/RecorderLnx-imagecheck.exe` из текущих исходников; полная
сборка успешна. Работающий стандартный EXE не перезаписывался и не завершался.
Пока пользовательская копия продолжает показывать 74, наиболее вероятна
устаревшая встроенная LFM-форма в запущенном EXE; подтвердить запуском новой
копии отдельно нельзя, пока активен single-instance процесс.

## Подтверждённая причина пустой оболочки

На последующем снимке заголовок приложения показывает 0.1.163, а в окне
исключения были инструкции нажать OK для игнорирования ошибки. Проверка
ImageList в `FormCreate` выполняется до `EnsurePageControl` и загрузки страниц;
при игнорировании исключения оставшаяся часть `FormCreate` не выполняется.
Это непосредственно объясняет оболочку с кнопками «Теги/Сообщения» и пустой
таблицей. Это не дефект текущего рендера мнемосхем.

Актуальная локальная версия 0.1.164 прошла image-list smoke на 77 элементов;
журнал её старта фиксирует семь загруженных страниц и отрисовку `Mnemonic7`.
Удалённую копию этим расследованием не обновляли.
