# 3D Skin: векторный тег не привязывался к кости

## Симптом

Канал генератора с ненулевой частотой опроса не показывался в списке тегов
координат кости. Даже сохранённая вручную привязка такого канала не работала.

## Причина

Редактор Skin и runtime-адаптер независимо отбрасывали любой тег с
`IsVector=True`. Кроме того, привязка имела единственный неявный способ чтения —
последний отсчёт буфера — и не позволяла использовать настроенную оценку тега.

## Исправление

- Скалярные и векторные теги допускаются в поиске и при runtime-разрешении.
- Для каждой оси кости хранится режим `Текущее значение` или
  `Оценка по умолчанию`.
- Текущее значение читается как последний отсчёт `SignalBuffer`.
- Оценка читается из кэша по `EstimateSettings.DefaultKind`; при неготовой
  оценке положение кости не меняется.
- Режимы сохраняются в проекте; старые проекты получают режим текущего значения.
- В горячем обновлении нет поиска тегов по имени и нет выделений памяти.

## Проверка

`RecorderFormModelTest` проверяет векторный канал `[1,2,3,4]`: последнее значение
равно `4`, оценка по умолчанию `tekMean` равна `2.5`, а режим оценки проходит
сохранение/загрузку проекта. Forced-сборка `RecorderLnxDragVerify.lpi` успешна.
Основная `RecorderLnx.lpi` дошла до линковки, но запущенный RecorderLnx удерживал
целевой EXE (Windows error 5).
