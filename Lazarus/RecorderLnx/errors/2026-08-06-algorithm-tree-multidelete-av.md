# Ошибка пакетного удаления узлов алгоритмов

## Симптом

После удаления второго выбранного узла спектрального алгоритма возникал Access Violation в `DeleteSelectedAlgorithms` на проверке типа `TRecorderSpectrumConfigNode`.

## Причина

Первый проход вызывал `DeleteBinding`, который освобождал `TRecorderSpectrumTagBinding`. Второй проход повторно читал сохранённый `TTreeNode.Data` и выполнял RTTI-проверку уже освобождённого объекта.

## Исправление

- До изменения модели отдельно сохраняются указатели выбранных привязок и конфигурационных узлов.
- После начала удаления `TTreeNode.Data` больше не читается.
- Если выбран родительский алгоритм, выбранные дочерние привязки отдельно не удаляются.
- Удаление выполняется с конца модельных списков.
- В `.lfm` включён `tvoAllowMultiselect`.
- При применении/подтверждении конфигурации удаляются теги `Spectrum estimate`, чей устойчивый `SourceId = spectrum:<исходный тег>` больше не используется ни одной привязкой.

## Проверка

Полная компиляция исходников `lazbuild -B RecorderLnx.lpi` проходит до линковки без ошибок компилятора. Линковка текущего запуска заблокирована активной отладочной сессией Lazarus, удерживающей `RecorderLnx.exe` (`error code 5`).
