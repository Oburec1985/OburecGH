# Экспорт в SDB терял тип ГХ

## Симптом

После экспорта масштабного множителя в БД ГХ и повторного выбора он открывался
как таблица интерполяции из двух точек `(0, 0)` и `(1, k)`.

## Причина

Экспорт сохранял только совместимый legacy CSV/XML. В этом представлении
масштаб аппроксимировался двумя точками, а JSON с типом и исходными параметрами
не создавался. Импорт без JSON закономерно распознавал файл как таблицу.

## Исправление

- `scale`, `linear`, `table` и `polynomial` представлены разными значениями enum;
- экспорт SDB после legacy-файлов атомарно пишет и проверяет JSON sidecar;
- импорт сначала читает JSON и поэтому восстанавливает исходный тип;
- редактор формульных ГХ сохраняет коэффициенты и пересчитывает их при смене
  единиц входа/выхода;
- legacy CSV остаётся для совместимости со старым Recorder.

## Правило предотвращения

Нельзя определять тип ГХ по количеству точек. При любом обмене надо сохранять
явный discriminator типа и проверять round-trip всех типов отдельно. Двухточечная
таблица не должна автоматически считаться масштабом или прямой.

## Проверка

Forced Windows/Linux build завершились с exit code 0. Linux ELF проверен на
зависимости (`MISSING_LIBS: none`). DEB 0.1.68 установлен на MIC-200:
1 succeeded, 0 failed; RecorderLnx запущен через HostAgent.
