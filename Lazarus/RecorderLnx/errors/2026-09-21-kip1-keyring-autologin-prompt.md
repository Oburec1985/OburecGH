# KIP: запрос разблокирования GNOME Keyring при каждом автологине

## Симптом

После автоматического входа Fly-DM появляется окно «Требуется аутентификация» для связки ключей «Вход».

## Подтверждённые факты

- Fly-DM использовал `AutoLoginEnable=true` и `AutoLoginUser=user`, но пароль автологина не был задан.
- PAM содержит `pam_gnome_keyring.so`, однако при беспарольном автологине ему нечего передать для разблокирования связки.
- В `login.keyring` была одна сохранённая запись; служба `org.gnome.keyring.SystemPrompter` запускала парольный диалог.
- Простая замена `login.keyring` пустым файлом не работает: файл имеет недопустимый формат.
- Передача `LF` как «пустого пароля» создаёт связку фактически с однобайтовым паролем перевода строки и не решает следующую загрузку.
- При передаче секрета из PowerShell в Linux через stdin необходимо удалить завершающий `CR`; иначе восьмизначный пароль становится девятибайтовым.

## Исправление

Старая связка сохранена в резервной копии. Новая связка создана штатным `gnome-keyring-daemon` с тем же паролем, что у пользователя. Fly-DM настроен передавать `AutoLoginPass` PAM; файл `/etc/X11/fly-dm/fly-dmrc` принадлежит root и имеет режим `0600`.

LinuxSetupManager получил отдельную функцию смены системного пароля. Секрет читается из stdin, не попадает в argv/environment/журнал; синхронизация Fly-DM выполняется только после явного согласия. Master-password GNOME Keyring автоматически не меняется: при его несовпадении требуется интерактивная смена либо резервное копирование и пересоздание связки.

## Проверка

- После реальной перезагрузки KIP-1 Fly-DM выполнил автологин пользователя.
- Secret Service показывает связку «Вход» как `locked=false`.
- В журнале текущей загрузки отсутствует `starting password prompt`.
- Конфигурация Fly-DM имеет владельца `root:root`, режим `0600`, длина пароля проверена без вывода значения.

## Правило профилактики

При включённом Fly-DM autologin и защищённой GNOME Keyring пароль автологина, Unix-пароль и пароль `login.keyring` должны совпадать. Передавать пароль только через stdin; после Windows→Linux передачи удалять один завершающий `CR`. Проверять исправление только после перезагрузки: автологин активен, Keyring `locked=false`, SystemPrompter не запускался.
