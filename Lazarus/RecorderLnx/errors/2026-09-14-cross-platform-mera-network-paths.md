# Кроссплатформенное открытие MERA из SQL-событий

## Требуемое поведение

- RecorderLnx публикует выбранный каталог замеров как стабильный SMB-ресурс.
- Каталог может находиться в любом месте файловой системы.
- Windows Recorder вправе передавать уже готовый UNC-путь.
- RecorderLnx и rcPanel разрешают один контракт пути на Windows и Linux.
- На Linux отдельная утилита подключает ресурс по хосту, имени SMB-папки и
  локальному названию.

## Подтверждённые факты

- Поле «Рабочий каталог» сохраняется как `RecordRootDir` и является корнем,
  под которым Recorder создаёт каталоги кадров.
- SQL schema уже связывает запись с `recorder_instance_id`, хранит
  `relative_name`, а опубликованный адрес файла — в `data_file_locations.path_key`.
- Текущий диалог SQL-события рассматривает `path_key` как локальное имя файла
  и вызывает `FileExists`/`OpenDocument`; сетевого разрешения пока нет.
- Существующий ресурс `Obmen` не содержит каталоги замеров и не может разрешить
  пути вида `/home/user/Mera Files/usml/...`.

## Принятый контракт

Публикуемый ресурс имеет стабильное имя, а его корень можно перепривязывать к
любому локальному каталогу. В SQL публикуется переносимый сетевой путь или URI,
содержащий хост, ресурс и путь относительно опубликованного корня. Прямой
Windows UNC-путь остаётся допустимым вариантом. Клиентский менеджер сначала
проверяет прямой путь, затем UNC, затем локальное Linux-монтирование ресурса.

## Сетевое обнаружение

Доступность `smb://host/share` не означает появление хоста в графическом
«Сетевом окружении». Для списка компьютеров нужны объявления NetBIOS либо
WS-Discovery (`wsdd`); это отдельный слой поверх Samba.

Для предотвращения повторения SMB-диалог теперь показывает пользователей и
галочки доступа к каждой управляемой публикации. Изменение прав сохраняет
других пользователей, проверяет временный `smb.conf` через `testparm` и при
ошибке reload восстанавливает исходный файл. Проверка на MIC-200: пользователь
`mera`, ресурс `MeraFiles`, доступ `True`.

## Правило публикации SMB и файловых прав

Разрешение в `valid users` не доказывает доступ к каталогу. При публикации для
конкретного пользователя обязательно проверять Samba-учётку и фактическое
чтение каталога от его имени. Недостающие права добавлять ACL чтения и прохода,
не меняя владельца и не удаляя существующие права; для каталогов задавать ACL
по умолчанию для новых файлов. Проверка — чтение ресурса через Samba под тем же
пользователем и отображение доступа в `smb access`.

Все точки входа публикации — GUI, CLI и совместимый системный helper — обязаны
вызывать один встроенный обработчик. Нельзя держать отдельный shell-код с
захардкоженным `valid users`: повторный вызов молча отменяет выбранного
пользователя и выглядит на Windows как неверный пароль. После установки пакета
проверять эффективные `valid users` и `read only` через `testparm`, затем
выполнять реальное чтение/запись по SMB.
