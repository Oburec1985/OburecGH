# 2026-09-14 — расхождение расчёта с контрольным XLSX

## Симптом

Для `e1=0`, `e2=1`, `e3=1`, `nu=0.3` Excel показывает
`sigma1=0.251643`, `sigma2=0.034071`, `angle=-22.5°`, а RecorderLnx —
`0.264`, `0.036`, `67.5°`.

## Подтверждённые факты

- XLSX использует `E=0.2 * 10^6 = 200000 MPa`; RecorderLnx хранит для
  проверенного проекта и использует по умолчанию `E=210000 MPa`.
- При одинаковом `E=200000` формулы напряжений RecorderLnx и XLSX дают
  одинаковые результаты. Разница на скриншоте равна коэффициенту `1.05`.
- XLSX считает угол как `0.5*ATAN(gamma/(e1-e3))`, поэтому теряет четверть.
  RecorderLnx использует `0.5*ArcTan2(gamma,e1-e3)` и для данного примера
  получает направление максимального главного напряжения `67.5°`.
- RecorderLnx дополнительно прибавляет `PositionDeg`, а при отсутствии данных
  показывает `PositionDeg` вместо расчётного угла. После уточнения пользователя
  это неверная семантика поля «Угол»: в нём должен быть только результат
  расчёта, не монтажное положение.

## Статус

Причины найдены. Код не менялся: пользователь запросил проверку расхождения.
