# Полосы спектра скрывались из-за нерабочего первого канала

## Симптом

В Linux частотные полосы присутствовали в конфигурации, но не отображались в
компоненте спектра. Часть входных каналов не рассчитывалась из-за неверных
путей источников, при этом один из последующих каналов исправно выдавал спектр.

## Причина

`TRecorderSpectrumView.RefreshControl` безусловно очищал полосы страницы и
строил их только из `fBufferedFrames[0].Bands`. Если первый настроенный канал
не получал данных, его массив полос был пуст, хотя последующие кадры содержали
валидные результаты.

## Исправление

Для общих полос выбирается первый реально рассчитанный спектральный кадр
(`Length(Rms) > 0`) с приоритетом кадра, содержащего `Bands`. Нерабочий канал
больше не подавляет визуализацию результатов остальных каналов.

## Проверка

- Полная сборка Windows `RecorderLnx.lpi`: exit code 0.
- Полная сборка Linux в Astra VM: exit code 0.
