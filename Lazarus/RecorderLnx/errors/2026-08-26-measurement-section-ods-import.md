# 2026-08-26 — импорт ODS измерительного сечения

## Симптом

Импорт сечения из `recorder_tags.ods` визуально не давал результата.

## Подтверждённые факты

- Файл прочитан vendored `fpspreadsheet`: лист `Recorder_Tags`, 273 строки.
- Заголовки и строки сечения корректны: для сечения `1` присутствуют роли
  `e1/e2/e3/t`, номера точек, имена и ID каналов.
- `GetLastColIndex(True)` возвращает `16383`, потому что LibreOffice записал в
  ODS повторяющийся пустой хвост `table:number-columns-repeated="16366"`.
- Старый поиск каждого отсутствующего необязательного заголовка обходил весь
  ложный диапазон и не сообщал пользователю результат импорта.

## Исправление

- Поиск заголовков ограничен первыми 256 столбцами таблицы.
- Импорт выбирает лист `Recorder_Tags`, проверяет обязательные заголовки и не
  подменяет отсутствующие колонки позициями старого формата.
- После импорта показывается число созданных точек и привязок каналов.

## Проверка

- Диагностическое чтение исходного ODS подтвердило лист, заголовки и строки
  точек 1–4 непосредственно через используемый `fpspreadsheet`.
- Forced Windows build `RecorderLnx.lpi` — exit 0.

## Остаточный риск

Нужен визуальный повтор импорта в запущенной форме; теперь его результат явно
показывается отдельным сообщением.

## Дополнение 2026-09-14 — диагностика формата общей таблицы каналов

Рабочий файл `recorder_tags_v02.ods` содержит `Объект/Сечение = Я3(14В)`, то
есть ID компонента совпадает. Импорт останавливался раньше сопоставления секций:
он ошибочно требовал отдельный `N точки`, а столбец угла назван `Расположение
точки контроля в сечении` вместо экспортного `Расположение`.

`N точки` исключён из обязательных колонок. Каждое новое непустое значение
`Объект/Сечение` начинает следующую точку, а следующие строки с пустой ячейкой
относятся к ролям этой точки. Строки после другого сечения больше не могут
попасть в импорт текущего компонента. Длинное имя столбца расположения принято
как алиас. При других ошибках формата диалог перечисляет отсутствующие и все
фактически найденные заголовки.

Forced Win64-сборка в отдельный EXE — exit 0.

## Дополнение 2026-09-14 — строки ролей ошибочно разъединялись

В общей таблице `Объект/Сечение` повторяется у каждой строки роли, поэтому
предыдущая реализация ошибочно считала каждую строку новой точкой. Кроме того,
значения угла вида `90°` не разбирались как числа и превращались в `0`, а имя
тега ошибочно бралось из технологической колонки `Имя канала` (`1E1`) вместо
`Имя датчика` (`185-{...}`).

Алгоритм исправлен:

- при наличии `N точки` сохраняется группировка по номеру;
- без `N точки` строки одного сечения группируются по числовому расположению;
- знак градуса удаляется перед разбором числа;
- при наличии `Имя датчика` эта колонка имеет приоритет для привязки тега;
- каждый повторный импорт заново очищает и строит черновик компонента.

Forced Win64-сборка — exit 0. Визуальная проверка в запущенной форме остаётся
за пользователем, поскольку основной экземпляр RecorderLnx уже запущен.
