# Lua / OPC UA: массовая запись задерживала чтение

## Симптом

Lua-цикл записывал 100 тегов. Мигающий входной тег обновлялся медленно, а
значения на OPC UA-сервере появлялись не одновременно.

## Причина

- каждый `setValue` немедленно публиковал тег и увеличивал общую revision;
- выходы Lua запускали следующий `PN_UPDATEDATA`, создавая самоподдерживающийся
  цикл;
- DataSource отправлял отдельный синхронный `WriteRequest` для каждого значения
  перед очередным чтением;
- успешная запись каждого тега отдельно попадала в журнал.

## Исправление

Lua накапливает итоговые значения до конца прохода. Входная revision отделена
от расчётных выходов. OPC UA DataSource читает входы первым, затем атомарно
снимает очередь и отправляет массив `WriteValue` одним `WriteRequest`, разбивая
его только по `maxNodesPerWrite`. Журнал содержит одну строку на пакет.

## Проверка

Forced-сборки RecorderLnx и LuaCalcPlugin завершены с exit code 0;
`LuaCalcSmoke passed`; приложение запускалось и штатно остановлено. Живой
пакетный обмен требует запуска пользовательского проекта с OPC UA-источником.
