# SQL-тренд: временной диапазон и одиночные точки

## Симптомы

- В настройках SQL-тренда время суток `От` и `До` выглядело одинаково.
- Изменение окна не пересчитывало границы времени и наоборот.
- Выбранные скалярные сигналы не были видны на графике.

## Подтверждённые факты

- В Firebird БД `C:\Mera Files\SQLdb\recorderlnx.fdb` находится 1171 значений
  и 60 сигналов.
- Фактический диапазон: `31.07.2026 15:05:59` — `15:38:10` UTC.
- У выбранных скалярных сигналов было по одной точке.
- Одинаковое время суток объяснялось ровно 24-часовым окном между разными датами.

## Корневая причина

Три параметра времени редактировались независимо, а Canvas-график рисовал только
отрезки между соседними точками и не рисовал отдельный маркер значения.

## Исправление

- `От`/`До` пересчитывают окно; окно пересчитывает `От`, сохраняя `До`.
- Добавлена проверка и подстановка фактического диапазона SQL БД.
- Каждая точка рисуется маркером, поэтому серия из одного значения видна.
- Цвет линии показывается отдельной залитой панелью.

## Проверка

- Прямой запрос Firebird подтвердил количество и диапазон данных.
- Полная сборка `RecorderLnx_verify.exe` завершилась с exit code 0.
- Штатный EXE не обновлялся: его удерживал запущенный RecorderLnx.

## Оставшийся риск

Интерактивное редактирование временных полей проверено компиляцией и логикой
обработчиков; требуется визуальная проверка после перезапуска пользовательского EXE.
## 2026-08-05 — обрезка линий при зуме

- Симптом: сегмент, пересекающий границу X, исчезал; значения вне Y прижимались к рамке.
- Причина: внешние X-точки разрывали сегмент, а Y ограничивался через `EnsureRange`.
- Исправление: отрезки клипуются по прямоугольнику графика; внешние маркеры не рисуются.
- Проверка: полная сборка `RecorderLnx.lpi`, exit code 0.
