# Диалог тега не получал частотную сетку MC-201

## Симптом

Для канала MC-201 поле «Частота опроса» показывало только текущее значение и не
содержало сетку частот модуля.

## Причина

`uTagSettingsDialog` знал только жёстко заданную таблицу MIC-140. Общего контракта,
через который аппаратный модуль мог опубликовать свою частотную сетку, не было.

## Исправление

Добавлен универсальный реестр `uRecorderFrequencyGrids`. Драйвер регистрирует
сетку по префиксу `SourceId`, а диалог запрашивает её без определения типа прибора.
MC-201 публикует 16 значений, вычисленных точной формулой
`ModuleMC201::IndexToFreq` из оригинального `mtc/Mc201.cpp`.

Первоначально в формулу ошибочно была подставлена внутренняя константа MC-201
`FREQ_CLK=16384000`, и список заканчивался на 64000 Гц. Это неверно: конструктор
базового `Module` оставляет `SelfClk=NOSELF_CLK`, поэтому `Module::GetFreqClk()`
возвращает `CCDevice::GetFreqBackplane()`. Для Ethernet81
`mdpEthernet81::GetProperty(PROP_DEV_FREQ_BACKPLANE)` жёстко возвращает 14745600,
а setter частоты backplane игнорируется. Исправленная сетка:
300, 450, 600, 900, 1200, 1800, 2400, 3600, 4800, 7200, 9600, 14400, 19200,
28800, 38400, 57600 Гц. Та же общая функция теперь используется при переводе
частоты в `FreqIndex/GridCode`, чтобы UI и программирование не расходились.

Дополнение для специсполнения: фиксированная регистрация только по префиксу
`MC-032: ` не позволяла двум контроллерам иметь разные кварцы. В конфигурацию
добавлен `CFG backplane=14745600|16384000`, а реестр выбирает наиболее длинный
совпавший префикс — точная запись полного `SourceId` перекрывает типовое значение.
Выбранный кварц также передаётся драйверу, иначе список показывал бы 64 кГц, но
модуль программировался бы кодом сетки 14,7456 МГц.

## Проверка

Полная сборка `RecorderLnx.lpi` завершилась с кодом 0. Первый запуск сборки дошёл
до линковки, но запущенный `RecorderLnx.exe` блокировал замену файла; после закрытия
процесса повторная полная сборка прошла успешно.
