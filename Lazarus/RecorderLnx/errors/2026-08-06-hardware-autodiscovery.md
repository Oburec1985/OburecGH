# Автопоиск не обнаруживал сетевые приборы

## Причина

Старый поиск использовал жёстко заданные подсети и адрес MIC183/185 по
умолчанию. Выбранный сетевой адаптер и его фактическая маска не определяли
область поиска. Для MIC-140 проверка открытого TCP-порта могла ошибочно считаться
идентификацией устройства.

После выдачи приложению доступа к сетевому интерфейсу выявлена дополнительная
причина: RecorderLnx ожидал broadcast только `1400 мс`, тогда как оригинальный
MebiusDAQ EthernetBus ожидает `5000 мс`. Стендовый MIC185 отвечает позже 1,4 с.

## Исправление

- Реализованы штатные modern MebiusDAQ и legacy Ethernet81 broadcast-запросы.
- Окно ожидания broadcast увеличено до `5200 мс`, сохраняя небольшой запас к
  оригинальным `5000 мс`.
- Broadcast отправляется через выбранный локальный IPv4, включая directed
  broadcast подсети.
- Ответ broadcast разбирается до типа и серийного номера; `TestLink` для такого
  устройства не выполняется.
- Резервный поиск строится по реальной маске выбранного активного адаптера.
- Сначала параллельно проверяется TCP/4000, затем открытые узлы идентифицируются
  полными запросами MIC183/185, MIC-140 и MC-032.
- После первого корректного broadcast-ответа поиск заканчивается, если в течение
  1000 мс не появилось нового устройства; верхний предел 5200 мс сохранён для
  медленно отвечающих приборов.
- Добавление выбранных приборов выполняется пакетно с единственным обновлением
  дерева и таблиц. Ранее каждый прибор заново перестраивал дерево и последовательно
  запускал сетевые проверки всех уже добавленных источников.
- Отрисовка дерева больше не выполняет сетевой `TestLink`. Новый найденный прибор
  показывается исправным; предупреждающая иконка появляется после реальной ошибки,
  зарегистрированной runtime-подключением или явной проверкой.
- В `LogWindows.log` пишутся этапы `[HardwareSearch]`: broadcast, TCP scan,
  fallback identification и batch add/UI refresh.

## Проверка

Адреса `192.168.9.147`, `.148`, `.151`, `.152`, `.155` доступны через выбранный
интерфейс `192.168.5.100` по TCP/4000. Последняя версия проекта собрана
`lazbuild` без ошибок.

Одиночная проверка `192.168.9.147`: при `6000 мс` получен ответ
`MIC183/185, SN=161`; при `1400 мс` ответ отсутствует.
