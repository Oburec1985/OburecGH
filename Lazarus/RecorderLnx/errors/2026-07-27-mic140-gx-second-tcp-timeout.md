# 2026-07-27 — MIC-140: таймаут чтения аппаратной ГХ

## Симптом

В `TagSettingsDialog` кнопка чтения аппаратной ГХ завершалась ошибкой подключения.

## Подтверждённые факты

- Поток данных MIC-140 перед открытием настроек работал корректно.
- `LogWindows.log`:
  - `start download host=192.168.14.48 port=4000`;
  - через 12 секунд `Connect failed ... timed out`.
- Источник данных уже держал зарегистрированное live-устройство и открытую
  TCP-сессию с этим MIC-140.
- Код чтения ГХ безусловно создавал второй `TMic140v2Tcp`.
- Контроллер не обслуживает такое конкурирующее соединение.
- В старой ветке после `StopScan` выполнялась очистка накопленных MDP-пакетов.

## Причина

Сервисная операция обходила зарегистрированное устройство и открывала второе
TCP-соединение. Это нарушало владение транспортом и приводило к таймауту ещё до
чтения EEPROM.

## Исправление

- Добавлен узкий `IMic140ServiceMemory`.
- Рабочий `TRecorderMic140Device` реализует чтение firmware/EEPROM через свой
  существующий `TMic140v2Tcp`.
- Чтение ГХ сначала ищет live-устройство по `SourceId` и использует его сессию.
- Отдельный TCP оставлен только как fallback, когда live-устройства нет.
- Во время `rdsStarted` сервисное чтение запрещено с явной ошибкой.
- После сервисного `StopScan` очищаются буфер и очередь MDP-пакетов.

## Проверка

- `lazbuild -B RecorderLnx.lpi` — успешно.
- `lazbuild -B Mic140ProtocolDebug_Codex.lpi` — успешно.
- Имеющийся `RecorderDataSourcesTest.exe` — все тесты прошли, включая MIC-140.
- Пересборка старого `RecorderDataSourcesTest.lpi` отдельно падает внутри FPC
  при чтении старого `uRecorderFrequencyBands.ppu`; ошибка не относится к
  изменённым MIC-140 units.

## Оставшаяся проверка

Проверить кнопкой в UI чтение реальной ГХ и последующий переход в просмотр.
В журнале должна появиться строка
`using registered MIC-140 service session`, без нового `Connect failed`.

## Продолжение: ложное «Calibration was not found»

- Каталог flash прочитан корректно: `mi118tar.bin`, адрес `0x00007FB6`,
  размер `53964`.
- Из-за несовпадения размера файла с расчётным размером для раскладки 48/96
  каналов код ошибочно прибавлял расчётный размер к адресу найденного файла.
- Чтение начиналось с `0x0000F26D` или `0x0000CEFD`, то есть из середины
  `mi118tar.bin`; в журнал попадали `FF` и фрагменты текста вместо `TARE_TYPE_1`.
- В оригинале смещение является частью ветки пересоздания файла: после
  `SetFileInfo` драйвер повторно получает адрес из каталога. Для операции
  чтения существующего файла переносить эту логику нельзя.
- Исправлено: если `mi118tar.bin` найден, его каталожный `Address` используется
  как абсолютный базовый адрес независимо от расхождения размера. Fallback
  оставлен только для действительно отсутствующего файла.
- `lazbuild -B RecorderLnx.lpi` завершён успешно.

## Продолжение: исключение после аппаратного диалога MIC-140

Сценарий воспроизведения: открыть `TagSettingsDialog`, открыть аппаратные
настройки MIC-140, нажать `OK`, затем нажать `OK` внешнего диалога. Отладчик
останавливался в `TMic140v2Tcp.Connect`.

Причина: `ApplyRecorderMic140SourceDialog` после обычного `OK` безусловно
вызывал `RecorderMic140QueryHardwareCalibrSerial`, который создавал второй
`TMic140v2Tcp` к уже подключённому прибору. Дополнительно диалог мог выполнять
такой же запрос при открытии конфигурации без сохранённой версии или серийного
номера.

Исправление:

- открытие аппаратного диалога больше не выполняет неявный сетевой запрос;
- обычный `OK` сохраняет полученные настройки без нового TCP-соединения;
- чтение версии и серийного номера оставлено за явной кнопкой «Проверить»;
- после сохранения настроек канала флаг и имя аппаратной ГХ синхронизируются
  обратно в универсальную проекцию тега.

Проверка: полная сборка `lazbuild -B RecorderLnx.lpi` завершена успешно.
- Остаётся подтвердить на приборе содержимое первой записи по адресу
  `0x00007FB6` и успешное отображение ГХ.

## Продолжение: ГХ прочитана, но не восстановилась после перезапуска

- Пользователь подтвердил успешное чтение ГХ первых четырёх каналов.
- В `default.config.json` флаг и имя были сохранены одновременно в
  `dataSources[].mic140.channels[]` и в универсальной записи тега.
- При загрузке `RecorderMic140MigrateLegacyFieldsToDeviceConfig` переносил
  значения в device config, после чего обнулял проекцию в теге. Диалог читал
  тег и поэтому показывал снятый флаг и пустое имя.
- Исправлено: миграция сохраняет синхронную проекцию в теге; изменение флага в
  `TagSettingsDialog` записывается также в настройки канала MIC-140.
- При загрузке каждого MIC-140 тега выполняется локальный поиск CSV по
  `Calibr/hardware/MIC140/snNNNN/<range>/NN.csv`. При наличии файла ГХ сразу
  добавляется в реестр без подключения к прибору.
- Проверка на текущем проекте: при старте автоматически назначены
  `sn0329/06_100mV/01.csv`–`04.csv` тегам каналов 1–4.
- `lazbuild -B RecorderLnx.lpi` завершён успешно.
