# Неполный маршрут и неизменный размер интенсивности

## Сквозная проверка и окончательно уточнённая нормировка

Пользователь уточнил опору: максимум FRF в ПРЕДНАСТРОЕННОМ диапазоне,
не в текущем zoom. Поэтому нормировка по текущей частоте ниже — историческая
промежуточная попытка, а не окончательная семантика.

Интеграционный тест с намеренно различными источниками воспроизвёл подмену:
ожидалось сохранённое значение123, aggregate возвращал runtime1.819349.
Причина: одинаковые CurveId, первый зарегистрированный источник выигрывал.
Сохранённому шагу даны route-owned ID. Второй дефект: при новом ударе worker
снимал stored-флаг, но не менял привязки. Теперь pending-флаг обрабатывается
однократно FillSnapshot на UI-потоке, который переключает провайдер/привязки.

Новая опора через optional range-scale sampler кэшируется по identity/version,
настройкам и preset. Band/RSS максимум считается скользящим окном O(n), без
аллокаций; обычное движение курсора использует уже готовую опору. Внешние пики
не входят в максимум (для полосы учитывается её расширение). Двойной курсор
публикует частоту реально изменённой линии X1/X2, не всегда X2.

Сквозной fixture: 2 сохранённых шага, 3 точки, третий несохранённый шаг,
3 RAM-удара. Проверены правильные saved/live значения, переход к новому удару
без повторного выбора шага, размеры10→40px при курсоре1→2Гц, все3точки и
числовые метки, переключение шагов, возврат из review, неизменность sequence,
времён/значений возбуждения и отклика, FRF и спектров RAM. Повреждение
сохранения проверено отдельно. Пользовательские файлы не использовались.
UI smoke проверяет отсутствие таблицы привязок в форме отображения,
сохранность geometry-полей при Enter, обе линии курсора, X/Y между шагами.
Нормировка отдельно проверена на single point, aggregate, preset change,
интерполированном краю, RSS и пиках1E200 вне диапазона. Все целевые тесты PASS.
Это автоматизированный сервис/LCL/adapter сценарий, не реальный аппаратный замер.

## Уточнение после повторного сообщения пользователя

Предыдущее изменение шкалы не соответствовало требуемой нормировке. При
большом пике вдали от курсора размер на текущей частоте становился <0.5px и
DrawIntensityMarkers пропускал кружок. Нормировка по текущей частоте восстановлена;
удалены ненужные full-spectrum scale API и предрасчёты.

Отдельная подтверждённая ошибка: PublishCurrentRouteBindings копировал общий
GeometryBindingMode, но не учитывал Response.IntensityOnly. Обычный
PublishPointBindings это делал. ConfigureFrf создаёт кружок только для
rgbmIntensity. В маршруте теперь копируется IntensityOnly и выбирается
rgbmIntensity, если он включён.

Регрессии: route-point-only проверяет mode при общем режиме oscillation и
IntensityOnly=True; intensity-markers-only проверяет нормированные размеры
10/20→20/10 при смене частоты и отсутствие исчезновения от пика 1E9 на другой
частоте. Трассировка cursor notification→selected frequency→3D sampling
не показала разрыва. Аппаратный пользовательский сеанс не воспроизводился.
Ниже оставлен исторический отчёт предыдущей попытки, а не действующая семантика.

Сценарий: два сохранённых шага, ещё один несохранённый, несколько новых ударов
в RAM. Просмотр результата ошибочно требовал сохранения каждого шага.
ShowSavedRoute проверял AllComplete и пытался читать все каталоги без пропуска.
Теперь отсутствующие session.json пропускаются, существующие повреждённые
файлы дают отдельную ошибку. Если нет ни одной сохранённой привязанной точки,
остаётся явное сообщение об отсутствии данных. Просмотр не сохраняет RAM.

Вторая причина: adapter.Update делил значение на максимум привязок на той же
частоте. Для одной точки value/value=1; одинаковая форма нескольких кривых
тоже даёт постоянный размер. Числовое значение менялось, кружок — нет.
Новая шкала: максимум спектра (для полосы верхняя RSS-граница всего спектра),
вычисленный при создании immutable snapshot. Общая опора для привязок
кэшируется по identity+Version снимка и сбрасывается Configure. Aggregate
провайдер передаёт optional scale-интерфейс, legacy fallback фиксирован.
Сканирования спектра при движении курсора нет.

Проверки: service --route-point-only (два сохранённых + несохранённый шаг,
пустые графики последнего, восстановление 3 RAM-ударов, диагностика повреждения);
UI --intensity-markers-only (single point, proportional curves, aggregate,
инвалидация после Publish); --route-spinner-only. Все PASS.
Forced app/UI/service builds exit=0. Реальное оборудование и пользовательские
файлы не изменялись; аппаратный GUI-сеанс не воспроизводился.
