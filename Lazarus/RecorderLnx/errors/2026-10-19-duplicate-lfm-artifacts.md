# Дубли `.lfm` в корне RecorderLnx

## Симптом

В корне проекта находился 41 отслеживаемый `.lfm`, хотя соответствующие модули
и актуальные ресурсы форм расположены в тематических каталогах. Ещё 52 `.lfm`
видны в `lib/x86_64-win64`.

## Подтверждённые факты

- каждому корневому `.lfm` соответствует исходный `.pas` и `.lfm` в `UI`,
  `Components`, `Device`, `SDB`, `SQLdb` либо `Calibrations`;
- `RecorderLnx.lpi` ссылается на модули из тематических каталогов, явных ссылок
  на корневые `.lfm` нет;
- часть корневых копий уже отличалась от актуальных ресурсов рядом с кодом;
- `lib/x86_64-win64` является `UnitOutputDirectory`; Lazarus/FPC помещает туда
  промежуточные копии LCL-ресурсов вместе с `.ppu`, `.o` и другими артефактами.

## Первопричина

Старые копии форм в корне были сохранены в Git после переноса модулей по
каталогам. Ресурсы в `lib` — нормальные игнорируемые промежуточные файлы сборки,
а не второй комплект исходников.

## Исправление

- удалён 41 корневой дубликат;
- в локальный `.gitignore` добавлено `/*.lfm`, чтобы корневые копии не были
  случайно добавлены повторно;
- авторитетными оставлены `.lfm` рядом с одноимёнными `.pas`.

## Проверка

- после forced-сборки в корне проекта осталось 0 `.lfm`;
- сборка завершилась успешно в `lib/x86_64-win64/RecorderLnx_lfm_verify.exe`;
- компилятор в журнале читает модули из тематических каталогов.

Остаточный риск: содержимое `lib` остаётся визуально насыщенным промежуточными
ресурсами; каталог целиком игнорируется Git и может безопасно очищаться командой
очистки проекта, но удалять его ресурсы после каждой сборки не следует.
