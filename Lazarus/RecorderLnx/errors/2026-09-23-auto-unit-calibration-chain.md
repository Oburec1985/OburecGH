# Auto-unit пропускал аппаратную ГХ MC-201

## Симптом

При включённом `AutoUnit` тег MC-201 с назначенной аппаратной ГХ продолжал
показывать `код`. Диалог искал единицу только у последней канальной ГХ и не
рассматривал аппаратную ГХ как первое звено общей цепочки.

## Причина

Определение итоговой единицы находилось в UI, а MC-201 отдельно переключал
только `код/В`. Общего контракта для единиц и жизненного цикла собранной
линейной цепочки не было.

## Исправление

- реестр тегов определяет AutoUnit по последней включённой канальной ГХ, с
  аппаратной ГХ как fallback;
- вход первой канальной ГХ приводится к выходу аппаратной через
  `RecorderUnitManager`; для `1 pC/mV` и источника `V` коэффициент становится
  `0.001`, а `UnitIn` — `V`;
- линейная цепочка собирается один раз в результирующий коэффициент тега;
  повторный `RebuildScales` при валидном флаге ничего не делает;
- изменение настроек/ГХ сбрасывает флаг, после reconfigure цепочка собирается
  заново; runtime умножает отсчёт на готовый коэффициент.

## Проверка

Forced-сборка `RecorderTagsTest.lpi` завершилась с exit code 0. Запуск старого
набора тестов дошёл до известной несвязанной проверки копирования block-event и
остановился на ожидании `0`, хотя текущая шина отправляет `1` событие.

## Правило предотвращения

Устройства не вычисляют AutoUnit самостоятельно. Единица и собранный линейный
коэффициент всегда выводятся из единой упорядоченной цепочки в реестре тегов;
любое изменение цепочки сначала инвалидирует кэш, затем reconfigure вызывает
`RebuildScales`.

## Follow-up 2026-09-24: галка Auto не обновляла открытый диалог

### Симптом

После включения `Авто` поле единиц оставалось на исходной единице тега, хотя
включённый pipeline заканчивался ГХ с другой `UnitOut`.

### Подтверждённая причина

`AutoUnitCheckClick` видел новое состояние checkbox и вызывал общий sync, но
`SyncTagAutoUnit` повторно проверял старое `TRecorderTag.AutoUnit`. Поле модели
обновляется только позднее, в `StoreToTags` по OK/Apply, поэтому sync завершался
до поиска конечной единицы.

### Исправление

Общий метод синхронизации получил явный флаг принудительного применения.
Диалог передаёт его только после собственной проверки `cbChecked`; остальные
вызовы по-прежнему зависят от сохранённого `Tag.AutoUnit`. Выбор конечной
канальной ГХ и fallback на аппаратную ГХ остаются едиными для всех устройств.

### Проверка

Проверена полная цепочка обработчика и отсутствие ошибок `git diff --check`.
Forced-сборка будет выполнена основной задачей после объединения параллельных
изменений.

## Follow-up 2026-09-24: базовая единица и масштаб входа

`SourceUnitName` теперь явно считается базовой единицей тега.
Предпросмотр `Auto` читает текущие галки ГХ диалога и не меняет
модель до `OK/Применить`; снятие `Auto` возвращает базовую
единицу. При отсутствии включённых ГХ ручной ввод сохраняется
как базовая единица.

Для примера `1 V` и сквозной чувствительности `20 mV/(m/s2)`
свёртка должна дать масштаб `1000 / 20 = 50`: менеджер единиц
возвращает `V -> mV = 1000`, затем применяются обратные
чувствительностям масштабы ступей.

Forced Windows-сборка `RecorderLnx.lpi` — exit code 0.

## Follow-up 2026-09-25: Auto отделён от управления ГХ

### Симптом

Управление единицей и применение аппаратной ГХ MC-201 смешивались: загрузчик
мог включить ГХ обратно, а ручная единица не получала пересчёт из UnitOut.
В редакторе масштаба также показывался не относящийся к нему флаг экстраполяции.

### Исправление

- расчет аппаратной и канальной ГХ зависит только от их собственных флагов;
- AutoUnit выбирает UnitOut последней включённой канальной ГХ либо аппаратной;
- ручная совместимая единица добавляет конечный коэффициент UnitOut→UnitName;
- список combo ограничен категорией UnitOut последней ступени pipeline;
- экстраполяция доступна только для `rckPiecewiseLinear`.

### Проверка

Forced Windows-сборки теста тегов и RecorderLnx — exit 0. Полная Linux-сборка
0.1.80: `BUILD_EXIT=0`, `MISSING_LIBS=none`; DEB установлен на MIC-200.

## Follow-up 2026-09-25: снятая галка блокировала загрузку ГХ MC-201

### Симптом

После установки 0.1.80 модули MC-201 не находили лежащие на диске аппаратные
ГХ, которые загружались предыдущей версией.

### Подтверждённая причина

`RecorderMc201LoadHardwareCalibrationForTag` завершался до поиска файла при
`HardwareCalibrationEnabled=False`. Галка применения ошибочно блокировала
регистрацию объекта и назначение имени ГХ тегу.

### Исправление и проверка

Загрузка и привязка ГХ снова выполняются независимо от галки; загрузчик не
изменяет `HardwareCalibrationEnabled`, который управляет только расчётом.
Forced Windows-сборка — exit 0; Linux 0.1.81 — `BUILD_EXIT=0`,
`MISSING_LIBS=none`; пакет установлен на MIC-200 со статусом `installed`.

## Follow-up 2026-09-25: общий флаг ошибочно дублировался внутри pipeline

### Симптом

Внешняя галка канальной ГХ и внутренняя галка «Цепочка ГХ включена» управляли
одним состоянием. При этом отдельную ступень нельзя было выключить, а категория
единиц определялась без состояния конкретных ступеней.

### Исправление

Внутренняя общая галка скрыта и исключена из API редактора. У каждой строки
pipeline появилось собственное состояние «Вкл», которое сохраняется в проекте.
Расчёт, сквозная чувствительность и UnitOut пропускают выключенные ступени;
общий внешний `ChannelCalibrationEnabled` по-прежнему выключает всю цепочку.
Старый строковый JSON pipeline читается как полностью включённый.

### Проверка

Forced-сборки RecorderTagsTest и RecorderLnx — exit 0. Linux 0.1.82:
`BUILD_EXIT=0`, `MISSING_LIBS=none`; пакет установлен на MIC-200,
`version=0.1.82 status=installed`.

## Follow-up 2026-09-25: аппаратная ГХ MC-201 снималась после OK

### Причина

После сохранения пользовательской галки `StoreToTags` вызывал
`RecorderTagClearMic140Settings` для любого не-MIC-140 источника. Процедура с
именем про MIC-140 на самом деле очищала общие поля тега:
`HardwareCalibrationEnabled` и `HardwareCalibrationName`. Поэтому повторное
открытие показывало снятую галку, а Auto возвращал тег в `code`.

Дополнительно привязка сигнала писала единицу источника прямо в `UnitName` и
автоматически включала аппаратную ГХ при первом bind MC-201.

### Исправление

- служебная очистка MIC-140 больше не меняет общие поля ГХ;
- обнаружение и привязка ГХ могут назначить её имя, но не меняют флаг применения;
- метаданные источника записываются в `SourceUnitName`, результат формирует
  централизованный pipeline;
- `code`, `codes`, `код` зарегистрированы как алиасы одной raw-величины;
- межступенчатые преобразования единиц выполняются и в нелинейной цепочке;
- новый тег не получает автоматически включённую канальную ГХ.

### Проверка

Forced Windows-сборки RecorderTagsTest и RecorderLnx завершились с exit code 0.
Запуск существующего RecorderTagsTest дошёл до прежней независимой проверки
EventBus и упал на ожидаемом ею числе копий measurement block (`expected 0,
got 1`); к изменённому pipeline тест не относится.

Полная Linux-сборка 0.1.83 завершилась с `BUILD_EXIT=0` и
`MISSING_LIBS=none`. Пакет установлен на MIC-200; после удаления проверенного
stale lock-файла новый бинарник запущен в активной графической сессии.
