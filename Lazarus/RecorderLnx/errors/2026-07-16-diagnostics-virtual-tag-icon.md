# Иконка виртуальных диагностических тегов

## Symptom

Теги `CpuUsage` и `MemTag` отображались без иконки виртуального тега.

## Context

Оба тега создаются внутренним источником `debug.diagnostics`; виртуальные теги Mera-файлов уже получали иконку ImageList 20.

## Facts

- `RecorderIsVirtualTagSource` возвращает `True` только для префикса `Mera file: `.
- Диагностический источник создаётся как `TRecorderDiagnosticsDataSource.Create('debug.diagnostics', ...)`.
- `debug.diagnostics` уже считается неаппаратным и всегда активным источником.

## Hypotheses

- Подтверждено: UI ошибочно использовал Mera-специфичный предикат как полную классификацию виртуальных тегов.
- Отклонено: проблема находится в загрузке изображения №20 — эта же иконка корректно рисуется для Mera-тегов.

## Actions

- В доменную модель `TRecorderTag` добавлен явный признак `IsVirtual`.
- Признак передаётся при создании через конструктор/`TRecorderTagRegistry.CreateTag` и сохраняется как JSON-поле `isVirtual`.
- Mera-, диагностические, тестовые программные и спектральные производные теги создаются с `IsVirtual=True`; аппаратные по умолчанию получают `False`.
- Иконка и фильтр «Только виртуальные» используют только `TRecorderTag.IsVirtual`.
- Для старых проектов без `isVirtual` оставлена миграция по известным legacy-источникам; после следующего сохранения значение становится явным.

## Current Conclusion

Причина устранена на уровне модели, а не UI-эвристики. Полная сборка `C:\lazarus\lazbuild.exe -B RecorderLnx.lpi` завершилась с exit code 0.
