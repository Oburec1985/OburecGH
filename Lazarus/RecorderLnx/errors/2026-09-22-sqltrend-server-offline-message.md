# SQL-тренд не показывал недоступность SQL-сервера

## Симптом

При выключенном или сетево недоступном SQL-сервере тренд оставлял старое
изображение без объяснения причины.

## Подтверждённые факты

- Worker до открытия репозитория выполняет TCP-проверку через
  `RecorderSqlServerAvailable`.
- При неуспехе устанавливался `lSkipDeliver`, поэтому результат проверки не
  попадал в `AcceptLoad` и `fErrorText` представления не обновлялся.
- Ошибки конфигурации, авторизации и SQL-запросов проходят отдельными путями и
  не должны называться выключенным сервером.

## Исправление

- Отрицательный TCP-probe передаёт в UI сообщение
  `Сервер SQL выключен или недоступен`.
- Техническая причина и идентификатор подключения сохраняются в файловом логе.
- Периодический worker продолжает проверки; успешный ответ очищает сообщение и
  восстанавливает обычную отрисовку.

## Проверка

- Forced-сборка RecorderLnx завершилась успешно, exit code 0.
- Ручная приёмка: закрытый SQL-порт показывает сообщение, открытие порта без
  перезапуска приложения восстанавливает тренд.

## Дополнение 2026-10-01: остановка отладчика во время просмотра

- При обрыве Firebird между TCP-preflight и очередной догрузкой репозиторий
  штатно создаёт `ERecorderSqlDbError`; worker перехватывает её, освобождает
  соединение и передаёт ошибку представлению.
- Lazarus при этом останавливал отладку непосредственно на `raise`, потому что
  `ERecorderSqlDbError` отсутствовал в списке игнорируемых исключений проекта.
- `ERecorderSqlDbError` добавлен в `RecorderLnx.lpi/Debugging/Exceptions` рядом
  с уже игнорируемым низкоуровневым `EIBDatabaseError`. Это убирает ложное
  «падение» в IDE, не скрывая `EAccessViolation` и другие дефекты программы.
