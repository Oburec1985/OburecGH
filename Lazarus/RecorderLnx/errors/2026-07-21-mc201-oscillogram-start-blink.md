# MC-201: линия осциллограммы пропадает после повторного старта

## Симптом

При каждом повторном запуске измерений сначала отображались один-два блока
MC-201, затем линия осциллограммы исчезала и позднее появлялась снова.

## Факты трассировки

- Поток MC-201 формирует завершённый блок на канал каждые 200 мс.
- `TRecorderMcbusDevice.Start` обнуляет `fSampleIndices`, поэтому первая временная
  метка каждого нового запуска снова равна нулю.
- `TRecorderSignalBuffer` сохранял историю тега между Stop/Start и без проверки
  дописывал новые отсчёты после старых.
- Осциллограмма ищет начало отображаемого окна через
  `TDoubleSearch.FindFirstGreaterOrEqual`, которому необходим отсортированный
  массив времён.

## Корневая причина

После повторного старта снимок имел вид: конец старого запуска с временем в
несколько секунд, затем новый блок `0..0,2`. Нарушение монотонности делало
результат бинарного поиска неопределённым. Линия возвращалась после вытеснения
старой временной эпохи из кольцевого буфера.

## Исправление

`TRecorderSignalBuffer.AddSample` и `AddSamples` определяют откат времени. При
его обнаружении старая эпоха очищается и первый новый отсчёт/блок добавляется
под той же критической секцией. UI никогда не видит промежуточный пустой буфер.

## Проверка

- `RecorderTagsTest`: добавлен сценарий времени `0,4..0,6 -> 0,0..0,1`; снимок
  содержит только две точки новой эпохи — тест пройден.
- `lazbuild -B RecorderLnx.lpi` — успешно.
- Аппаратная визуальная проверка нескольких Stop/Start остаётся контрольным
  испытанием на стенде MC-032/MC-201.
