# MIC-140: GUI-пример не запускал сбор данных

## Симптом

`Mic140ProtocolDebug_Codex.exe` открывался и выполнял проверку контроллера, но
таблица каналов оставалась пустой.

## Причина

Кнопка `Run 3 s` вызывала только `Connect -> InitializeDevice ->
ConfigureDevice`. Локальный каркас `TRecorderMic140Device` не переопределял
`Start` и `ReadBlock`, поэтому после настройки прибора поток не запускался и
данные в UI не попадали.

## Исправление

- пример подключён к рабочему `TRecorderMic140v2Device` из основного проекта;
- реализован полный цикл `Connect -> Init -> Config -> Start -> ReadBlock -> Stop`;
- таблица показывает последний код, среднее, число отсчётов, эталон и отклонение
  по всем 48 каналам;
- трёхсекундный тест автоматически запускается после создания формы;
- эталон загружается из `data/mic140_adc_reference.txt` рядом с EXE.

## Проверка на приборе 192.168.14.48:4000

22.07.2026 после закрытия оригинального Recorder:

- `hwCal=329`, прошивка `rev=14.1`, BIOS `1.8`;
- скан запрограммирован: `stride=48`, `fifoReady=96`, `msgWords=106`;
- принято 15 блоков за 3 секунды;
- каждый блок содержит 48 каналов по 2 отсчёта;
- итог: `gaps=0 dup=0 corrupt=0 resync=0`.

Лог: `Lazarus/RecorderLnx/Tests/LogWindows.log`.

## Отклонённая гипотеза

Первые `TCP probe failed` были получены при запуске процесса в ограниченной
сетевой песочнице. При штатном запуске процесса с доступом к локальной сети TCP,
программирование и поток работают с первой попытки.
