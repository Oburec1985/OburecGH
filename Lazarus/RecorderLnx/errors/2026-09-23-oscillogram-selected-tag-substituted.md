# 2026-09-23 — Осциллограмма добавляла другой тег

## Симптом

В настройках осциллограммы пользователь выбирал тег в списке каналов, но при
добавлении в компонент попадал другой тег.

## Причина

`PrimaryTagChange` сразу привязывал выбранный тег к текущей строке. Следующий
щелчок по `Добавить` обнаруживал, что этот тег уже используется, и
`AddLineClick` без сообщения заменял выбранный объект первым свободным элементом
комбобокса. Поэтому имя и `TagId` сохранялись согласованно, но относились не к
пользовательскому выбору, а к автоматически выбранному индексу.

## Исправление

- Удалён скрытый поиск «первого свободного» элемента: `AddLineClick` передаёт в
  `RecorderBindComponentTag`/`RecorderBindTrendLineTag` ровно объект текущего
  элемента combo, поэтому `TagId` и `TagName` соответствуют видимому выбору.
- Таблица `Активный сигнал` в правой панели закреплена снизу; непосредственно над
  ней добавлен горизонтальный splitter для изменения высоты.

## Проверка

- `git diff --check` для двух изменённых UI-модулей — без ошибок пробелов.
- Forced-сборка `RecorderLnx.lpi` после освобождения файла — exit code 0.

## Осталось

Визуально проверить добавление/замену тега и изменение высоты таблицы
splitter-ом.
