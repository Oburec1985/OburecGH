# Linux: Enter не фиксировал значение поля ввода

## Симптом

После ввода числа и Enter поле на Linux визуально очищалось. При повторном
фокусе текст появлялся, но значение привязанного тега не обновлялось.

## Причина

`TRecorderInputFieldView.NumericKeyPress` пропускал все управляющие символы
ранним `Exit`. Enter (`#10`/`#13`) не вызывал `CommitValue`, поэтому поведение
зависело от последующей GTK/LCL обработки фокуса и `OnEditingDone`.

## Исправление

Enter явно вызывает `CommitValue` и затем заменяется на `#0`. Это обеспечивает
однократную локальную публикацию через `PublishExternalValue`, постановку
записи источнику и запрещает GTK дополнительно обрабатывать эту клавишу.

## Повтор после переключений редактор/просмотр

После первой установки пользователь подтвердил работу, но после многократных
переключений поле один раз снова перестало подтверждать Enter. Уточнённая
причина: `EditChange` выставлял `fEditing` только при `Focused=True`. Поле
скрывается в редакторе и повторно показывается в просмотре; после такого
hide/show GTK способен вызвать `OnChange`, пока LCL ещё сообщает старое
состояние фокуса. Текст менялся, но `CommitValue` выходил по `not fEditing`.

Исправлено: любое пользовательское `OnChange` вне защищённого
`fUpdatingText` включает `fEditing`, а Enter дополнительно устанавливает этот
флаг перед commit. В журнал добавлены строки `[INPUT-FIELD] committed` и
`[INPUT-FIELD] commit rejected` с компонентом, тегом и причиной.

## Проверка

Forced Windows-сборка RecorderLnx завершилась с exit code 0. Forced Linux build
через VMware Tools завершился с `BUILD_EXIT=0`, `MISSING_LIBS=none`. Свежий DEB
`0.1.104`, SHA-256
`24CDF5FE8C047F47FAAE6898D2F2FDA0B5C58D609ED4752933AD2BB2B96F9D80`,
установлен и проверен на KIP-3 `192.168.9.66`.

Из-за потери пустого второго аргумента при вызове BAT из PowerShell фильтр
хоста не применился: тот же пакет повторно установлен также на KIP-1, KIP-2,
KIP-4 и MIC-200. Все пять установок завершились успешно.

Остаётся интерактивно проверить под Linux: ввести новое значение, нажать Enter,
убедиться, что текст остаётся и ревизия тега меняется.

После уточнённого исправления forced Windows- и Linux-сборки завершились с
exit code 0; Linux `MISSING_LIBS=none`. Обновлённый DEB 0.1.104, SHA-256
`1F957FFCDB8B0377D960950AB0F1F3D5E3204E1FC093411E8E7E4F1EDADA449D`,
установлен адресно только на KIP-3: `1 succeeded, 0 failed`.

`RLNX_LCL_EDIT_COMMIT_AFTER_HIDE_SHOW_2026_09_29`.
