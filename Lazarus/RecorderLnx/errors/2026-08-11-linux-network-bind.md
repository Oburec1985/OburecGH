# Linux: приборы недоступны из-за чужого bind-адреса

## Симптом

Linux-сборка загружала из общего проекта адрес интерфейса Windows
`192.168.5.100`. Любое подключение завершалось ошибкой `bind: 99`, хотя приборная
сеть была доступна через маршрут виртуальной машины.

## Причина

`SetRecorderNetworkBindAddress` проверял только формат IPv4, но не принадлежность
адреса локальной системе. Поэтому настройка интерфейса ошибочно считалась
переносимой между Windows и Linux.

## Исправление

На Linux адрес проверяется пробной локальной привязкой сокета. Если адрес не
принадлежит системе, явная привязка снимается и маршрут выбирает ОС. Windows-
поведение не изменено: там по-прежнему можно явно выбрать настроенный метриками
интерфейс.

## Проверка

- В VM есть только `ens33 / 192.168.112.128`; маршрут к `192.168.9.147` проходит
  через `192.168.112.2`, ping около 0,7 мс.
- Windows и Linux clean build завершились с кодом 0.
- Linux smoke test: в lifecycle-логе `bind=`; MIC-185 `192.168.9.147` выполнил
  `connect`, `initialize`, `configure`, прочитаны `SN=161`, версия `20.6.6`.
- Ошибка `Не удалось привязать сокет к 192.168.5.100: 99` исчезла.

Остальные четыре MIC-185 не ответили на TCP connect за 4 секунды; это уже не
ошибка локальной привязки — соединение создавалось через автоматический маршрут.
