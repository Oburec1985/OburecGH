# MIC-185: нагрузка CPU в Preview

## Симптом

После перехода в Preview предположительно возрастает загрузка процессора при
сборе данных MIC-185.

## Подтверждённые причины

`PublishMeasurementBlock` на каждом блоке и для каждого измерительного канала:

- искал тег по строковому имени;
- искал аппаратную ГХ в реестре;
- при отсутствии ГХ мог повторно обращаться к её файловому кэшу;
- заново вычислял токовую поправку;
- создавал массивы времени и значений.

Вспомогательные температурные и UTS-каналы дополнительно искались полным
обходом тегов со сборкой строкового адреса.

## Исправление

- ссылки на измерительные, температурные и UTS-теги сохраняются при создании
  тегов источника;
- аппаратные ГХ и токовые поправки готовятся после программирования каналов;
- рабочие массивы времени и значений принадлежат источнику и растут только при
  увеличении фактического блока;
- публикация использует перегрузку с прямой ссылкой на тег.

## Проверка

Полная сборка `RecorderLnx.lpi` завершена успешно. Автоматический запуск не
воспроизвёл рабочий Preview текущей пользовательской конфигурации, поэтому
стендовый сравнительный замер CPU ещё нужен.

## Оставшийся риск

TCP-разбор MIC-185 пока создаёт промежуточные массивы `Single`, затем повторно
копирует их в `Double`. Этот участок следует менять только после отдельного
профиля времени чтения и публикации, чтобы не повредить порядок пакетов.
