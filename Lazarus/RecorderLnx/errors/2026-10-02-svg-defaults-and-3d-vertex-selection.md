# SVG defaults и выбор вершин 3D

## 2026-10-05 — промах луча около вершины

Подтверждено чтением `T3dLclWidget.MouseUp`: при промахе `PickScene` возвращал
пустой `T3dHit`. `NodeIdAfterPick` сохранял выбранный объект, но
`LogicalVertexFromHit` продолжал брать `NodeId` из пустого попадания. Поэтому
увеличение экранного допуска с 5 до 7 пикселей не действовало за пределами
поверхности. Изменено: `LogicalVertexFromNode` получает итоговый выбранный
`NodeId`, и поиск остаётся ограничен только этим объектом. Альтернативная
forced-сборка RecorderLnx — exit 0; `ThreeDInteractionTest` — PASS. Штатный
EXE заблокирован работающей программой; интерактивная проверка не выполнена.

## Симптомы

- Вместо неподключённых постоянных подписей SVG отображал шаблонный текст.
- Пустой клик при выборе вершины снимал выбранный объект.
- Вершины за заполненными гранями не были видны.

## Причины

- Runtime заменял только сохранённые bindings, но не defaults новых параметров.
- Пустой результат picker безусловно превращался в `SelectNode(0)`.
- `GL_POINTS` проходил depth-test уже нарисованных полигонов.

## Исправление и проверка

- `ResolveSvgParameterDefaults` завершает подстановку до BGRASVG.
- `NodeIdAfterPick` сохраняет объект в контексте vertex-pick.
- `rpPoints` и `rpVertexHighlight` являются overlay без depth-test с
  восстановлением предыдущего OpenGL state.
- `SvgParametersTest`, `SvgImageSettingsUiSmoke`, `ThreeDInteractionTest` —
  PASS; альтернативная полная сборка RecorderLnx — exit 0. Стандартный EXE
  удерживается работающим процессом (Windows error 5).

## Регрессия runtime-рендера параметрического прибора

Основной контрол отклонял `parametric-dual-gauge.svg`, хотя миниатюра диалога
строилась. В `LogWindows.log` подтверждено: параметр `TickCount|24` считался
запрещённым внутри атрибута `d`. Причина — `d` уже распознавался как числовой
контекст, но отсутствовал в белом списке шаблона и в ветке числовой проверки
значения. В `d` разрешён только числовой параметр с числовым default внутри
внутреннего выражения `recorder-ticks(...)`; произвольная параметризация пути
по-прежнему отклоняется. Значение параметра также проходит числовую проверку.
