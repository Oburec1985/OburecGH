# Спектр терял порции и продолжал рисовать отключённые максимумы

## Симптомы

- при FFT 32768 и входных блоках 8192 спектр обновлялся по прежнему ритму и
  не собирал настроенную порцию 0,5 с;
- после отключения расчёта максимума полосы график продолжал показывать
  маркер и подпись максимума;
- требовался опциональный параллельный расчёт независимых каналов.

## Причина

`TRecorderSpectrumChannel` правильно накапливал данные до `FFTSize`, но
`TRecorderSpectrumRuntimeManager.QueueInput` заменял ожидающий входной блок
новым блоком того же тега. При частых порциях промежуточные 8192 отсчёта
терялись до попадания в FFT-канал. Это отличалось от `plgControlCyclogram`, где
источник удерживает данные до полной `m_portionsize`.

`TOpenGLChartRenderer.DrawFrequencyBand` независимо пересчитывал пик каждой
видимой полосы и не имел признака отключения, поэтому нулевые результаты
алгоритма не скрывали графическую метку.

## Исправление

- Для каждого спектрального входа при конфигурации выделены кольцевой и рабочий
  буферы ёмкостью четыре FFT-порции. Runtime только копирует блоки в готовую
  память; `Create/Free/SetLength` на каждом обновлении удалены.
- Один и тот же канал не может одновременно выполняться двумя worker-ами;
  новые блоки, пришедшие во время FFT, повторно ставят канал в очередь.
- Настройка `ParallelChannels` сохраняется вместе с параметрами спектра. При
  включении создаётся постоянный пул размером не больше числа каналов и
  числа физических ядер: Windows использует
  `GetLogicalProcessorInformationEx(RelationProcessorCore)`, Linux считает
  уникальные пары `physical id/core id` из `/proc/cpuinfo`; при отсутствии
  топологии используется безопасный fallback `TThread.ProcessorCount`.
  Reconfigure/reset сначала штатно останавливает пул.
- Кэш, теги и события публикуются под отдельной блокировкой последовательно.
- В результат полосы передаются признаки реально включённых оценок. Общий
  chart получил `ShowPeak`; маркеры не рисуются, когда максимум и частота
  максимума отключены. Общая галка компонента «Метки пиков» также скрывает
  полноспектральный максимум.

## Проверка

- Добавлен регрессионный сценарий: четыре блока по 8 отсчётов, отправленные без
  ожидания worker-а, дают один FFT 32 с диапазоном времени `0..31/64`.
- Тот же тест проверяет создание многопоточного пула при двух каналах.
- `TestSpectrumMath2.exe`: PASS.
- Forced Windows build `RecorderLnx.lpi`: exit code 0.

## Правило

Граница уведомления источника не является границей FFT. Ни один ещё не
обработанный входной блок нельзя заменять следующим; логическая порция спектра
завершается только после накопления `FFTSize` отсчётов.
