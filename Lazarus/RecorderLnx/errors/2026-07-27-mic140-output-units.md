# 2026-07-27 — MIC-140: единицы не соответствуют активному конвейеру

## Повтор 2026-11-10: граница аппаратной ступени и выбора единиц

Пользователь повторно показал: MIC-140 настроен на градусы, но включение АХ
в диалоге тега оставляет только напряжительные единицы. Схема пользователя
требует, чтобы datasource объявлял допустимые единицы и принимал изменение
единицы через общий интерфейс; полный аппаратный результат (включая внутренние
пересчёты) — одно логическое звено перед внешними канальными ГХ.

Подтверждено по исходникам до правки:

- MIC140 provider ReadState возвращает degC только при legacy
  `lSettings.ChannelCalibrationEnabled`, иначе при АХ возвращает mV.
- Core TryGetTagAutoUnit отдаёт SourceUnitName только через специальную ветку
  MIC185; MIC140 получает промежуточный UnitOut аппаратной АЦП-ГХ.
- RefreshUnitChoices сначала ограничивает категорию AutoUnit и может вообще
  не использовать список допустимых единиц, возвращаемый provider.
- MIC140 уже обрабатывает АЦП, КХС и термопару в datasource, но публикация
  `AddBlockSamples(..., True)` обходит также внешнюю канальную ГХ. Замена True
  на False без разделения ступеней повторно применит аппаратную ГХ.

Исходный сценарий воспроизведён отдельным SourceUnitPipelineUiSmoke:
проверка `Core AutoUnit must prefer complete datasource stage, not ADC mV`
падает при выбранном температурном режиме и выключенной внешней канальной ГХ.
Исправлено в 0.1.200: provider объявляет режимы источника, диалог применяет
выбор через него; полный аппаратный выход хранится отдельно в проекте.
Core получает подготовленный физический блок и применяет только внешнюю ГХ,
не повторяя АЦП. MIC140 обновляет кэш пересчётов между блоками при Apply.
Отсутствующие/несовместимые ступени отклоняются при холодной подготовке.

Forced Windows build 0.1.200: exit 0. Native SourceUnitPipelineUiSmoke:
температурный/напряжительный выбор MIC140, Apply/Cancel, JSON roundtrip,
независимые флаги, численный Core scalar/block и AH off цепочки — PASS.
Полный аппаратный расчёт MIC140 с реальным TC/CJC не проверялся на приборе.
Аппаратные настройки пользователя и живой сеанс не изменялись; установки нет.

## Симптом

Дополнение 0.1.205: обнаружен несогласованный native combo: текст degC при
ItemIndex=-1/старом индексе; перестройка теперь восстанавливает оба значения.
Три цикла degC/Auto/OK/reopen, включая прежний uV, проверены Windows/Linux GTK.
Список при множественном выборе теперь пересекает допустимые режимы всех
источников; вся группа предварительно проверяется до первого SetUnits.
Пустая TC в температурном режиме получает реальную K/К_ГОСТ Р 8... при наличии;
UTF8 каталог и полное имя 8.585-2001 исправлены. Существующая TC не заменяется.

Дополнение 0.1.204: прежний pending UI режим не обновлял datasource до Apply,
поэтому вложенный аппаратный редактор показывал mV при выбранном degC.
Решение перенесено в модель: явный Tag.SetUnits вызывает общий интерфейс
источника немедленно. Внутренний UnitName не вызывает рекурсивную команду.
Также аппаратный редактор молча сбрасывал degC в mV при пустом имени TC;
этот сброс удалён, неполный режим проверяется перед запуском сбора.
Вход в форму и Refresh защищены от команд единицы/изменения Auto.
Тесты проверяют typed настройки до Apply, обратную связь и неизменность Auto
при входе/выходе; live MIC140 атомарно обновляет модель и подготовленный кэш.

Дополнение 0.1.203: программный предпросмотр АХ ошибочно обрабатывался OnExit
как ручной выбор и выключал Auto. Проверяется изменение относительно последнего
показанного текста. При ручном Apply provider восстанавливал старый code во
время смены режима, а StoreToTags не возвращал draft.UnitName при Auto=False.
Это давало degC -> code. Теперь manual draft восстанавливается после provider.
Native smoke проверяет оба сценария и реальные typed settings источника.

Дополнение 2026-11-10 (0.1.202): OnSelect не покрывал ручной ввод combo;
Auto возвращал code при AH off до передачи режима provider. Добавлены commit
ручного ввода и pending source mode для предпросмотра. Явный физический выбор
включает АХ как часть команды выбора режима; само Auto флагов не переключает.
Тест начинает с реального mV + AH off и проверяет degC после Auto/Apply и
температурный режим в typed настройках DataSource, а не только подпись тега.

После выбора термопарной ГХ и компенсации холодного спая диалог тега продолжал
показывать `mV`. Снятие галки аппаратной ГХ также не переводило единицу в коды
АЦП.

## Подтверждённая причина

- Настройки канала хранят отдельные признаки аппаратной ГХ, термопарной ГХ и
  режима выхода.
- Диалог канала сохранял имя термопарной ГХ, но не обновлял `OutputMode` и
  `ChannelCalibrationEnabled`.
- Диалог тега менял единицу по галке канальной ГХ, не учитывая состояние
  аппаратной ГХ.
- В нескольких местах существовали отдельные присваивания `mV`/`degC`, поэтому
  загрузка проекта, аппаратный диалог и runtime могли показывать разные единицы.

Старый `D:\works\bu\recorder_lnx\001_unstable` подтвердил рабочий конвейер
КТХС и порядок преобразований, но в нём также не было полного единого правила
переключения единицы.

## Исправление

- Добавлен единый `RecorderMic140ApplyTagOutputPresentation`.
- Инвариант: без аппаратной ГХ — `code`; с аппаратной ГХ и напряжительным
  режимом — `mV`; с аппаратной и термопарной ГХ — `degC`.
- Выбор/очистка термопарной ГХ обновляет `OutputMode` и
  `ChannelCalibrationEnabled`.
- Массовое применение настроек копирует эти поля для каждого выбранного канала.
- Единый метод вызывается после аппаратного диалога, изменения галок,
  загрузки конфигурации, назначения ГХ и перед программированием источника.
- Галка аппаратной ГХ сразу меняет показанную единицу в `TagSettingsDialog`.

## Проверка

Полная сборка `lazbuild -B RecorderLnx.lpi` завершена с exit code 0.
Аппаратный протокол и код сбора данных не изменялись.

## Follow-up 2026-09-04: единица источника и AutoUnit

Повторная проверка с командой выявила, что прежний единый метод смешивал три
разных состояния: физический режим источника, включение аппаратной ГХ тегом и
автоматическую подпись единиц. Из-за этого ручная единица перезаписывалась, а
при загрузке проекта устаревшая копия флага из MIC-140 channel config могла
перекрыть уже загруженное свойство тега.

Исправлен контракт:

- `SourceValueMode` всегда отражает физический режим MIC-140: `mV` либо `degC`;
- `HardwareCalibrationEnabled` тега выбирает сырые коды или физическое значение;
- при `AutoUnit=True` единица равна `code` для сырых данных и единице источника
  для включённой аппаратной ГХ;
- при `AutoUnit=False` пользовательская единица не изменяется;
- при загрузке нового JSON флаг тега является главным и синхронизирует legacy
  channel config; fallback из channel config оставлен только старым проектам.

MIC-185 не изменялся. Forced-сборки RecorderLnx, Tags и DataSources завершились
успешно. DataSources suite прошёл; Tags suite остановился на существующей
проверке EventBus `expected 0, got 1`, не связанной с единицами MIC-140.

## Follow-up 2026-09-04: включённая ГХ продолжала показывать коды

На активном проекте у `140_{40_1}` подтверждены корректные данные: флаг тега
включён, ГХ `MIC140 sn0326 06_100mV ch01` присутствует, а код около `25303`
должен преобразовываться примерно в `73 мВ`.

Причина была в runtime-кэше: указатель на ГХ фиксировался только при подготовке
источника. После включения галочки во время Preview в кэше оставался `nil`, а
решение о преобразовании дополнительно читалось из копии флага в конфигурации
источника вместо свойства тега.

Исправлено:

- runtime MIC-140 кэширует объект ГХ независимо от текущего состояния галочки;
- ветка `code/physical` на каждом блоке выбирается по
  `TRecorderTag.HardwareCalibrationEnabled`;
- если ГХ назначена во время Preview, существующий кэш подхватывает её без
  пересоздания источника, TCP-сессии и без аппаратного Configure;
- автоматическая единица также определяется по флагу тега;
- MIC-185 не изменялся.

Проверка: forced-сборки `RecorderDataSourcesTest.lpi` и `RecorderLnx.lpi` — OK;
полный существующий `RecorderDataSourcesTest` — все сценарии passed. В текущем
журнале MIC-140 `.40` не прошёл TCP TEST, поэтому показанный на экране старый
буфер не является аппаратной проверкой свежего потока.
