# 2026-09-14 — ГХ из БДГХ разворачивалась в конфигурацию проекта

## Симптом

После импорта большой табличной ГХ из БДГХ файл проекта содержал весь массив
`points`, хотя пользователь не создавал эти точки вручную.

## Причина

Модель калибровки не сохраняла происхождение. Импорт из БДГХ загружал обычную
полную копию `TRecorderCalibration`, а общий сериализатор безусловно записывал
её коэффициенты и все точки.

## Исправление

- В модель добавлен переносимый `SdbKey`.
- Импорт из БДГХ устанавливает этот ключ.
- Проект сохраняет для такой ГХ только тип, имя и `sdbKey`.
- При загрузке содержимое ГХ заново читается из актуального корня БДГХ.
- Явное проектное редактирование или создание локальной копии снимает `SdbKey`,
  поэтому автономная изменённая ГХ продолжает сохраняться целиком.
- Старые проекты с массивами `points` загружаются по прежнему контракту.

## Проверка

Forced Win64-сборка RecorderLnx — exit 0.

## Остаточный риск

Нужен пользовательский round-trip реального проекта с его сетевым каталогом
Mera Files/SDB; при недоступной БДГХ ссылка и имя сохраняются, но преобразование
не имеет точек до восстановления каталога.
