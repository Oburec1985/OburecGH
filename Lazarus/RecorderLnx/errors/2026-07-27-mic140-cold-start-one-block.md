# MIC-140: один блок после холодного старта

## Симптом

После перезагрузки MIC-140 RecorderLnx получал один блок и затем поток
останавливался. После настройки прибора оригинальным Recorder поток становился
устойчивым.

## Факты

- Настройки scan, stride `55`, FIFO ready `110` и период `200 мс` ранее
  совпали с эталонным дампом.
- Рабочий отладочный пример начинал сеанс с `CMD_TEST_LOAD`.
- `mdpEthernet81::CheckInitialized` оригинала передаёт в `CMD_TEST_LOAD`
  максимальный массив из 32 нулевых WORD и проверяет `reply[0] = 1`.
- Эталонный дамп оригинала содержит:
  `TEST_LOAD → REPLY → CMD_RESET → REPLY → RESETSCANMAIN → ~5 с →
  RESETSCANMAIN → STOPSCANMAIN → Config`.
- Производственный драйвер пропускал `TEST_LOAD` и ждал после `CMD_RESET`
  только 500 мс, после чего сразу начинал конфигурирование.

## Ранее предполагавшаяся причина

Init не воспроизводил очистку командного автомата и полный асинхронный цикл
готовности BIOS. На холодном контроллере Config мог начаться до завершения
reset; единичный блок считался остатком прежнего/промежуточного состояния scan.

Пользователь проверил старый тестовый проект из бэкапа `008` после перезагрузки
прибора: первая инициализация на нём также сбоит. После подготовки прибора
Original Recorder тест запускает устойчивый поток. Это подтверждает дефект
cold-init, но ещё не доказывает обязательность трёх проходов Config и всех
общих trigger-команд Original Recorder.

## Экспериментальное изменение

- В `TMic140v2Tcp` добавлен `TestLoad`.
- `TRecorderMic140Device.InitializeDevice` теперь выполняет подтверждённую
  дампом последовательность и ждёт готовности BIOS до Config.
- Тестовый проект `Tests/mic140/Mic140ProtocolDebug_Codex` не изменялся.

## Проверка

- `RecorderLnx.lpi` полностью пересобран `lazbuild -B`, exit code `0`.
- Формат команд и интервалы вручную сопоставлены с эталонным сетевым дампом.
- Сквозной автоматический запуск текущей конфигурации остановился до создания
  главного окна, на загрузке проекта; это отдельный блокер тестовой оснастки.
- Окончательный cold-start PASS для изменения ещё не получен.
- EXE из бэкапа `008` является эталоном рабочих таблиц и потока после
  предварительной подготовки прибора, но не эталоном холодного Init.
- Новый дамп после перезагрузки требуется сравнить с cold-init Original Recorder
  и с таблицами scan `008`.
- Аппаратный PASS требует:
  минимум 8 секунд и около 40 последовательных блоков при периоде 200 мс.

## Правило предотвращения

Не сокращать Init сетевого прибора до успешного чтения идентификатора.
Команды очистки автомата, аппаратного reset и ожидания готовности переносятся
из оригинала вместе с порядком и временными барьерами. Проверка выполняется
после холодного старта, потому что тёплый прибор скрывает ошибку жизненного
цикла.
