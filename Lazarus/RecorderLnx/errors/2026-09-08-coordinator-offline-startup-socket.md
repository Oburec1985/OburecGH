# Coordinator offline: ESocketError при старте RecorderLnx

## Симптом

При запуске RecorderLnx под отладчиком без Coordinator на
`127.0.0.1:8765` Lazarus останавливался в `TFPHTTPClient.Post` на
`ESocketError: Connection refused`.

## Причина

Клиент Coordinator включён по умолчанию и сразу выполнял HTTP `hello`.
`TFPHTTPClient` сообщает об обычной недоступности необязательного сервиса через
исключение. Код перехватывал его, однако отладчик показывал first-chance
exception до входа в обработчик.

## Исправление

Перед HTTP-вызовом endpoint проверяется через общий небросающий исключений
`RecorderOpenBoundTcpStream`. При отказе клиент остаётся автономным, сохраняет
причину и переходит в штатный backoff, не вызывая `TFPHTTPClient`.

## Проверка

- forced-сборка `RecorderLnx.lpi`: exit code 0;
- без запущенного `RecorderCoordinator` RecorderLnx оставался работающим более
  пяти секунд; стартового socket-исключения не возникло;
- `git diff --check`: ошибок нет, только предупреждения о будущей нормализации
  переводов строк в уже изменённых файлах.

## Остаточный риск

Проверка и HTTP-запрос используют два последовательных TCP-соединения, поэтому
теоретически остаётся TOCTOU-окно, если сервер исчезнет между ними. Для
production-клиента нужен единый не бросающий исключений transport и mock-тесты
разрыва/reconnect. Текущее исправление закрывает воспроизводимый холодный старт
при отсутствующем локальном Coordinator.
