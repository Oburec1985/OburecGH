# OPC UA-теги не отображались после загрузки проекта

## Симптом

После запуска RecorderLnx теги настроенного OPC UA-источника отсутствовали в
правом списке и появлялись только после входа в конфигурацию и выхода из неё.

## Причина

`TRecorderOpcUaDataSource` успешно подготавливал OPC UA-устройство, но не
регистрировал его в общем `uRecorderHardwareLiveDevices`. Поэтому
`TMainForm.UpdateActiveSourceIds` не мог подтвердить живую связь и исключал
`SourceId` из видимых. Редактор OPC UA временно маскировал дефект собственным
`RegisterActiveSource`.

## Исправление

- После успешного `PrepareHardware` OPC UA datasource регистрирует живое
  устройство по своему `SourceId`.
- При потере связи, повторной подготовке и уничтожении datasource регистрация
  снимается.
- Отложенная стартовая подготовка уже выполняет `UpdateActiveSourceIds`,
  перестраивает правый список и активную страницу до закрытия splash screen.

Дополнительно программный переход из цифровой таблицы/индикатора теперь сначала
снимает прежнее выделение в правом списке, поэтому подсвечивается ровно один тег.

## Проверка

- Полная forced-компиляция основного проекта прошла до линковки; штатный EXE
  нельзя было заменить, поскольку он запущен (Windows error 5).
- Forced-сборка `RecorderLnxDragVerify.lpi` с тем же кодом полностью
  скомпилирована и слинкована, exit code 0.
