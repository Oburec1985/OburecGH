# 2026-09-21 — подписи перекрывали поля в настройках Linux

## Симптом

В диалоге «Настройка» под Astra Linux длинные подписи вплотную подходили к полям или перекрывали их. На MIC200 это проявлялось при экране 1680×1050 и Linux-шрифте.

## Подтверждённая причина

LCL автоматически вычислял фактическую ширину `TLabel` по системному шрифту, а соседние `TEdit`, `TComboBox` и `TRadioButton` оставались на абсолютных координатах из LFM. Координаты были рассчитаны по более узким Windows-метрикам и не сохраняли зазор на GTK.

## Исправление

`TRecorderSettingsDialog.AdjustRecorderTabTextSpacing` после загрузки формы ставит соседние контролы после фактической правой границы подписи или переключателя с зазором 8 px. Исправлены строки отображения, сигналов и условий старта/останова. Версия поднята до 0.1.47.

## Проверка

- forced Windows build `RecorderLnx.lpi`: exit 0;
- свежий Linux ELF собран в Astra VM и не имеет отсутствующих библиотек;
- DEB 0.1.47 собран и установлен на MIC200;
- встроенный проход создания форм на MIC200: exit 0;
- RecorderLnx 0.1.47 возвращён в обычный режим, процесс использует `/opt/mera/RecorderLnx/RecorderLnx`.

Общий Linux build script завершился кодом 1 только на отдельной `PluginInfoProbe` из-за повреждённой локализованной строки; основной RecorderLnx ELF и DEB проверены отдельно.

## Правило профилактики

Соседний с автоматически измеряемой подписью контрол нельзя располагать по фиксированному X. После загрузки формы вычислять его позицию через `Label.Left + Label.Width + gap` и проверять на Astra с фактическим системным шрифтом.
