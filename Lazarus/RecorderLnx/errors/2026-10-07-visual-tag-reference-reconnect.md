# Визуальный элемент терял тег после его пересоздания

## Симптом

Привязка визуального элемента могла остаться с прежним числовым `TagId` либо
очиститься в редакторе, если тег временно отсутствовал. После появления канала
с тем же именем соединение само не восстанавливалось.

## Причина

Часть потребителей разрешала пару `TagId/TagName` сначала по ID. ID является
идентификатором текущего экземпляра и после пересоздания канала не подходит как
постоянная ссылка. Редакторы с `csDropDownList` не позволяли сохранить имя
отсутствующего тега.

## Исправление

- Добавлен общий `RecorderResolveTagReference`: непустое строковое имя является
  авторитетным, ID используется только для старых конфигураций без имени.
- Реестр тегов получил `StructureRevision`; 3D Skin переразрешает подготовленные
  ссылки только при изменении состава реестра, а не на каждом кадре.
- В базовой модели визуального элемента сохраняется `UseInactiveTag`.
- В общем редакторе и редакторе Skin добавлен флажок
  `Использовать неактивные`; при его включении можно оставить вручную имя
  отсутствующего тега.
- Строковая ссылка и флажок сохраняются в GUI-конфигурации.

## Проверка

`RecorderFormModelTest` удаляет векторный тег кости, создаёт новый экземпляр с
тем же именем и другим ID и подтверждает автоматическое возобновление движения.
Также проверен roundtrip `UseInactiveTag`. Все тесты passed.
`RecorderLnxDragVerify.lpi -B` собран успешно. Штатный EXE удерживается текущим
процессом RecorderLnx, поэтому `RecorderLnx.lpi` дошёл до линковки и получил
Windows error 5.
