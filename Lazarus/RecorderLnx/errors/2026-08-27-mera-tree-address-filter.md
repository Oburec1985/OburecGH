# Mera File запускался без сигналов из-за адреса дерева

## Симптом

Источник Mera File был включён, файл существовал, Preview переходил в рабочее
состояние, но теги файла не получали данные.

## Причина

Фабрика runtime-источников формировала фильтр выбранных сигналов только из
`Tag.Address`. В сохранённом проекте этот адрес содержит индекс источника в
дереве (`5- 2- 1`), тогда как внутри файла `.mera` хранится исходный адрес
канала (`1- 2- 1`). Поэтому `TRecorderMeraFileDataSource.Start` отбрасывал все
сигналы и запускался с пустым списком проигрывателей.

## Исправление

В фильтр Mera добавляется также имя тега. Оно не зависит от позиции источника
в дереве и уже поддерживается `IsSignalSelected`. Адрес оставлен для
совместимости со старыми проектами. Добавлена одноразовая диагностика числа
открытых сигналов и первой фактической публикации.

## Проверка

- forced Windows build `RecorderLnx.lpi`: exit 0;
- автоматический `--preview-seconds=5`: exit 0;
- журнал: `signals=10`, затем `first data published` через ~0,3 с;
- векторный MERA-сценарий `RecorderDataSourcesTest` прошёл; полный набор далее
  остановился на известном нестабильном ожидании нулевого времени скалярного
  MERA (`0,000` против нормализованного `0,016`).
