# Linux: External exception code 13 при запуске

## Симптом

Linux-сборка RecorderLnx после загрузки конфигурации показывала модальное окно
`External: Unknown exception code '13'`, адрес `$41F321`. Процесс оставался
жив, но запуск приложения не завершался.

## Подтверждённые факты

- `LogLinux.log` обрывался после создания настроенных источников данных.
- Запуск ELF под GDB с остановкой на `SIGPIPE` воспроизвёл ошибку.
- Главный поток остановился в `fpSend`; `$41F321` соответствует `fpSysCall`.
- Недоступный TCP peer может закрыть соединение между проверкой сокета и
  отправкой стартовой команды.

## Причина

Процесс не игнорировал POSIX-сигнал `SIGPIPE`. Поэтому запись в уже закрытый
TCP-сокет превращалась в внешнее исключение FPC раньше, чем драйвер получал
возврат `EPIPE` и мог обработать отказ конкретного устройства.

## Исправление

В `RecorderLnx.lpr` после `Application.Initialize`, но до создания формы, для
UNIX установлен `fpSignal(SIGPIPE, SignalHandler(SIG_IGN))`. Дополнительно все
TCP-клиенты на `TSocketStream` устанавливают `WriteFlags or MSG_NOSIGNAL`.
Флаг сокета необходим для запуска из Lazarus IDE: отладчик может остановиться
на сигнале до того, как процесс применит `SIG_IGN`. Теперь `send()` вообще не
генерирует сигнал и возвращает драйверу обычную ошибку.

## Проверка

1. Полная Linux-сборка `lazbuild -B RecorderLnx.lpi` завершилась с кодом 0.
2. ELF запущен в активной X11-сессии VM с `--preview-seconds=5`.
3. Приложение записало `RecorderLnx started`, прошло `Stop -> Preview`, через
   5 секунд выполнило `Preview -> Stop` и завершилось с кодом 0. Модальное
   `External code 13` больше не появилось.
4. MC-032 был штатно помечен offline: из гостевой ОС сеть `192.169.12.87`
   недоступна на уровне маршрутизации (`Network is unreachable`), поэтому
   аппаратный поток MC-201 этим запуском не проверен.
5. Строгий запуск под GDB с `handle SIGPIPE stop print pass` прошёл полный цикл
   Preview и завершился нормально: GDB не зарегистрировал ни одного SIGPIPE.

## Правило предотвращения

Маркер: `RLNX_UNIX_SOCKET_SIGPIPE_2026_07_21`.

Каждый `TSocketStream`, выполняющий TCP-запись под UNIX, обязан устанавливать
`WriteFlags or MSG_NOSIGNAL`; процессная установка `SIG_IGN` остаётся вторым
рубежом. Ошибки закрытого peer должны доходить до драйвера как `EPIPE`.
Проверка — GDB с остановкой на SIGPIPE не останавливается при запуске с
недоступным TCP-источником, а остальные источники продолжают работать.

## Дополнение: сеть VM и MDP TCP write failed

Последующее `EMc201MdpProtocol: MDP TCP write failed` оказалось отдельным
следствием сети VM: единственный интерфейс `ens33` был `DOWN`, без адреса и
маршрута. После ручного DHCP он получил `192.168.112.128/24`, а ping и TCP/4000
до `192.169.12.87` прошли. Автоподъём закреплён через
`/etc/network/interfaces.d/ens33`.

Дополнительно исправлен контракт `TestLink`: TEST_LOAD выполняется в отдельной
probe-сессии, которая всегда закрывается; рабочий `Connect` открывает свежую
TCP-сессию. Ошибки Connect/Init/Config при старте теперь помечают источник
offline и не выходят исключением в GUI.

После исправлений Linux-сборка успешна. Автотест Preview 5 секунд получил
16 каналов MC-201, по 11520 отсчётов на блок каждые ~200 мс, затем штатно
выполнил Stop без `SIGPIPE` и `MDP TCP write failed`.

## Дополнение: BIOS MC-201 не найден при первом Linux-запуске

Причина: `CMc201DefaultBiosPath` содержал абсолютный путь машины разработчика,
а прежний Linux fallback зависел от одной фиксированной глубины build-tree.
Поток мог появиться только потому, что BIOS оставался загружен в модуле.

Добавлен общий `uRecorderResourcePaths`. BIOS теперь имеет логическое имя
`devices/mc201/mc_201a.bio`; поиск не зависит от CurrentDir и проверяет каталог
рядом с exe, переменную `RECORDERLNX_RESOURCES`, настроенный
`Mera Files/Resources` и дерево проекта при запуске из IDE. После сборки BIOS
копируется в `lib/<cpu>-<os>/resources/devices/mc201`.

Проверка: Windows использует встроенный ресурс (22040 байт); Linux-тест,
запущенный из `/tmp`, нашёл файловый BIOS (22040 байт). Полная Linux-сборка
RecorderLnx успешна, файл размещён рядом с ELF.
