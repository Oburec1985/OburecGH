# MC-032: исключение MDP command timeout при остановке просмотра

## Симптом

При остановке RecorderLnx после просмотра отладчик останавливался на `ERecorderDeviceError: MC-032 stop: MDP command timeout`.

## Корневая причина

После потока данных ответ `STOPSCANMAIN` иногда не находился до таймаута среди оставшихся потоковых пакетов. Низкоуровневый `TMc032Device.Stop` уже закрывал неоднозначную TCP-сессию, однако `TRecorderMcbusDevice.Stop` повторно превращал этот безопасный fallback остановки в исключение.

## Исправление

Остановка сделана идемпотентным teardown: при отсутствии подтверждения `STOPSCANMAIN` ожидаемо очищаются буферы, сессия остаётся закрытой и адаптер переходит в `rdsDisconnected` без исключения. Runtime-источник пишет причину принудительного отключения в `[MCBUS] stop forced disconnect`.

## Автоматическая проверка

Добавлен `Tests/RecorderTests/McbusPreviewSmoke`. Он использует production `TRecorderMcbusDevice`, запускает сбор на заданное число секунд, вызывает `ReadBlock` с периодом RecorderLnx и проверяет остановку.

Реальный стенд `192.169.12.87:4000`, 3 секунды, 200 мс:

- 15 полученных блоков из ожидаемых 15;
- 5,00 блока/с;
- каждый блок: 16 каналов по 68 отсчётов;
- остановка без исключения, итоговое состояние `rdsDisconnected`.

## Отклонённая гипотеза

Драйвер не испытывает нехватку данных: чтение без pacing получило 191 полный блок за 3 секунды. Период 5 блоков/с задаётся worker-циклом источника, а не частотой сырых кадров контроллера.
