# Переименование спектрального тега `fmax` в `f1`

## Симптом и риск

Требовалось заменить суффикс частоты максимума `fmax` на `f1`. Простая замена
строк при создании и публикации оставила бы в старых проектах два разных тега и
сломала бы компоненты, привязанные к прежнему `TagId`.

## Причина

Имя производного тега использовалось не только для отображения, но и как один из
ключей материализации. При смене соглашения старый объект переставал находиться.

## Исправление

При подготовке конфигурации старый автоматический тег ищется по точному legacy-имени
или по `SourceId` и legacy-адресу `<полоса>/fmax`. Найденный объект переименовывается
в `f1`, его адрес обновляется до `<полоса>/f1`, а `TagId` сохраняется. Публикация
оценки выполняется только в тег с новым суффиксом.

## Проверка

- `TestSpectrumMath2.exe`: PASS;
- тест подтверждает новый суффикс, отсутствие старого имени и сохранение `TagId`;
- полная сборка `RecorderLnx.lpi`: exit code 0.
