# 2026-09-22 — Mera file сбрасывал ручную единицу тега

## Симптом

Пользователь сохранял для тега ручную единицу `g` с выключенным флагом
`AutoUnit`, но после перезапуска RecorderLnx источник Mera file возвращал
единицу из `YUnits` файла (`В`).

## Причина

Загрузка проекта правильно восстанавливала `UnitName` и `AutoUnit`. Затем
создание runtime-источников вызывало `ConfigureTags`, а локальная процедура
`TRecorderMeraFileDataSource.DoCreateTags.UpdateTag` безусловно копировала
`lSignal.UnitsName` в уже загруженный тег.

## Исправление

Единица из Mera-файла назначается только тегу с `AutoUnit=True`. Новые теги
по умолчанию имеют автоматические единицы, поэтому их начальная настройка
сохранилась. Ручная единица существующего тега больше не меняется ни при
старте, ни при повторной конфигурации источника.

## Проверка

- В `RecorderDataSourcesTest` добавлен цикл `mm (авто) → g (ручная) → mm (авто)`.
- Forced-сборка и запуск `RecorderDataSourcesTest`: exit code 0.
- Forced-сборка `RecorderLnx.lpi`: exit code 0 после завершения запущенного EXE.

## Правило

Метаданные источника могут обновлять единицу существующего тега только при
`AutoUnit=True`; при `AutoUnit=False` сохранённое пользовательское значение
является главным.
