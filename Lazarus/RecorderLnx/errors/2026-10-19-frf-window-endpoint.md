# FRF: конец экспоненты должен участвовать в DSP

## 2026-10-19: левая граница и зависшие спектральные результаты

Пользователь: левая граница не отсекает воздействие; после перемещения окон
спектральные характеристики не меняются. Курсоры должны быть ярко-синими.

Подтверждено: Round(N*fraction) в DSP может сохранять отсчёт до физического
начала окна. Оракул Fs=8/16, окно [.13,.6): DC Sxx должно быть 25, было 64.
Использован Ceil с допуском 1e-9 отсчёта для полуоткрытой поддержки [start,end).
Пустая поддержка не должна искусственно сохранять один отсчёт.

Вторая проверяемая причина: EstimateImpactMoments отклоняет всю кривую из-за
одного нулевого FFT-бина воздействия/взаимного спектра. Тогда filter worker
не публикует даже новые подготовленные спектры, хотя временной график уже
показывает новое окно. Агент воспроизводит это на сигнале с notch после обрезки;
до проверки исправления не считать закрытым.

UI: ярко-синие линии 3px и нижние ручки со смещением внутрь 14px, чтобы
не перекрывать оранжевую конечную ручку экспоненты. Смещение компенсируется
при переводе координат мыши во время. Последний completion fix таймера
должен проверяться без ручного Refresh, иначе тест скрывает stale-график.

## Регрессия 0.1.188: release и живой пересчёт

Запрос: маркеры откатываются при отпускании; изменение экспоненты должно сразу
перестраивать отклики, прямоугольник — воздействие, и затем частотные линии.
Подтверждено: LCL `WMLButtonUp` снимает mouse capture до `DoMouseUp`, наш
`CaptureChanged` успевает отменить draft до commit. Прямые вызовы view handlers
в прошлом тесте обходили этот порядок. Дополнительно прямоугольная маска
ошибочно применялась ко всем каналам, а пересчёт работал лишь при release.
Регрессионный тест с `Perform(LM_LBUTTONDOWN/MOVE/UP)` воспроизвёл
`end handle X not committed` на 0.1.188; прежний прямой вызов `chartMouseUp`
ошибочно проходил. Исправление в работе: release guard вокруг LCL dispatch,
независимые окна каналов,
coalesced live worker recalculation и устойчивость к устаревшим snapshots.

Дополнение запроса: снятие галки должно возвращать сигналы/FRF без интерактивных
масок. Проверяется сравнение с baseline до включения для RAM/ring/saved; при
снятии галки во время drag нельзя потерять желаемый флаг из-за отмены preview.
Повторное пользовательское наблюдение подтвердило пробел доставки: service
восстанавливал baseline, но таймер view выключался на release/при drag=0 до
готовности worker. Без периодического refresh владельца линии оставались старыми.
Добавлен явный snapshot-флаг `FilterRebuildPending`; UI доводит обновление до
готового результата независимо от окончания жеста. Проверка в работе.

### Дополнительные проверки этой итерации

- Численные тесты независимых EXC/RESP масок проходят также при глобальном
  FFT-окне `iwExponential`: интерактивный уровень отклика отделён от него.
- Runtime latest-wins, удаление удара во время пересчёта и ring/saved workspace
  PASS. Worker владеет копиями raw-блоков до конца транзакции.
- В ring/saved отключение окон восстанавливает каждый Y отсчёт времени,
  SPM, FRF, фазы и когерентности; исходный файл не меняется.
- Реальный UI dispatch проходил несколько раз, но последующие прогоны выявили
  отдельную потерю native capture. В trace есть случай с другим foreground HWND
  и нажатой физической кнопкой; временная диагностика проверяет вмешательство
  рабочего стола отдельно от исходного дефекта release. Пассивный захват без
  live-редактирования выдержал 5/5 контрольных прогонов. Проверка в работе.
- Замер DSP 1 с / 57600 Гц / FFT65536: 8 window-only пересчётов, максимум
  31 мс; CPU тестового процесса 93.75 мс суммарно. FFT-план/буфер переиспользуются;
  транзакционные снимки и подготовленные результаты всё ещё выделяют память.

## Симптом и проверка

При переходе от native trackbar к двум графическим маркерам экспоненты второй
маркер должен независимо менять время и относительный уровень спада.

## Подтверждённые факты

- `uRecorderImpactHammerService.CopyTimeSeries` использует разность
  `ExponentialEndSeconds - ExponentialStartSeconds`.
- `ConfigureDsp` и `PrepareCapturedResponses` передавали только начало и уровень;
  `uRecorderImpactDsp` делил показатель на конец прямоугольного окна минус начало.
- Поэтому новый независимый X конца экспоненты не мог согласоваться с FRF.

## Гипотеза и критерий

Причина — потеря endpoint при передаче UI/service → DSP, а не частотный курсор.
Передать endpoint явно; тест с одинаковым уровнем и разными временами конца
должен получить разные коэффициенты спада по физической длительности.

## Исправление и проверка

Добавлен явный `ExponentialEndPositionFraction`; оба service-пути передают
физический конец. DSP заранее кеширует дробные координаты начала/длительности;
значение 0 сохраняет legacy-поведение прямых старых callers. На частичной записи
обрезается только прямоугольная поддержка, не физическая опора экспоненты.
Вырожденный интервал отклоняется до постановки пересчёта.

Forced DSP suite PASS: два разных endpoint, дробное начало, продолжение после
endpoint, endpoint за длиной доступной порции, legacy fallback и неизменность
воздействия. Forced Windows/Linux main builds PASS; Linux `MISSING_LIBS none`.
Service response-fs, manual-portion и focused window-integration regression PASS.
UI graph gestures, отмена/применение и GL readback PASS; оранжевые маркеры
проверены на снимке экрана. Полный service suite
останавливается на соседнем `half maximum FRF maps yellow` до проверки окон;
это не объявлено успешным тестом данной итерации. Общий RunIntegration после
оконной секции также выявляет ошибку deferred-stop; focused window-integration
завершается до неё. Эта соседняя ошибка не скрыта и не входит в подтверждённый
оконный сценарий.

Ограничение старого сценария: если начало спада уже находится за концом короткой
порции, существующая валидация DSP отклоняет окно. Этот случай не объявлен
поддержанным. Исходные raw-отсчёты не изменяются.
