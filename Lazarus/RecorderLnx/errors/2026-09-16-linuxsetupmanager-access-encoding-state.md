# LinuxSetupManager: `?` в результате прав и сброшенные галки

## Симптом

После «Применить» раздел «Пользователи и права» показывал русские слова как
`?`. При следующем открытии ранее добавленные группы не отображались галками.

## Подтверждённая причина

Русские литералы в Pascal-модуле были UTF-8, однако FPC `WriteLn` при запуске
CLI с локалью `C` преобразовывал их в кодовую страницу консольного потока и
заменял символы на `?` ещё до чтения GUI. Отдельно форма всегда создавала
галки с `False` и не читала фактическое членство пользователя в группах.

## Исправление

На входе CLI заданы UTF-8 для преобразований, stdin/stdout/stderr; русские
сообщения операции доступа явно передаются в `WriteLn` как `UTF8String`.
Встроенная команда `access show-state --user` возвращает группы из `id -nG`.
Форма загружает галки при открытии, после выбора другого пользователя и после
успешного применения.

## Проверка

- Forced Win64-сборки GUI и CLI — exit 0.
- Linux-сборка в Astra-VM — exit 0.
- Под `LC_ALL=C` план с `USER=user; GROUPS=sudo,dialout,plugdev` содержит
  точную UTF-8 строку `Добавить user в группу sudo`.
- `access show-state --user user` в VM возвращает строку `groups=`.

## Ограничение

Установка нового бинарника на рабочие KIP не выполнялась; пакет 0.1.23 остаётся
черновым. Ручная проверка GUI после переустановки пакета ещё нужна. Снятие
галки пока не удаляет уже имеющееся членство в группе: операция добавляющая.
