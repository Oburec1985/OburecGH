# Перепутаны масштаб и чувствительность ГХ

## Симптом

Редактор показывал хранимый множитель `Scale` в первой строке под названием
«Масштаб» с размерностью `выход/вход`, а обратную величину — как безымянное
`1/a`. Для датчика с чувствительностью `V/ф.в.` это провоцировало ввод значения
в неверном направлении и получение `V²/ф.в.` при умножении.

## Причина

В интерфейсе не были разделены два разных понятия:

- чувствительность датчика `S = вход/выход`;
- вычислительный масштаб `K = 1/S = выход/вход`.

Внутренняя формула `output = input * Scale` корректна, но подписи и порядок
полей не соответствовали физическому смыслу.

## Исправление

Первая строка редактора теперь показывает и редактирует чувствительность
`вход/выход`, вторая — масштаб `выход/вход`. Изменение любого поля пересчитывает
второе как обратную величину. В модель сохраняется масштаб; runtime продолжает
умножать вход на него. Смена единиц пересчитывает обе отображаемые величины.
Сквозная чувствительность pipeline также показывается как `вход/выход`, а не
как вычислительный масштаб.

Исходная единица канала отделена от автоматически отображаемой выходной
единицы тега. При `RebuildScales` переход между единицей текущего значения и
`UnitIn` следующей ГХ включается в кэшированный итоговый коэффициент. Поэтому
для `1 V` и чувствительности `20 mV/(m/s²)` получается
`1 * 1000 / 20 = 50 m/s²`. На каждом отсчёте pipeline не пересчитывается:
используется готовый `ResultScale`.

## Правило предотвращения

В коде и сериализации `Scale` означает только вычислительный множитель
`выход/вход`. Термин «чувствительность» использовать только для обратной
величины `вход/выход`; формулы и единицы всегда показывать рядом.

## Проверка

Для примера `V -> mV` менеджер возвращает `1000`; при чувствительности
`20 mV/(m/s²)` хранимый масштаб равен `0.05 (m/s²)/mV`, поэтому собранный
`ResultScale = 1000 * 0.05 = 50`. Forced Windows/Linux сборки завершились с
exit code 0, Linux ELF не имеет недостающих библиотек.
