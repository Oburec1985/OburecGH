# Ping-поиск не находил MIC-200 / MC-032

## Симптом

Общий аппаратный автопоиск с включённой галкой `Ping` не находил MIC-200,
пока MC-032 не был добавлен вручную или его адрес не появился в ARP-кэше.

## Причина

Протокольная проверка MC-032 уже существовала, но список кандидатов состоял
только из настроенных источников и адресов ARP-кэша. Неиспользованный адрес
реального прибора `192.169.12.87` мог отсутствовать в обоих списках. Кроме
того, отдельный ручной поиск содержал ошибочную подсеть `192.169.13.*`.

## Исправление

Ping-режим явно добавляет `192.169.12.1..254`, сначала проверяет TCP/4000 с
коротким таймаутом и только для открытых узлов читает BIOS контроллера через
`TMc032Device.TryConnect`. Валидный ответ содержит тип и серийный номер
контроллера; отдельный `TEST_LOAD` после этого не нужен. Проверка не
программирует прибор, не читает модули и не запускает сбор. Дефолтная подсеть
теперь задана одной константой `CMc201DefaultDiscoverySubnet`.

## Проверка

`C:\lazarus\lazbuild.exe -B RecorderLnx.lpi` завершён с exit code 0.
Живой CLI дошёл до протокольного обмена с `192.169.12.87:4000`, но прибор не
ответил на команду в пределах 1200 мс; вероятная причина — занятая
однопользовательская сессия. Окончательная проверка выполняется из UI при
свободном приборе.
