# SVG-картинка не обновлялась и занимала не весь компонент

## Симптом

После выбора другого SVG компонент продолжал показывать предыдущий файл.
Тестовый прямоугольник с градиентом занимал только часть ширины компонента.

## Подтверждённые причины

- `PreviewFileName` безусловно предпочитал уже загруженный файл и не проверял,
  остался ли он в новом списке `Images`.
- `SelectFile` считал совпадающий путь достаточным признаком актуальности, хотя
  файл мог быть повторно выбран или заменён на диске.
- SVG `26.2 rectangle gradient.svg` имеет viewport `400x110`, а видимый
  прямоугольник — `300x100`; масштабирование viewport закономерно оставляло
  пустую четверть ширины.

## Исправление

- В модель картинки добавлена ревизия ресурсов, изменяемая диалогом и при
  копировании; смена ревизии принудительно перезагружает файл.
- Текущий файл сохраняется только если он присутствует в актуальном списке.
- Общий SVG-рендерер определяет alpha-границы рисунка, вырезает пустые поля и
  масштабирует видимое содержимое; его используют контрол и превью.

## Проверка

- Forced Windows-сборка `RecorderLnx.lpi` завершилась с exit code 0.
- Проверочный SVG содержит подтверждённое различие viewport и границ рисунка.

## Оставшийся риск

Нужна визуальная проверка в GUI для SVG с фильтрами или полностью прозрачными
декоративными областями.
