# MIC-200: тесная компоновка и чрезмерная точность осциллограммы

## Симптомы

- splitter pipeline ГХ почти не влиял на место для сквозной чувствительности;
- параметры страницы «Рекордер» пересекались при GTK-метриках;
- осциллограмма показывала шумовые значения вроде `0.000023 m/s2`.

## Причины

Подпись чувствительности имела фиксированную высоту независимо от нижней панели.
Страница «Рекордер» сохраняла размеры и интервалы Windows. Значения графика
форматировались без привязки к диапазону шкалы и без настройки модели.

## Исправление

Высота подписи теперь следует за нижней панелью splitter. Для страницы
«Рекордер» увеличены вертикальные интервалы и правая область условий. В модели
осциллограммы добавлено сохраняемое число значащих цифр (по умолчанию 4).
Перед форматированием значение округляется с шагом
`0.0001 * max(abs(YMin), abs(YMax))`, поэтому разряды мельче 0,01% максимума
шкалы не выводятся.

## Проверка

Forced Windows и полная Linux-сборки RecorderLnx 0.1.74 завершились успешно;
Linux ELF не имеет недостающих библиотек. Остаётся визуальная проверка GTK
после установки на MIC-200.
