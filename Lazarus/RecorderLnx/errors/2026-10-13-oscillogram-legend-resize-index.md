# Ошибка индекса колонки при переключении на страницу осциллограммы

## Симптом

При открытии страницы с плагинной осциллограммой и спектром локальный
RecorderLnx останавливался на `EStringListError` в отладчике.

## Подтверждённая причина

Стек из отладчика ведёт через `TCustomGrid.SetColWidth` в
`TRecorderOglOscillogram.LegendPanelResize`. При создании таблицы легенды
`Parent` назначался до `ColCount := 7`. Назначение родителя могло синхронно
вызвать `OnResize`; обработчик затем обращался к `ColWidths[0..6]`, пока
седьмой колонки ещё не было. Спектр находился на той же странице, но
исключение происходило в раскладке легенды осциллограммы.

Плагин осциллограммы активирует этот код представления, однако непосредственная
ошибка находится в host-компоненте `TRecorderOglOscillogram`, а не в коде DLL.

## Исправление

- Инициализировать `ColCount` до назначения `Parent`.
- Не менять ширины колонок, пока таблица не содержит все семь ожидаемых
  колонок.

## Проверка

- Win64-проект RecorderLnx собран успешно через установленный Lazarus/FPC.
- Собранный локальный RecorderLnx запущен с временно выбранной страницей
  `Mnemonic4` (`Page_02`), содержащей `sample.oscillogram` и `Spectrum`.
  Журнал подтвердил отрисовку `components=23`; процесс оставался жив. Исходное
  значение `ActivePageId=Mnemonic6` возвращено после теста; остальные поля
  проекта не изменялись.
- На удалённой копии выполнен контролируемый A/B-запуск с DLL осциллограммы и
  без неё. Без DLL окно приложения оставалось открытым; после теста DLL
  восстановлена, SHA-256 совпадает с исходным, временные task и копии DLL
  удалены. Это подтверждает, что загрузка/создание плагинного компонента
  вовлекает ошибочный путь, но не локализует исключение внутри DLL.
- Повторный аварийный сбой при создании таблицы легенды не воспроизвёлся.

## Следующий сбой: ELayoutException при resize

После исправления раннего обращения к колонкам появился отдельный стек на
`TControl.ChangeBounds` из `LegendPanelResize`. Скрин отладчика показывает
строку присваивания `fLegendGrid.Width := lWidth`: таблица уже имеет `Align =
alTop`, поэтому её ширину должен задавать родительский `TScrollBox`; ручной
`SetWidth` из `OnResize` запускал повторный align/layout.

Исправление: удалено ручное изменение ширины таблицы; обработчик resize меняет
только ширины столбцов. Добавлен регулируемый splitter и высота легенды по
числу строк. Ручная высота ограничивается доступной высотой и восстанавливается
после временного сжатия окна; при изменении числа строк снова действует
автоподбор.

Проверка: forced build Inno Setup 0.1.159 завершился успешно. Установщик
развёрнут на MIC-315; SHA-256 установленного RecorderLnx.exe и
SampleInfoPlugin.dll совпал с payload. Визуальный runtime-тест перемещения
splitter и повторного resize не проводился. На последующем скриншоте пользователь
подтвердил, что фактический splitter не даёт увеличить легенду.

## Повторная корректировка: нижний dock-контейнер (0.1.160)

Скриншот показал узкую легенду и splitter, расположенный на границе без
возможности растянуть область. Предыдущая схема делала scrollbox легенды и
splitter соседними dock-контролами непосредственно у `TOglChart`; этого
оказалось недостаточно для желаемого поведения. По требованию пользователя
нижняя область теперь состоит из `alBottom` splitter-а и отдельной
`alBottom` панели-хоста; scrollbox и таблица легенды вложены в эту панель.
График остаётся `alClient`, правая панель `alRight`, toolbar `alTop`.

Во время drag родительский `Resize` не вызывает авто-подбор высоты легенды;
после `OnMoved` новая высота фиксируется до смены числа строк. Это устраняет
конфликт между ручным drag и автолayout.

Проверка: forced Win64 build и Inno Setup 0.1.160 прошли; установлено на
MIC-315. Registry version = 0.1.160, SHA-256 установленного EXE совпал с
payload: `0FD25DB9F56EBA3FF28E4F23455C66FE82C9006935867396D94B162A37779F66`.
Recorder оставлен остановленным. Живой визуальный drag после этой коррекции
пока не проверен.

## Повторный снимок: grid не заполняет legend client area

Снимок после установки 0.1.160 показывает, что таблица заканчивается сразу
после единственной строки данных, тогда как внутри нижней области остаётся
пустое место. Проверка кода подтверждает прямую причину: `fLegendGrid.Align`
был `alTop`, а его высота равнялась числу строк. Нижний host panel при этом
растягивался отдельно.

Исправление 0.1.161: `fLegendGrid.Align := alClient` внутри дочернего scrollbox;
высоту host panel по-прежнему определяют число строк либо пользовательское
перетаскивание splitter-а. Win64 forced build и Inno Setup завершились
успешно. Установлено на MIC-315; SHA-256 EXE совпал с payload, версия 0.1.161.
Остаточный риск: визуальная проверка после запуска не выполнена.
