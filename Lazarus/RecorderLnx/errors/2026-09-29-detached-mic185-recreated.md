# 2026-09-29 — удалённый MIC-185 создавался повторно из detached-тегов

## Симптом

На KIP-3 источник `MIC-185: 192.168.9.164:4000` после удаления из аппаратного
дерева снова появлялся при переходе между разделами настроек и сохранялся.

## Подтверждённые факты

- Журнал KIP-3 показывает успешное удаление конфигурации и перевод связанных
  тегов в `Detached: MIC-185: 192.168.9.164:4000`.
- Следующая сборка runtime создавала этот MIC-185 снова и выполняла
  `RecorderConfiguredDataSourcesEnsure`.
- `TryParseRecorderMic185SourceId` нормализует `Detached:`; фабрика runtime не
  отсеивала такие теги до группировки источников.

## Исправление

- `RecorderBuildRuntimeSources` пропускает все detached-теги: они сохраняют
  данные для возможной ручной перепривязки, но не создают устройство.
- При удалении узлов аппаратного дерева UI отдельно спрашивает, удалить ли
  связанные теги. «Нет» оставляет их detached, «Да» удаляет из реестра.
- Для множественного удаления вопрос задаётся один раз с общим числом тегов.

## Проверка

- Forced Windows build `RecorderLnx.lpi -B` завершён успешно (exit 0).
- Forced Linux build завершён успешно: `BUILD_EXIT=0`, `MISSING_LIBS=none`.
- DEB 0.1.101 установлен на KIP-1…KIP-4; `dpkg-query` подтвердил версию на
  каждом узле.
- Требуется ручной повтор сценария удаления MIC-185 `.164` в интерфейсе KIP-3.
