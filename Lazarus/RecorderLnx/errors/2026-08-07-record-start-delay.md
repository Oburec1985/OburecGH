# Длительная пауза при старте записи

## Симптом

При переходе `Stop -> Record` интерфейс надолго не отвечает. Предположение: задержка вызвана созданием большого количества файлов каналов.

## Подтверждённые факты RecorderLnx

- `OpenRecordFrame` синхронно создаёт каталог кадра и `frame.ini`, после чего сразу пишет в журнал `MERA recording opened` (`UI/uMainForm.pas:2385`).
- Файлы каналов `.dat` открываются лениво при поступлении первого блока каждого тега (`Core/uRecorderDataStorage.pas:885`) из `ConsumeTagDataCycle` (`UI/uMainForm.pas:2788`), то есть уже после запуска источников.
- В фактическом журнале кадр открыт в `13:20:03.799`, а источники запущены только в `13:20:10.663`: пауза 6,864 с находится после открытия кадра, но до первого цикла файловой записи.
- Внутри этого интервала UI-поток последовательно выполняет `ApplyChannelProgramSettings` для MIC-185. Последний прибор `192.168.9.148` завершает неудачную попытку/отключение в `13:20:10.631`, непосредственно перед `Data sources started`.

## Как устроено в оригинальном Recorder

- `CRcCore::PrepareRecordingTargets` заранее готовит файловые targets и вызывается при программировании/обновлении связей, а также повторно после завершения предыдущей записи (`rc_core/Rc_core.cpp:2110, 4257, 5351`).
- `CRecTarget::Prepare` формирует имена файлов и заранее открывает/резервирует `.dat` и при необходимости файлы времени через `CreateFileAndReserveSpace` (`rc_core/RecTarget.cpp:492, 585, 594`).
- Поэтому открытие файлов является отдельной стадией подготовки targets; обычный старт записи активирует уже подготовленные targets.

## Вывод

Наблюдавшаяся пауза не вызвана открытием файлов. Основная подтверждённая причина — повторное последовательное конфигурирование/подключение пяти MIC-185 в UI-потоке при каждом `Stop -> Record`, включая трёхсекундный сетевой timeout последнего прибора. Отдельный потенциальный скачок при первом поступлении сотен тегов остаётся из-за ленивого создания `.dat`, но он происходит позже и в данном журнале не измерен.

## Следующее исправление

Не выполнять `Connect/Init/Configure` при тёплом `Start` уже подготовленных источников; запуск нескольких независимых устройств не должен последовательно блокировать UI. Для файлов приблизить жизненный цикл к оригиналу: подготовить список каналов и файловый writer до приёма первого блока, а фактическую запись выполнять вне UI-потока пакетами.
