# Редактор Лиссажу падал при открытии по правой кнопке

## Симптом

При открытии настроек компонента Лиссажу выполнение останавливалось внутри
`TCustomStringGrid.ReadCells` до появления диалога.

## Подтверждённая причина

В `uRecorderLissajousSettingsDialog.lfm` блок `Cells` был записан вручную как
последовательность координат и строк. Потоковый reader `TStringGrid` ожидает
первым целым количество записей. Первое значение `0` принималось за пустой
первичный блок, после чего reader пытался прочитать строку как номер строки.

Компилятор только встраивает LFM в ресурс, поэтому forced build успешно
завершался и не обнаруживал ошибку. Исключение возникало при `inherited Create`.

## Исправление

Сериализованный `Cells` удалён из LFM. Заголовки двух столбцов присваиваются
сразу после создания формы до заполнения таблицы тегами.

## Проверка

Forced Windows-сборка RecorderLnx 0.1.98 завершена с exit code 0. В ресурсе
формы больше нет блока `Cells`, поэтому ошибочный путь `ReadCells` при создании
этой таблицы не вызывается.

## Оставшийся приёмочный тест

Открыть редактор Лиссажу правой кнопкой в работающем RecorderLnx и проверить
табличные заголовки и список тегов.
