# NTP-сервер KIP3 и клиенты Astra Linux

Симптомы: GUI на KIP3 сообщал «Chrony не установлен»; KIP2 после назначения
сервера не синхронизировался. Адреса КИПов были ошибочно сопоставлены по
порядку инвентаря: 192.168.9.45 — KIP2, 192.168.9.66 — KIP3.

Факты: установка пакета `chrony` на Astra 1.8 удаляла бы
`systemd-timesyncd`. Частный `chronyd -x` отвечает на UDP/123 без управления
системными часами. После применения GUI конфигурация сервера содержала
`allow 192.168.1.0/24`, а клиенты находятся в 192.168.9.x. Клиентская
ветка менеджера требовала Chrony, хотя штатный `systemd-timesyncd` установлен.
Его drop-in с одним `NTP=192.168.9.66` не сбрасывал внешний сервер из
основного конфига, поэтому клиент сначала обращался к недоступному адресу.

Исправление: пакет `0.1.39+ntp1` включает отдельный бинарник Chrony и unit,
серверная служба включается по отдельной опции; клиентский режим пишет
drop-in `systemd-timesyncd` со сбросом списков. GUI рассчитывает подсеть из
IPv4-адреса и маски адаптера. Установщик компонентов получил отдельный
невыбранный по умолчанию пункт «NTP-сервер».

Проверка: все четыре КИПа имеют `0.1.39+ntp1`, `dpkg --audit` пуст. KIP3
раздаёт время из пакетного unit; KIP1, KIP2, KIP4 показывают сервер
192.168.9.66 и `NTPSynchronized=yes`. Установка пакета не удаляла и не
обновляла системные пакеты. KIP3 сам пока не синхронизирован с внешним
источником; он является локальным эталоном для остальных.

Правило предотвращения: см. `development-rules.md`, раздел «NTP на КИПах
Astra Linux».
