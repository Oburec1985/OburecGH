# 2026-09-10 — повторяющееся имя при импорте таблицы тегов

## Симптом

Импорт `_tags_v02.ods` останавливался в `TRecorderTagRegistry.RenameTag` с
исключением `Tag name already exists`, если одно имя канала встречалось в
таблице больше одного раза.

## Подтверждённые факты

- `RenameTag` корректно запрещает одному тегу занять имя другого тега.
- Импорт сначала временно переименовывает целевые теги, затем последовательно
  применяет строки таблицы.
- При повторённом имени разные строки могли претендовать на одно имя. Выбор
  первой строки не устраняет конфликт с исходным или уже переименованным тегом.

## Исправление

До временных переименований импорт проверяет все разрешённые строки. Если
непустое имя повторяется без учёта регистра, все строки с таким именем
исключаются из применения. Для каждой строки увеличивается `SkippedRows` и
добавляется предупреждение. Реестр и остальные свойства этих каналов не
изменяются. Поведение `RenameTag` не ослаблено.

## Проверка

- Логика проверена для двух разных целевых тегов и для повторной строки одного
  тега: неоднозначные строки удаляются до `RenameTargetsToTemporaryNames`.
- Forced-сборка скомпилировала изменённый модуль и весь проект, но линковка не
  смогла заменить запущенный `lib/x86_64-win64/RecorderLnx.exe`: Windows вернула
  `error code 5`. Требуется закрыть RecorderLnx, повторить сборку и импорт ODS.

## Правило предотвращения

`RLNX_TAG_IMPORT_DUPLICATE_NAME_SKIP_2026_09_10` добавлено в
`Docs/architecture/development-rules.md`.
