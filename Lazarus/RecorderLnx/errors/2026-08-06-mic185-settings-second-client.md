# MIC-185: второе TCP-соединение из диалога настройки

## Симптом

После нажатия OK в диалоге подключённого MIC-185 возникало исключение:
`already has an active TCP client in RecorderLnx`.

## Причина

Диалог сохранял настройки и вызывал `RecorderMic185ProgramConfiguredSource`, который всегда создавал новый объект прибора и выполнял `Connect`. В это время тем же endpoint уже владел активный runtime-источник.

## Исправление

Если endpoint уже зарегистрирован как live-device, отдельное программирующее соединение не создаётся. Настройки остаются в реестре и применяются штатной переинициализацией источника после применения общих настроек Recorder. Получение серийного номера для дерева переведено на runtime-кэш/live-device без нового TCP-подключения.

## Защита от повторения

У одного endpoint должен быть один владелец TCP-сессии. Настроечный UI не подключается параллельно runtime и не выполняет сетевые диагностические операции при обычной перерисовке дерева.

## Проверка

Полная сборка `C:\lazarus\lazbuild.exe -B RecorderLnx.lpi` завершилась с exit code 0.
