# Теги спектральных оценок не создавались по «Применить»

## Симптом

После включения «Создать теги» и оценок по полосам галочки сохранялись, но выходные теги в списке каналов не появлялись.

## Причина

Диалог изменял черновую конфигурацию спектра, однако обработчики внутренней и общей кнопок «Применить» не вызывали `TRecorderSpectrumRuntimeManager.PrepareConfiguration`. Именно эта конфигурационная фаза создаёт производные теги через `EnsureEstimateTags`. Кроме того, общая кнопка могла сохранить настройки без предварительного переноса текущих контролов выбранного узла в модель.

## Исправление

- `StoreToSettings` всегда сохраняет текущий выбранный узел алгоритма.
- Добавлен единый `ApplySpectrumConfiguration`: он вызывает `PrepareConfiguration`, затем перестраивает таблицы каналов.
- Оба пути «Применить» используют этот метод.
- Подтверждено, что в конфигурации проекта заданы полосы `B01` и `B02`; при трёх включённых оценках должно создаваться по шесть тегов на привязанный канал.

## Правило предотвращения

Если настройка декларативно создаёт теги, каналы или другие производные объекты, каждый путь Apply/OK выполняет один порядок: контролы UI → модель → рабочая конфигурация → материализация производных объектов → обновление UI. Нельзя откладывать материализацию исключительно до закрытия диалога или следующей загрузки проекта.

## Проверка

Полная сборка `lazbuild -B RecorderLnx.lpi` завершилась с exit code 0.

## Регрессия повторного Apply

Повторное применение конфигурации не должно создавать новый экземпляр уже материализованной оценки. Поиск только по вычисленному имени недостаточен: имя тега может быть изменено пользователем. `EnsureEstimateTags` теперь сначала ищет тег по имени, затем по устойчивой паре `SourceId = spectrum:<исходный тег>` и `Address = <полоса>/<оценка>`. Новый тег создаётся только если оба поиска ничего не нашли. Полная сборка после исправления завершилась с exit code 0.

## Регрессия отображения после закрытия настроек

Теги присутствовали в реестре, но главный список обновлялся только при `mrOk`; после «Применить» → «Закрыть» оставался старый снимок. Дополнительно `RecorderTagSourceIsVisible` классифицировал `spectrum:*` как неактивный аппаратный источник, игнорируя явный `TRecorderTag.IsVirtual=True`. Теперь главный список и активная страница перечитываются после любого закрытия диалога, а виртуальный тег считается видимым по явному признаку независимо от формата `SourceId`. Полная сборка завершилась с exit code 0.
