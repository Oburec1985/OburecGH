# 2026-09-09 — SQL-тренд не открывает удалённую Firebird без клиента

## Симптом

На компьютере без установленного Firebird SQL-тренд выводит красную ошибку,
хотя база находится на другом ПК и сервер на рабочей станции не нужен.

## Причина

`TIBConnection` обращается к удалённому серверу через нативную клиентскую
библиотеку Firebird. Linux-пакет RecorderLnx зависел только от `libc6` и GTK,
поэтому `libfbclient.so` не гарантировалась установщиком. Наличие сервера и
наличие клиента ошибочно воспринимались как одно условие.

## Исправление

- Debian-пакет зависит от `libfbclient2`; локальный сервер не устанавливается.
- `recorderlnx-install-check` отдельно проверяет наличие `libfbclient.so`.
- `postinst` находит фактический `libfbclient.so.2` через `ldconfig`, создаёт
  совместимую ссылку в `/opt/mera/RecorderLnx/lib`, а штатный launcher добавляет
  этот каталог в `LD_LIBRARY_PATH`. Это закрывает несовпадение с FPC 3.2.2,
  который после старых versioned-имён ищет `libfbclient.so`.
- Ошибка открытия БД распознаёт отсутствие `fbclient`/`libgds` и сообщает,
  какой клиент поставить на Linux или Windows.

## Проверка

- полная Win64-сборка `RecorderLnx.lpi` — успешно;
- `python -m py_compile installer/RecorderLnx/linux/build_deb.py` — успешно;
- `git diff --check` — успешно.

Стендовая проверка Linux требует установки обновлённого `.deb` на ПК без
Firebird server и подключения SQL-тренда к удалённому endpoint.

## 2026-09-11 — устранено расхождение системного и проектного подключения

Подключение ошибочно хранилось вместе с каналами в проектном `sql-db.ini`.
Из-за этого разные проекты и SQL-компоненты могли использовать разные host и
database. Каноническое подключение перенесено в `[SQLdbConnection]` общего
`app.ini`; `TRecorderSqlDbConfig.LoadFromFile` сначала читает проектные
параметры, затем всегда накладывает системное подключение. Сохранение удаляет
старые connection-ключи из проекта. Старый файл остаётся миграционным fallback,
если новая секция ещё отсутствует.

Проверка: forced-сборки RecorderLnx Win64, RecorderLnx Linux,
RecorderCoordinator Linux и RecorderHostAgent Linux завершились с кодом 0;
DEB `0.1.9` создан. Фактическое подключение к `192.168.9.66:3050` с Windows
остаётся зависимым от доступности сетевого порта.
