# Цифровой формуляр: значения переходили между строками при обновлении

## Симптом

Пользователь прислал кадры цифрового формуляра, где при периодической
перерисовке список выглядел нестабильным: строки казались появляющимися и
пропадающими. Требуемый инвариант — неизменные подписи/порядок строк и обновление
только видимых значений, статуса и цвета тревоги.

## Проверенные факты

- `UpdateRecorderDigitalPage` не очищал таблицу и не менял `RowCount` на каждом
  тике.
- Однако каждый тик повторно обходил реестр и заново применял
  `RecorderTagSourceIsVisible`. Эта проверка зависит от активности источника.
- Номер строки вычислялся заново только по текущему набору активных тегов,
  тогда как подписи/`RowCount` оставались от предыдущей полной отрисовки.
  При изменении активности источника значения могли отображаться в строках
  другого тега или оставаться старыми.
- `PrepareDigitalCanvas` дополнительно искал имя тега в реестре на каждой
  перерисовке ячеек.

## Исправление

- Полная отрисовка один раз записывает ссылку на тег и тип оценки в объекты
  соответствующей строки.
- Периодическое обновление обходит только строки в viewport и меняет колонку
  значения плюс текст статуса тревоги для первой строки тега.
- Цвет строки получает тег напрямую из привязки строки, без поиска по имени.
- Структура строк меняется только при явном полном рендере после изменения
  конфигурации/режима или при повторном входе в страницу.

## Проверка и остаточный риск

- Первая правка устранила повторную фильтрацию тегов, но не прекратила
  визуальное мерцание.

## Повторное расследование: мерцание при таймерном refresh — 2026-10-28

Повторный просмотр call chain выявил две дополнительные причины:

1. `RefreshLive` раз в интервал обновления вызывал `RenderDigitalPage(False)`.
   Эта процедура при каждом тике повторно переключала Visible у панелей,
   вызывала `BringToFront` и присваивала `sgFormular.Align := alClient`.
   Эти операции запускали layout/перерисовку страницы, хотя требовалось только
   обновить значения.
2. `UpdateRecorderDigitalPage` заключал инкрементальную запись двух колонок в
   `BeginUpdate/EndUpdate`. Завершение update инвалидировало таблицу целиком
   каждые 200 мс, даже если менялась только одна ячейка Value.

Исправлено: `RenderDigitalPage(False)` теперь делает только вызов обновления
данных в уже активном представлении и выходит. Таймерная запись не подавляет
перерисовку всей сетки; изменённые значения обновляют свои ячейки. При смене
текста тревоги инвалидируются строки только соответствующего тега в viewport,
чтобы обновить их цвет.

Forced Win64 build `RecorderLnx-digital-no-flicker.exe` прошёл: 237521 строк,
exit 0. Визуальный запуск с текущим проектом не выполнялся, чтобы не запускать
второй OPC runtime параллельно с уже открытым Recorder; остаточный шаг — проверить
обновлённую сборку на экране пользователя.
