# Перезапись цепочки ГХ при добавлении второй характеристики

## Симптом

После добавления первой ГХ следующая выбранная характеристика заменяла её.
Диалог цепочки с изменением порядка и общим отключением ГХ больше не открывался.

## Причина

- обработчик добавления записывал новую ГХ поверх последнего элемента
  `CalibrationNames` вместо безусловного добавления;
- кнопка настройки цепочки была переназначена на редактор одной выбранной ГХ.

## Исправление

- новые ГХ всегда добавляются в конец `CalibrationNames`;
- кнопка снова открывает редактор всей цепочки с добавлением, удалением,
  стрелками порядка и флагом включения цепочки;
- двойной щелчок по имени оставлен для редактирования выбранной ГХ.

## Проверка

- полная Windows-сборка `RecorderLnx.lpi` — успешно;
- полная Linux-сборка через Astra VM — успешно;
- `git diff --check` по изменённым модулям — без ошибок.

## Правило предотвращения

Список `CalibrationNames` является упорядоченным pipeline. Операция «Добавить»
не должна менять существующие элементы. Редактирование одного элемента и
редактирование состава/порядка цепочки должны оставаться разными действиями UI.
