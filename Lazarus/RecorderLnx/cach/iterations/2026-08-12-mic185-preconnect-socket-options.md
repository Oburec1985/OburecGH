# MIC-185: параметры сокета до connect

## Запрос

Сверить настройку сокета RecorderLnx с оригинальным Recorder из-за остановки
потока MIC-185 примерно через 85–125 секунд.

## Сверка

| Участок | Оригинальный Recorder | RecorderLnx до правки |
|---|---|---|
| `SO_RCVBUF` | 4 МиБ до `connect` | 4 МиБ после `connect` |
| `SO_KEEPALIVE` | включён до `connect` | включён после `connect` |
| keep-alive Windows | idle 5 с, interval 1 с до `connect` | 5 с/1 с после `connect` |
| прикладной heartbeat | выключен для MIC-185 | не вызывается |
| разбор TCP | накопление, поиск сигнатуры по байту, сохранение неполного хвоста | совпадает |
| программирование | controller params, device bin, session id, program | совпадает |

`QUERY_SESSION_STATE` добавлять нельзя: базовый `OnGetKeepAliveFlag` оригинала
возвращает `false`, а MIC-185 его не переопределяет.

## Сделано

- В общий открыватель TCP добавлен необязательный обработчик уже созданного,
  но ещё не подключённого сокета.
- MIC-185 задаёт приёмный буфер и keep-alive через этот обработчик до `connect`.
- Остальные устройства и вызовы общего сетевого модуля не изменены.

Порядок важен для согласования TCP window scale в SYN. Позднее увеличение
`SO_RCVBUF` не меняет уже согласованный масштаб окна приёма.

## Проверка

Полная сборка `RecorderLnx.lpi` прошла. Нужен аппаратный прогон дольше прежней
границы 85–125 секунд; компиляция не подтверждает устойчивость прибора.
