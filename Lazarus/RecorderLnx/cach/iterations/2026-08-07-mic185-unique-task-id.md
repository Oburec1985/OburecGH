# Итерация: уникальный Mebius TASKID клиента MIC185

## Результат анализа лога

- После transport-ready задержки `192.168.9.147` и `.152` успешно прочитали SN и сконфигурировались.
- `.148`, `.151`, `.155` принимали TCP-соединение, но обе попытки первого IoControl завершались таймаутом.
- Увеличение задержки не является решением: исправные ответы приходят примерно за 31 мс.

## Отличие от оригинального Recorder

Оригинальный `CTCPLink::IoControlEx` записывает в поле `MEBE_PACKET.id_from` значение `(TASKID)this`, то есть уникальный 32-битный идентификатор экземпляра TCP-клиента. RecorderLnx использовал общий фиксированный `REC_HOST_SETTINGS_PORT_ID` для всех параллельных соединений.

## Исправление

- `fClientTaskId` формируется из младших 32 бит адреса экземпляра `TRecorderMebiusTcpClient`, как в оригинальном коде.
- Фиксированный settings ID оставлен только как резерв для невозможного нулевого значения.
- Полная сборка успешна; исполняемый файл перелинкован.

## Проверка

Нужен холодный запуск на пяти приборах. Критерий: все ответившие на TCP приборы должны пройти `initialize state=OK`; идентификаторы SN должны читаться независимо в параллельных потоках.
