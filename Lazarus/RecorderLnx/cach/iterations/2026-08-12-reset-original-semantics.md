# Сброс устройств: сверка с оригинальным Recorder

## Запрос

Уточнить, разрывает ли оригинальный Recorder соединение при reset, и чем
«Сброс всех устройств» отличается от сброса одного устройства.

## Результат

- `ForceResetDevice` для MebiusDAQ выполняет `Disconnect`, ждёт 300 мс,
  выполняет `Connect`, ждёт 1000 мс и вызывает `Program(false)`.
- `Disconnect` оригинального `CTCPLink` отключает автопереподключение,
  посылает событие потоку транспорта, ждёт его завершения, выполняет
  `shutdown(SD_BOTH)`, закрывает сокет и переводит устройство в `ATTACHED`.
- Перед аварийным reset отдельная команда `Stop` не отправляется.
- «Сброс всех» помечает все host-устройства для reset/config, запускает
  асинхронный reset каждого устройства, затем ожидает завершение каждого и
  только после этого выполняет общий этап конфигурирования.

## Изменения RecorderLnx

- reset снова безусловно освобождает сессию;
- `Disconnect` MIC-185 больше не вызывает `Stop` неявно;
- пауза после disconnect установлена 300 мс, после connect — 1000 мс;
- пакетный reset сохраняет схему «все reset параллельно -> ожидание -> общий
  PrepareHardware» без искусственного разнесения запусков по времени.

## Проверка

Полная сборка `RecorderLnx.lpi` выполнена успешно.
