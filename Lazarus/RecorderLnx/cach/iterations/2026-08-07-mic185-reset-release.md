# Итерация: освобождение MIC185 endpoint перед сбросом

## Запрос

Разобрать повторяющиеся ошибки инициализации MIC185 по lifecycle-логу и устранить обнаруженную программную причину.

## Сделано

- Установлено, что `RequestStop` оставлял `RuntimeHoldBusy=True` у источников, для которых init завершился ошибкой и live-device не был зарегистрирован.
- В `TRecorderHardwareResetTask.Execute` добавлено безусловное освобождение runtime endpoint MIC185 через `RecorderMic185RuntimeDetach` перед новой попыткой.
- Добавлена запись стадии `reset-release` в lifecycle-лог.
- Полная сборка проекта завершилась успешно; EXE перелинкован.

## Осталось проверить на приборах

- На первой попытке сброса больше не должно быть ложного `busy by active RecorderLnx session`.
- Отдельно оценить остающиеся реальные таймауты `Mebius IoControl` и TCP после устранения загрязнённого runtime-состояния.
