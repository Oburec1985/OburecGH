# Общие интерфейсы плагинов RecorderLnx

Каталог `Plugins/SDK` содержит общие модули контракта между RecorderLnx и плагинами. При сборке плагина добавьте этот каталог в путь поиска модулей Lazarus и подключайте нужный модуль через `uses`.

- `uRecorderPluginApi.pas` — существующий ABI плагинов и сервисы хоста, включая переходный интерфейс осциллограммы.
- `uRecorderVisualComponentApiV2.pas` — общий ABI визуальных компонентов версии 2. Подробности и правила совместимости приведены в `visual-component-abi-v2.md`.
- `uRecorderPluginBase.pas` и `uRecorderPluginFramework.pas` — общие класс и экспортируемые функции жизненного цикла визуальных и невизуальных плагинов. Визуальная библиотека задаёт регистрацию фабрик через `ConfigureFramework`, невизуальная — создание своего класса через `ConfigurePluginFramework`.
- `uRecorderPluginClass.pas` и `uRecorderPluginComponentManager.pas` — общий класс визуального плагина `TExtRecorderPack`, менеджер фабрик `cCompMng` и базовая фабрика `cRecBasicFactory`. Менеджер перечисляет фабрики и передаёт им уведомления. Имена соответствуют оригинальному фреймворку; реализация и её кроссплатформенный ABI RLNX отличаются от оригинального COM-интерфейса.
- `uRecBasicIFrm.pas` — общий маршрут настроек компонента: `doWriteSettings` вызывает `SaveSettings`, `doReadSettings` — `LoadSettings`. Данные передаются буфером; конкретный компонент определяет формат, осциллограф использует JSON.
- `uPluginTagServices.pas` — общие типы метаданных и чтение каталога тегов через сервисы хоста. Это ещё не реализация оригинального `cTag` с его блоковой буферизацией и курсором.
- `uPluginTag.pas` — общий читающий `cTag`: копирование окна или диапазона во внешние подготовленные буферы. Запись не включена; независимый курсор и обнаружение потери данных пока не поддерживаются ABI.

Получение уведомления о данных не обязывает копировать историю. Компонент сам
проверяет нужные ему триггеры и критерии и запрашивает только требуемый диапазон
в подходящий момент; общий менеджер лишь доставляет событие.

При закрытии `PluginClose` и `doClose` должны остановить и дождаться собственных
потоков до удаления экземпляров. `doClose` безопасен при повторном вызове,
включая повтор после собственной успешной остановки, если соседняя фабрика
сообщила ошибку. Он не должен ждать синхронной операции, требующей выполнения
в UI-потоке, где происходит закрытие. При отказе хост сохраняет плагин и его
объекты для повторной попытки; это относится и к частично созданным плагинам.

Хост и плагины используют одни и те же объявления из этого каталога. Не создавайте отдельные копии заголовков внутри плагинов: изменения ABI должны сохранять совместимость, описанную в самих модулях. Подкаталог `Tests` содержит проверки контракта.

Маршрут нового визуального плагина: библиотека вызывает `ConfigureFramework` → хост вызывает `CreatePluginClass` и `PluginCreate` → `TExtRecorderPack._Create` создаёт менеджер и вызывает регистрацию фабрик плагина (`uCreateComponents`) → хост перечисляет дескрипторы → уведомления идут через `PluginNotify`, `Notify`, `ProcessNotify`, менеджер и фабрики к экземплярам. При уничтожении менеджер проверяет наличие живых экземпляров фабрик. Старый хост V2, который не вызывает жизненный цикл плагина, не сможет загрузить плагин нового вида. Новый хост продолжает поддерживать старые V2-библиотеки без этого маршрута. Нативный ABI не передаёт контекст при перечислении дескрипторов, поэтому допускается один общий объект плагина на загруженную библиотеку.

Базовая `cRecBasicFactory` учитывает экземпляры и распределяет события через
`doStart`, `doStop` и `doUpdateData`; ошибка одного получателя не препятствует
доставке остальным. При переходе в просмотр или запись, включая переход между
этими режимами, хост посылает плагинам START, при фактической остановке — STOP.
Ожидание триггера само по себе события не создаёт. Переход определяется с учётом
исходного состояния до ожидания. Старые V2-плагины получают те же события через
адаптер хоста; запуск и остановка встроенных компонентов остаются независимыми.
Для `PN_RCSTART` `AData` — непрозрачное числовое значение: `0` (`nil`)
означает просмотр, `1` — запись. Его нельзя разыменовывать. Общая фабрика
предоставляет режим в свойстве `Recording`, а её экземпляры получают при
START временную запись `TRecorderVisualRunContextV2` с заголовком ABI и полем
`Recording`. Указатель действителен только в течение синхронного вызова;
старые V2-плагины без общего фреймворка по-прежнему получают START без данных.
При `PN_RCINITIALIZED` после обновления каталога тегов менеджер вызывает
расширяемый `doRecorderInit` каждой фабрики; повторного обновления каталога
общий метод не выполняет.

Перед уничтожением плагина хост вызывает `PluginClose`. Общий `TExtRecorderPack`
через `cCompMng.Close` вызывает `doClose` каждой фабрики; фабрика должна
остановить и дождаться всех собственных потоков и callback, способных обращаться
к хосту или исполнять код плагина. Базовая реализация не имеет потоков и
возвращает успех. Ошибка либо исключение одной фабрики не мешает остановить
остальные, но `PluginClose` возвращает отказ: хост обязан сохранить библиотеку
и её состояние. Успешное закрытие идемпотентно; после частичной ошибки
повторные вызовы `doClose` каждой фабрики должны быть безопасны. Завершение
только callbacks хоста не доказывает, что поток перестал исполнять код DLL.

Сервисы хоста предоставляются на время жизни экземпляров и callback. При
ошибке их уничтожения библиотека и шлюз сервисов удерживаются; после окончания
работы хоста шлюз возвращает отказ и не обращается к уничтоженному runtime.
Вызов напрямую `Free` для окна или runtime из callback сервиса запрещён:
закрытие должно происходить после возврата callback. Перед уничтожением
вызывающий обязан получить успех `TryBeginShutdown`: при активном callback он
возвращает False без разрушения объектов, и закрытие следует повторить позже.
Обычное закрытие главного окна планирует такой повтор автоматически. После
успешной подготовки завершение ждёт начатые вызовы, не удерживая блокировку
шлюза во время их исполнения.
