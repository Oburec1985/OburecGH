# Mdb — XML-базы испытаний RecorderLnx

## Компонент MeraBase

В палитре конструктора RecorderLnx доступна самостоятельная кнопка
«База испытаний». Она создаёт встроенный компонент `MeraBase` с выбором
изделия, испытания и существующей регистрации. Рядом с путём находятся кнопка
`...` для выбора корня и кнопка `БД` для входа в настройку базы. На одной форме
допускается один такой компонент.

Архитектура повторяет разделение legacy `plgControlCyclogram`: общий класс
`TRecorderXmlDatabase` отвечает только за каталог, XML-дескрипторы, свойства и
жизненный цикл узлов. `TRecorderMdbRepository` задаёт конкретную иерархию
`Объект → Испытание → Регистрация`. Другой модуль может унаследовать базу и
задать, например, `Турбина → Ступень → Лопатка`, не меняя общий XML-класс.

Стабильный сценарий:

1. `TRecorderXmlDatabase` сканирует и сохраняет универсальные XML-узлы.
2. `TRecorderMdbRepository` проверяет предметные связи и создаёт регистрации.
3. `TRecorderMdbDialog` позволяет найти или создать изделие и испытание.
4. `TRecorderMdbManager` хранит проверенный текущий контекст компонента.
5. RcPan/Recorder передаёт фактический каталог замера в `CreateRegistration`;
   XML-база хранит этот путь как контекстную ссылку и не управляет хостами.
6. `ListMeasurements` возвращает замеры по изделию и испытанию без разбора
   имён файлов.

Путь XML-базы и выбранные UUID сохраняются в модели компонента внутри проекта.
SQL-клиент и SQLite для MeraBase не нужны, поэтому отдельная SQL-ошибка в
журнал настроечной формы не выводится. Сетевая маршрутизация и каталоги других
хостов остаются ответственностью RcPan/Recorder; база лишь принимает готовый
путь регистрации.

Проверка:

```powershell
pwsh -File Scripts/run-mdb-checks.ps1
```

Тест создаёт временную XML-базу, проверяет полный цикл
`Объект → Испытание → Регистрация`, повторное открытие и сохранение пути данных.
Отдельный сценарий строит на том же базовом классе независимую иерархию
`Турбина → Ступень → Лопатка`.
