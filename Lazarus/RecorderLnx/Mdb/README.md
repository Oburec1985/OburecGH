# Mdb — контекст измерений RecorderLnx

`Mdb` переносит предметную механику legacy `MBaseControl`, но использует общую
SQLdb RecorderLnx вместо файловой XML-иерархии и второй базы данных.

Стабильный сценарий:

1. `TRecorderMdbRepository` создаёт и читает изделия, испытания и замеры.
2. `TRecorderMdbDialog` позволяет найти или создать изделие и испытание.
3. `TRecorderMdbManager` проверяет пару UUID и передаёт её SQLdb manager.
4. При старте записи пара `object_id/test_id` копируется в job writer-потока.
5. Значения, события и файлы связываются с созданной `registration_id`.
6. `ListMeasurements` возвращает замеры по изделию и испытанию без разбора
   имён и путей файлов.

Выбранные UUID сохраняются в секции `[Mdb]` проектного `sql-db.ini`. Смена
контекста во время активной SQL-записи запрещена, поэтому один замер не может
получить смешанный контекст.

Проверка:

```powershell
pwsh -File Scripts/run-mdb-checks.ps1
```

Тест создаёт временную SQLite БД, выполняет миграцию, CRUD изделия/испытания,
создаёт замер со значением, событием и файлом, повторно открывает БД и проверяет
выборку всей цепочки по UUID изделия и испытания.
