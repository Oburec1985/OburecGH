# MC bus: MC-032 / MC-201

Драйвер поддерживает шину модулей с Ethernet-контроллером MC-032 и MC-201.
MIC-200 — это вариант конструктива, а не тип протокола. Рабочая граница —
стандартный `TRecorderDevice`:

1. `Connect` открывает MDP/TCP-сессию и ищет MC-201 в слотах.
2. `ProgramDevice` загружает BIOS при необходимости и программирует скан.
3. `Start` запускает `STARTSCANMAIN`.
4. `ReadBlock` собирает сообщения отдельных каналов в общий
   `TRecorderAcquisitionBlock`.
5. `Stop` и `Disconnect` освобождают контроллер и TCP-сессию.

Создание драйвера: `CreateRecorderMcbusDevice`. Endpoint, частота и период
обновления задаются через `rdpHost`, `rdpPort`, `rdpPollFrequencyHz` и
`rdpUpdateTimeMs`. После программирования `GetChannels` возвращает по четыре
канала для каждого обнаруженного MC-201; адрес имеет вид `<слот>-<канал>`.

`TMc032Device` — низкоуровневый драйвер контроллера: TCP/MDP, TEST, поиск
слотов и команды модулей. `TRecorderMcbusDevice` — адаптер связки MC-032 + MC-201 к
жизненному циклу `TRecorderDevice`.

Низкоуровневый MDP-клиент изолирован в этой папке. Его нельзя подменять
клиентом MIC-185: транспорт у обоих TCP, но кадрирование, команды и жизненный
цикл сессии различаются. Общий контракт находится уровнем выше — в
`TRecorderDevice`.

BIOS `mc_201a.bio` встроен в `RecorderLnx.exe` ресурсом `MC201A_BIO`; внешний
путь используется низкоуровневым кодом только как диагностический fallback.
