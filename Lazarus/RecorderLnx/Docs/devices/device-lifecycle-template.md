# Шаблон жизненного цикла устройств RecorderLnx

Этот документ задаёт обязательную архитектуру для всех физических устройств
RecorderLnx. Специфичный драйвер наследуется от `TRecorderDevice`, а источник
данных управляет им через `IRecorderDevice`.

## Нормативный конвейер

```text
Connect
  -> InitializeDevice (один раз после включения/reset прибора)
  -> ConfigureDevice  (может вызываться многократно)
  -> Start
  -> Stop
  -> ConfigureDevice
  -> Start
  -> Stop
  -> Disconnect
```

`ProgramDevice` оставлен только как совместимый фасад:

```pascal
InitializeDevice;
ConfigureDevice;
```

Новый код источников должен по возможности вызывать эти этапы явно.

## Connect

Назначение: установить транспортную связь, не менять аппаратную конфигурацию.

Допустимо:

- открыть TCP/USB/COM/драйвер;
- определить адрес и транспортные параметры;
- прочитать идентификатор, серийный номер и версию контроллера;
- выполнить безопасный тест связи.

Недопустимо:

- загружать BIOS/firmware;
- выполнять общий аппаратный reset;
- создавать измерительный scan;
- запускать сбор данных.

Повторный вызов при открытом соединении должен быть no-op.

## InitializeDevice

Назначение: выполнить дорогую одноразовую подготовку после включения или reset
прибора.

Типичные операции:

- аппаратный reset, если он является частью штатного cold start;
- ожидание готовности и восстановление транспорта после reset;
- поиск модулей по слотам;
- загрузка BIOS/firmware;
- создание постоянных IDMA-дескрипторов;
- подготовка базовой инфраструктуры прерываний и триггеров.

Повторный вызов при подтверждённой инициализации должен быть no-op.

Признак инициализации инвалидируется, если:

- прибор сообщил о перезагрузке или сменился его boot/session identifier;
- выполнен общий reset;
- изменился состав модулей;
- потеряно содержимое RAM с BIOS;
- завершилась ошибкой операция, после которой состояние прибора неизвестно;
- выполнен `Disconnect`, а подтвердить сохранность состояния при новом
  соединении невозможно.

Обычные `Stop`, повторный `Start` и изменение пользовательских настроек не
инвалидируют `InitializeDevice`.

## ConfigureDevice

Назначение: многократно применять пользовательские настройки без загрузки BIOS.

Допустимо:

- остановить и сбросить только измерительный scan;
- передать частоты, диапазоны, фильтры, ICP/IEPE и коммутацию;
- передать сохранённые коды ЦАП;
- задать FIFO и список каналов;
- пересоздать изменяемую часть scan;
- обновить параметры триггеров, зависящие от конфигурации;
- перевыделить программные буферы нужного размера.

Недопустимо:

- выполнять общий reset контроллера;
- разрывать и повторно открывать транспорт без ошибки связи;
- повторно загружать неизменившийся BIOS;
- запускать поток данных.

После успеха устройство находится в состоянии `rdsProgrammed`.

## Start

- требует выполненных `Connect`, `InitializeDevice`, `ConfigureDevice`;
- очищает только runtime-буферы и счётчики;
- запускает аппаратный scan;
- не загружает BIOS и не перевыделяет конфигурационные структуры;
- после успеха переводит устройство в `rdsStarted`.

Для потокового устройства ACK команды запуска и получение первого пакета —
разные диагностические события. Отсутствие данных не должно подменять результат
проверки связи с контроллером.

## Stop

- останавливает аппаратный scan;
- завершает чтение без исключений teardown в UI;
- сохраняет транспорт, BIOS, IDMA и применённую конфигурацию;
- возвращает устройство в `rdsProgrammed`;
- повторный вызов является no-op.

## Disconnect

- при необходимости вызывает `Stop`;
- закрывает транспорт;
- освобождает runtime-ресурсы соединения;
- переводит устройство в `rdsDisconnected`.

Аппаратное состояние не следует сбрасывать специально. Локальный признак
инициализации разрешено сохранять только при наличии надёжного способа
подтвердить ту же boot-сессию после повторного подключения.

## Ошибки и повторные попытки

- Перед управляющей операцией применяется безопасный `TestLink`.
- Ошибка `ConfigureDevice` не должна автоматически приводить к бесконечным
  reset/retry.
- Разрешена одна явно залогированная попытка восстановления: invalidation Init
  -> reconnect -> InitializeDevice -> ConfigureDevice.
- `Stop` и `Disconnect` не должны выбрасывать ожидаемые сетевые ошибки в UI.
- В логе каждый этап имеет отдельное имя: `CONNECT`, `INIT`, `CONFIG`, `PLAY`,
  `STOP`, `DISCONNECT`.

## Состояния и внутренние признаки

Общая FSM сохраняет совместимые состояния:

```text
rdsDisconnected -> rdsConnected -> rdsProgrammed -> rdsStarted
```

Одноразовая инициализация хранится отдельным признаком драйвера, например
`fHardwareInitialized`. Она не должна маскироваться состоянием
`rdsProgrammed`, поскольку повторный `ConfigureDevice` сохраняет Init.

## Чек-лист нового драйвера

- [ ] `Connect` выполняет только транспорт и идентификацию.
- [ ] `InitializeDevice` идемпотентен и загружает BIOS не более одного раза за
      boot-сессию.
- [ ] `ConfigureDevice` идемпотентен и не вызывает общий reset.
- [ ] `Start/Stop` не выделяют конфигурационную память.
- [ ] `Stop` сохраняет возможность немедленного повторного `Start`.
- [ ] `Disconnect` безопасен после частично выполненного запуска.
- [ ] Проверка связи контроллера отделена от проверки наличия данных модулей.
- [ ] Причина инвалидирования Init записывается в лог.
- [ ] Есть стендовая проверка: cold start, повторный Config, пять циклов
      Start/Stop, reconnect и аппаратный reset.

### Правило конфигурации транспортной очереди данных

Если протокол устройства передаёт измерения через BIOS/DSP-очередь сообщений,
`ConfigureDevice` обязан не только создать scan и каналы, но и выделить и
зарегистрировать транспортную очередь до запуска ADC/scan. Успешный ACK команды
Start не подтверждает готовность этой очереди.

Проверка обязательна по фактическому потоку: после cold start должны прийти
первые сырые пакеты и затем блоки с ожидаемым числом отсчётов в секунду. Для
MC-032 это `CMD_CONFIG_MESSAGE` после `SCAN_SET_CHANS` и до настройки стартовых
триггеров.
