# Канал СЕВ (UTS) MIC183/185

## Формат оригинального Recorder

MIC183/185 передаёт СЕВ отдельным потоком `dev_id = 0`. Это не массив
`float` и не обычный `UNIVERSAL_DATA_SAMPLE`. В исходниках оригинального
Recorder пакет разбирает `CPcUTSImpl::Decommutate`:

- `marker_` — идентификатор потока (`dev_id = 0`);
- `type_ = 2` — обычный формат СЕВ МЕРА;
- `sampl_count_` — счётчик пакетов;
- `m_Start_CLK` — аппаратный CLK начала измерения;
- `m_Sev_CLK` — CLK текущей секундной метки;
- `m_Sev_Sec` — абсолютное значение UTS в секундах;
- `m_CLK` — частота аппаратного CLK.

Оригинал формирует пару `Double`:

```text
X = (m_Sev_CLK - m_Start_CLK) / m_CLK
Y = m_Sev_Sec
```

`X` — время метки относительно старта измерения прибора, `Y` — абсолютное
UTS-время в секундах. `CBaseUTSChannel::PutSample` передаёт оба числа как один
XY-отсчёт. Поэтому на цифровой форме пользователь видит `Y`, а не CLK и не
сырой `Single`.

Первичные источники оригинала:

- `Mebius/MebiusDAQ/DAQ/Common_pc/PcUTSImpl.h` — структуры пакета;
- `Mebius/MebiusDAQ/DAQ/Common_pc/PcUTSImpl.cpp` — расчёт X/Y;
- `Mebius/MebiusDAQ/Base/BaseUTSChannel.cpp` — передача пары;
- `Mebius/MebiusDAQDevices/mic185v2/mic185v2_pc/mic185v2scan.cpp` — маршрутизация `dev_id=0`;
- `Mebius/MebiusDAQDevices/mic185v2/mic185v2_pc/mic185v2.cpp` — включение `TASKSEV_EN_FLAG`.

## Включение потока

При конфигурировании подключённого UTS-канала оригинал устанавливает
`TASKSEV_EN_FLAG = 1` командой `SET_CONTROLLER_PARAMS`. Прибор сам сообщает
формат пакета полем `type_`; отдельное принудительное переключение формата ему
не требуется.

## Реализация RecorderLnx

`uMic185MebiusTcpProtocol.pas` разбирает `TUtsFrame`, проверяет ненулевые
`m_Start_CLK` и `m_CLK`, вычисляет X и Y по формуле оригинала. Драйвер хранит
последнюю пару. Источник данных публикует:

```text
timestamp тега = X
значение тега  = Y
```

Одновременно `Y` передаётся в `TRecorderTimeSystem` как последнее UTS-время.
Это позволяет выбрать отображение UTS в системе времени RecorderLnx.

## Запись Mera File

UTS является каналом с явной временной осью:

- `<тег>.x` содержит X — относительное аппаратное время метки;
- `<тег>.dat` содержит Y — абсолютные секунды UTS.

Это повторяет обработку `VT_R8 | VT_UTS` оригинального Recorder. Обычные
измерительные каналы продолжают использовать собственную шкалу времени блока.

## Проверка на стенде

1. В конфигурации присутствует канал `185-{<последний октет IP>-uts}`, 1 Гц, `s`.
2. После перехода в просмотр значение меняется примерно раз в секунду и не равно нулю.
3. Разность соседних Y обычно равна одной секунде; X монотонно растёт.
4. В созданном Mera File размеры `.x` и `.dat` одинаковы и содержат пары X/Y.
5. При выборе UTS как источника системного времени `LastUtsTimeSec` обновляется Y.

Формат `type_ = 1` (IRIG-B) имеет другую структуру и календарное декодирование;
он должен обрабатываться отдельной веткой, не как `TUtsFrame`.
