# MIC183/185 — настройки по умолчанию и коды АЦП

Зафиксировано по диалогам Recorder («Свойства канала 1», «Дополнительные свойства») и таблице каналов в режиме **коды** для прибора **MIC183/185** (s/n 157, `192.168.9.142:4000`, прошивка `20.6.6`).

Соответствие полям blob `CMIC185V2_BASESETTINGS` / `CMIC185V2_BASECHAN_SETTINGS` — исходники windev-v3.9: `mic185v2chanbase.cpp::Init`, `MIC185V2_DEFAULT` в `computephysical.h`, `CMIC185V2Base::Init` в `mic185v2base.cpp`.

Порт Lazarus (`Mic185BuildSettings` в `uMic185MebiusTypes.pas`) повторяет те же значения.

| Земля в циклограмме | вкл. | `Gnd_` | **true** (по `CMIC185V2Base::Init`) |

### Формула «Макс. частота канала»

Из `CMIC185V2Base::CalcMaxRate` (дефолты, `groupCount = 16`, режим «1 канал» выкл.):

```
chnTime = (GndCommut + NIOS_IRQ_DELAY) + (ChnCommut + NIOS_IRQ_DELAY) + 5 + 2 * (1 << AveragePointCount)
sampleTime = chnTime * groupCount
MaxFreq = (1 / sampleTime) * 1e6 * 0.90
```

При дефолтах: `(110 + 160 + 5 + 256) * 16 = 8496` мкс → **≈ 105 Гц** (совпадает с UI).

**Наблюдения:**

- Большинство каналов на **−32768** — типичное насыщение АЦП при отсутствии сигнала / обрыве / неподключённом входе.
- Каналы **3-1**, **3-3** на **+32767** — насыщение в положительную сторону.
- Активные коды (3-6, 3-8, 3-14, …) — реальный сигнал с датчиков на модулях.
- Значение **−124.0** у 3-46 не укладывается в int16; в стенде Lazarus для сверки использовать **целочисленные коды** тензоканалов; физические единицы — после `CComputePhysical::Eval`.

### Сверка со стендом Lazarus

Пакет `DEV_ID_MEAS_CHANNELS` содержит **float-коды АЦП** (режим «коды» в Recorder, `TYPE_SIGNAL_CODE=0`). Парсер: `RecorderMebiusParseFloatBlock`, смещение данных **12** байт (`CMic185PacketDataOffset`).

Команды сверки с таблицей ниже:

```bat
mic185_acquire_test.exe -verify-codes 192.168.9.142 4000 100 5
mic185_acquire_gui.exe --verify
```

Допуск ±3 (округление float→int). Эталон windev: [windev_mic185_test.md](windev_mic185_test.md).
