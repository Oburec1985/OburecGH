# Архитектура MIC185V2

## Аппаратный состав

Комплекс (из комментариев `mic185v2.cpp`):

- **MS046** — контроллер (OMAP)
- **MBP183** — блок питания
- **MI001** — Ethernet-выноска
- **BRO183** — плата индикации
- **MI0185** — модуль термокомпенсации (1 шт.)
- **MI0183** — модули тензоканалов (до 4 шт. × 16 каналов = 64 логических канала)

В конфигураторе Recorder отображается как **MIC183/185**, тип `MIC185V2_DEVICE_TYPE = 0x442A`.

## Каналы

| Группа | Макс. | Единицы в UI | Примечание |
|--------|-------|--------------|------------|
| Измерительные | 64 | мВ | Диапазоны ±500/±50/±5 мВ, тензо |
| Температурные | 5 | °C | LM74 на MI183, **1 Гц**, отдельные пакеты `dev_id=2`; см. [temperature_channels.md](temperature_channels.md) |
| СЕВ (UTS) | 1 | время | Опционально (`TASKSEV_EN_FLAG`) |

На скриншоте пользователя активно **20 каналов** (типично один модуль MI183 + часть второго или выборочная конфигурация). Драйвер программирует только каналы с `Connected = true`.

### Таблица коммутации

Физический адрес разъёма ≠ номер канала в ПО. Таблица `CHN_COMMUT_TABLE[64]` в `mic185v2base.h` задаёт соответствие логического канала и аппаратного входа.

### Диапазоны напряжения

```cpp
CHN_500_mV = 0
CHN_50_mV  = 1
CHN_5_mV   = 2   // ±5.000 мВ в UI
```

### Коммутация

```cpp
CHN_COMMUT_IN     = 0  // «Вход»
CHN_COMMUT_GND    = 1  // «Земля»
CHN_COMMUT_39_2mV = 2  // калибровочный
```

## Состояния устройства

По `DevState.h` / `CMIC185V2::OnProgram`:

```
DISCONNECTED → CONNECTED → PROGRAMMING → PROGRAMMED → STARTED
```

`ClearProgram()` сбрасывает программу при изменении свойств (частота, коммутация, балансировка и т.д.).

## Скан и буфер Nios

- Макс. буфер Nios: `MAX_NIOS_BUFFER_SIZE = 1016` (с учётом float × 4 ≤ 4096 байт solid limit).
- `CMIC185V2Scan::Program()` вычисляет `m_SamplesInBlock` из `MEPROPCH_BLOCK_SIZE` первого подключённого канала.
- Если блок не помещается — уменьшается число сэмплов в пакете.

## Метрология

Файл метрологии (`MIC185V2_METROLOGY_FILE`): КХ по диапазонам U, току, TKC, температурные коэффициенты. Загрузка через `IOCTL_CMD_LOAD_BLOCK_CALIBR`, `IOCTL_CMD_RELOAD_CALIBR` и др.

Для тестового чтения сырых данных достаточно заводских коэффициентов в приборе; blob `ProgramDeviceBin` передаёт только настройки скана, не файл метрологии.

## Отличие от MIC-140

| | MIC-140 | MIC185V2 |
|---|---------|----------|
| Протокол на живом приборе | Часто **legacy MDP** | **Mebius TCP** |
| Контроллер | MC031 + MC114 | MS046 (OMAP) |
| Каналы | 48 AIn + TIn | 64 тензо + 5 temp |
| Settings blob | `TMic140BaseSettings` (с TareName) | `CMIC185V2_BASESETTINGS` (компактнее) |
| Тип в devapi | `MIC140_*` | `MIC185V2_DEVICE_TYPE` |

## Отличие от legacy MIC0185

| | MIC0185 | MIC185V2 |
|---|---------|----------|
| Тип | `0x4129` | `0x442A` |
| Шина | MC114 scan / MC031 Ethernet | Прямой Mebius TCP |
| Модуль | `MIC0185mod.cpp` | `mic185v2_pc/` |
