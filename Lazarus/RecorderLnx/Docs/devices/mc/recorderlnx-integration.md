# Интеграция MC-032 и MC-201 в RecorderLnx

## Термины и границы

`MIC-200` — название конструктива прибора, а не отдельного протокола или
контроллера. В RecorderLnx программная граница называется `MCbus`:

- `MC-032` — Ethernet-контроллер крейта и ведущий шины;
- `MC-201` — четырёхканальный измерительный модуль в слоте;
- `Device/MCbus` — весь специфичный для этой связки транспорт, протокол,
  адаптер устройства, runtime-источник и диалоги.

MIC-140 и MIC-185 не зависят от MCbus. Общая граница устройств проходит через
`TRecorderDevice`; объединять можно жизненный цикл, но не форматы MDP/Mebius.

## Конфигурация и дерево

Источник сохраняется как `MC-032: <host>:<port>` в общем списке
`ConfiguredDataSources`. Слоты и их настройки сохраняются в конфигурационном
тексте источника. Нельзя восстанавливать дерево только из списков MIC-140,
MIC-185 и MERA: иначе MC-032 будет удалён при синхронизации реестра.

Диалог MC-032 выполняет:

1. поиск адреса в подсети `192.169.13.*`;
2. обязательный `TEST_LOAD`, подтверждающий поддерживаемый протокол;
3. чтение flash-полей слотов и распознавание MC-201/MC-201A;
4. сохранение найденных модулей после `Применить`/`OK`.

В дереве MC-032 является родителем, найденные MC-201 — дочерними узлами.
Двойной клик по дочернему узлу обязан открывать диалог слота MC-201, а не
диалог контроллера. Маршрутизация проверяет номер слота, маркер `MC-201` и
наличие родителя.

Для каждого MC-201 создаются четыре доступных канала. Имя канала имеет вид
`MC201_<индекс-источника>-<слот>-<канал>`, адрес — только цифровую часть
`<индекс-источника>-<слот>-<канал>`. Первый компонент адреса всегда равен
текущему индексу аппаратного узла. Для виртуальных тегов используется префикс
адреса `v`, а не слово `virtual`. Выбранные теги не должны повторно появляться
в списке доступных.

## Жизненный цикл Preview

Путь данных:

```text
TMainForm
  → TRecorderMcbusDataSource (рабочий поток)
  → TRecorderMcbusDevice (TRecorderDevice)
  → TMc032Device
  → TMc201LegacyMdpClient
  → MC-032 / MC-201
  → TRecorderAcquisitionBlock
  → TRecorderTagRegistry
  → визуальные компоненты
```

Последовательность подготовки и запуска:
`Connect → ProgramDevice → Start → ReadBlock`. Обычная остановка Preview
выполняет `Stop`; `Disconnect` относится к уничтожению или переконфигурации
источника. UI не читает потоковые данные.

В production `Connect → ProgramDevice` выполняются при загрузке проекта или
переконфигурировании. Успешный `Stop` сохраняет запрограммированную TCP-сессию,
поэтому следующий Preview выполняет только `STARTSCANMAIN`. Накопительные
массивы, матрица блока и массив времени повторно используются; Start/Stop не
меняют их ёмкость. Полный Disconnect выполняется при уничтожении источника.

`STOPSCANMAIN` может не получить подтверждение от контроллера. Если TCP-сессия
после этого безопасно закрыта, остановка считается завершённой, исключение в UI
не выбрасывается, а причина остаётся в логе. Teardown должен быть идемпотентным.

## Программирование диапазонов MC-201

Диалог слота сохраняет для четырёх каналов индексы диапазонов в строках
`CFG slot=N;c0=...;c1=...;c2=...;c3=...`. При создании runtime-источника строка
`SpecificConfigText` обязательно передаётся в `TRecorderMcbusDevice` до первого
`ProgramDevice`. Значение по умолчанию — индекс 1, то есть 2 В.

Порядок диапазонов повторяет `ranges_MC201` из оригинального `mtc/Mc201.cpp`:
8,5; 2; 1; 0,2; 0,1; 0,02 В. `SetRange` преобразует индекс в
`Amplif = index div 2` и `Att = (index mod 2) = 0`. Для ревизии `$0884` (2180)
биты раскладываются по `SetControlRegV5`: каналы идут блоками по 8 бит в обратном
порядке, а бит ослабления передаётся инвертированным. Для старых ревизий драйвер
использует раскладку оригинального `SetControlReg`.

### ICP/IEPE и субмодуль MM202

ICP не входит в основной управляющий регистр MC-201. Если в конфигурации слота
выбран вибромодуль MM202, драйвер для каждого канала передаёт отдельные свойства
`PRP_ICP_ON`, `PRP_ICP_HPF`, `PRP_SINGLE` командой `CMD_SET_PROPERTY`. Галочка ICP
соответствует исходной логике `PROP_INPUT_MODE=2`: значения `1,1,1`. После
отправки регистра MC-201 драйвер получает HANDLE через
`CMD_GET_OBJECT(OBJ_TYPE_ICPSUB)` и применяет накопленное слово MM202 командой
`CMD_SEND_CONTROL_WORD`. Отсутствие MM202 или ответ, отличный от `PRP_OK`, —
ошибка программирования, а не молчаливое продолжение запуска.

Диалог слота повторяет `Cmc201pp::OnIcpCheck` оригинального Recorder. Включение ICP
принудительно выбирает недифференциальный вход и запрещает ручную смену режима.
Снятие ICP возвращает дифференциальный вход и разрешает список. При повторном
открытии активный ICP отображается в том же состоянии. Без MM202 элементы ICP и
режима входа недоступны.

Частотная сетка MC-201 публикуется самим модулем через
`uRecorderFrequencyGrids`, а не задаётся в диалоге тега. Она содержит 16 значений
`ModuleMC201::IndexToFreq` от backplane 14,7456 МГц: 300, 450, 600, 900, 1200,
1800, 2400, 3600, 4800, 7200, 9600, 14400, 19200, 28800, 38400 и 57600 Гц.
Хотя в `Mc201.cpp` есть внутренняя константа 16,384 МГц, модуль имеет
`SelfClk=NOSELF_CLK`, поэтому `GetFreqClk()` берёт частоту backplane. Обычный
диалог крейта предлагает 14,7456/16/16,384 МГц, но `mdpEthernet81` программно
возвращает 14,7456 МГц и игнорирует setter. UI выбирает сетку по префиксу
`MC-032: `; преобразование в аппаратные коды использует тот же источник.

Для специсполнения MC-032 в диалоге контроллера выбирается частота backplane:
14,7456 МГц (стандарт, сетка до 57,6 кГц) или 16,384 МГц
(специсполнение, сетка до 64 кГц). Выбор хранится в специфичной конфигурации
строкой `CFG backplane=<Гц>`. При загрузке проекта сетка регистрируется по полному
`SourceId` контроллера, поэтому разные MC-032 могут иметь разные кварцы. Это же
значение передаётся в `TMc032Config` и применяется при переводе частоты тега в
`FreqIndex/GridCode`; UI и программирование модуля используют одну формулу.

Частота дискретизации принадлежит слоту MC-201, то есть сразу четырём его
каналам. Изменение частоты любого тега обновляет все теги того же слота, но не
затрагивает другие слоты MC-032. Перед программированием runtime собирает
`TMc201SlotConfig.SampleRateHz` из тегов; `SET_GRID`, `SET_FREQ`, размер кадра и
метаданные записи рассчитываются отдельно для каждого слота. Универсальный блок
захвата поддерживает необязательные поканальные `SampleCount`, `SampleRateHz` и
`FirstTimeSec`, поэтому разные частоты слотов не выравниваются искусственно.

## Аппаратная балансировка MC-201

Кнопка балансировки тега повторяет назначение `ModuleMC201::ZBalance`
оригинального Recorder. Команда модуля `SEND_BALANCE_CC` (`53`) получает канал и
два независимых 8-битных biased-кода ЦАП. Операция сериализована с обычным
чтением TCP; из Stop временно запускается служебный скан. При ошибке
восстанавливается прежний код.

Балансировка MC-201 выполняется одним ограниченным циклом. Драйвер собирает одну
секунду данных выбранного канала, потоково вычисляет среднее в кодах АЦП и один
раз программирует балансировочный ЦАП. Стендом подтверждена характеристика
`deltaADC ≈ -2,8*(lo-128)*(hi-128)`: выбирается минимальная достаточная ступень
`lo`, а основная поправка задаётся `hi`. Итерационный подбор ЦАП и повторные
служебные выборки не используются.

Код хранится отдельно для каждого канала и каждого из шести диапазонов как
`d<channel>r<range>` в строке `CFG slot=...`. Диалог свойств слота обязан сохранять
эти неизвестные ему поля. При каждом программировании MC-201 сохранённый код
повторно отправляется после настройки частоты. Программная компенсация данных для
MC-201 не используется.

`STOPSCANMAIN` не является гарантией сохранения регистров балансировочного ЦАП.
Поэтому успешная балансировка помечает текущую аппаратную программу устаревшей.
После служебного Stop ближайший `Start` один раз выполняет штатный
`ProgramDevice`, где сохранённые коды входят в конфигурацию MC-201 до
`STARTSCANMAIN`. Отправлять `SEND_BALANCE_CC` после запуска измерительного потока
нельзя: ответы модульных команд конкурируют с пакетами данных. Благодаря
перепрограммированию результат первой балансировки действует уже при ближайшем
переходе в просмотр.

Применение рассчитанного кода повторяет обязательную часть оригинального
`ModuleMC201::ChanCalibrFullSingleScan`: после `SendBalanceDAC` выполняется
отдельный цикл Stop/Start скана и короткая контрольная выборка. Она не меняет
рассчитанный код и не является вторым проходом балансировки; цикл нужен для
физического применения ЦАП модулем.

## Формат потока и объём данных

MDP-пакет может содержать несколько вложенных BIOS-сообщений. Его нельзя
трактовать как один канал. Для каждого вложенного сообщения:

- определяется канал по полной паре `slot + final flag`;
- первые 10 слов являются служебным заголовком и не публикуются как сигнал;
- payload накапливается отдельно по каждому из 16 каналов;
- готовый блок за 200 мс содержит 11 520 отсчётов на канал при 57 600 Гц.

Критический инвариант: `SetADSPFifoSize(256)` означает 256 отсчётов **на каждый
канал**, а не общий FIFO, делимый на 16. Деление на число каналов даёт примерно
1 700 отсчётов за 5 секунд и является ошибкой.

Проверенный результат стенда `192.169.12.87:4000`: 16 каналов, 25 блоков за
5 секунд, `25 × 11 520 = 288 000` отсчётов на канал, то есть ровно 57 600 Гц.

## Осциллограмма

Диалог показывает единый список каналов. Отдельной пользовательской сущности
«Основной канал» нет. Первый добавленный канал получает синюю линию, второй —
зелёную, третий — красную. Ограничение выбора каналами того же аппаратного
модуля сохраняется.

В модели первая линия исторически хранится в `TRecorderComponent.TagName`, а
остальные — в `TRecorderOscillogramComponent.Lines[]`. Это деталь совместимости
формата проекта, которая не должна проявляться в UI.

# Сервисные команды канала MC-201

Диалог настройки тега использует те же сервисные кнопки, что MIC-140/MIC-185:

- аппаратная настройка открывает `uRecorderMc201SlotSettingsDialog` для слота,
  вычисленного из адреса выбранного канала;
- балансировка проходит через `IRecorderZeroBalanceSupport`, затем через
  `IRecorderDevice.ExecuteDeviceAction(rdaZeroBalance, ...)`;
- чтение аппаратной калибровки вызывается через общий
  `rdaReadHardwareCalibration`.

Поддержка определяется базовым контрактом устройства, а не кодом протокола в
форме. Текущая балансировка MC-201 программная и действует до пересоздания
драйвера. Формат чтения заводской калибровки из flash MC-201 пока не портирован;
до его реализации общий вызов возвращает пользователю явную ошибку.
