# Hardware Source Lifecycle

Информация взята из текущей реализации RecorderLnx:
`Core/uRecorderHardwareLiveDevices.pas`, `Core/uRecorderHardwareTree.pas`,
`UI/uMainForm.pas`, `UI/uRecorderSettingsDialog.pas`, а также адаптеров
`Device/MIC140/uRecorderMic140DataSource.pas` и
`Device/mic185/uRecorderMic185DataSource.pas`.

## Active, live and offline

У аппаратного источника теперь есть три разных состояния:

| Состояние | Где хранится | Назначение |
| --- | --- | --- |
| Configured | теги и `dataSources[]` проекта | Источник есть в проекте, даже если прибор сейчас не подключен. |
| Active | `TRecorderTagRegistry.ActiveSourceIds` | Источник участвует в визуализации и создании data source при запуске просмотра. |
| Live | `uRecorderHardwareLiveDevices` | Уже есть рабочая сессия устройства, можно проверять связь через `IRecorderDevice.TestLink`. |
| Offline | `uRecorderHardwareLiveDevices` | Последняя попытка запуска/подключения не удалась; автоподключение запрещено до ручного сброса. |

## Правило автоподключения

Если MIC-140 или MIC-185 не подключился во время подготовки просмотра, sourceId
помечается offline. После этого:

- `UpdateActiveSourceIds` снимает этот sourceId из активных источников;
- `EnsureDemoDataSources` не создает для него runtime data source;
- дерево аппаратных настроек не делает долгие повторные TCP-попытки для уже
  помеченного offline sourceId;
- источник снова пробуется только после ручного сброса состояния.

Это сознательно отличается от старой логики, где каждый вход в просмотр мог
снова синхронно ждать сетевой timeout отключенного прибора.

## Ручной сброс

В контекстном меню дерева аппаратных настроек добавлены команды:

- `Сбросить состояние устройства` - снимает offline-метку выбранного sourceId;
- `Сбросить состояние всех устройств` - снимает offline-метки всех источников.

После сброса следующая проверка дерева или старт просмотра снова может
попробовать подключить прибор. Если прибор все еще недоступен, он снова будет
помечен offline при неудачной подготовке.

## Таймауты

- Быстрый probe в дереве аппаратуры ограничен `250 ms`, чтобы диалог настроек
  не зависал на каждом отсутствующем приборе.
- MIC-185 runtime connect сокращен до одной попытки с timeout `1200 ms`.
  Протокол и формат пакетов при этом не меняются.

## Приоритет признаков состояния и подсказки

- Текущая работающая сессия со состоянием `rdsStarted` является более свежим и
  надежным признаком доступности, чем сохраненная ранее offline-ошибка. При
  обнаружении работающей сессии устаревшая offline-метка снимается.
- Команда ручного сброса не должна безусловно окрашивать устройство зеленым:
  после снятия старой ошибки выполняется `TEST`. Зеленый статус назначается
  только при успешном результате; при отказе сохраняется текст новой ошибки.
- Hint узла устройства показывает сохраненную причину offline-состояния.
  Обработчики наведения являются только отображением состояния и не выполняют
  TCP-подключение, `TEST` или другие операции с оборудованием.
- Для MCbus активный поток данных уже подтверждает соединение. Нельзя посылать
  отдельную команду `TEST` в занятую потоковую MDP-сессию: это может нарушить
  разбор ответов и создать ложную offline-ошибку.
- Если Stop сохраняет TCP-соединение и запрограммированное состояние для
  быстрого повторного Preview, live-регистрация также сохраняется. Каждый
  успешный Start обязан идемпотентно подтвердить регистрацию; удалить ее можно
  только после disconnect или уничтожения владельца.
