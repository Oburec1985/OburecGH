# Исторический SQL-тренд RecorderLnx

## Назначение

Компонент `SQL trend` показывает сохранённые в SQL БД значения сигналов с
привязкой оси X к астрономическому времени. Он не использует текущий реестр
тегов RecorderLnx: доступные каналы считываются из поля `signals.name` базы.
Поэтому тренд может открыть старую или внешнюю БД, в которой имена сигналов
отличаются от имён тегов текущего проекта.

## Добавление и настройка

1. Открыть пользовательскую мнемосхему и включить режим редактирования.
2. Нажать инструмент `SQL` и указать щелчком место компонента.
3. Открыть настройки компонента двойным щелчком.
4. Нажать `Прочитать каналы из БД`, выбрать сигнал и добавить линию.
5. Для линии назначить подпись, цвет, видимость и ось Y.
6. Настроить оси Y и временной режим.

Настройки имеют два временных режима:

- фиксированный диапазон `От/До (UTC)`;
- последнее окно заданной длительности в часах.

Поля `От`, `До` и `Окно` связаны соотношением `Окно = До - От`. Изменение
границы пересчитывает длительность, изменение длительности сдвигает `От`,
сохраняя `До`. После чтения каналов диалог показывает фактическое количество
точек и диапазон БД; кнопка `Весь диапазон` подставляет эти границы.

`Max points per line` ограничивает количество отображаемых точек одной линии.
Это защищает UI и память при просмотре длинных интервалов. Запрос выполняется
в отдельном потоке после появления формы, поэтому соединение с БД не блокирует
запуск и перерисовку RecorderLnx.

## Система времени

В `signal_values.timestamp_utc` хранится абсолютное время точки в формате
`TDateTime` UTC (число суток от эпохи Delphi/FPC). SQL-тренд использует это поле
непосредственно как координату X. Для режима последнего окна его правая граница
вычисляется как текущее UTC-время, левая — как `UTC now - window duration`.

Это отличается от обычного runtime-тренда, где X строится из времени текущего
сеанса Recorder. Преобразование аппаратного или локального timestamp в
астрономическое UTC выполняется при публикации и SQL-записи; исторический тренд
не пересчитывает точки повторно.

## Хранение конфигурации

Тип компонента: `sql-trend`. В `.gui.ini` сохраняются:

- относительный путь к `sql-db.ini`;
- режим и границы времени;
- длительность последнего окна;
- ограничение числа точек;
- список линий с именами сигналов БД;
- список осей и диапазоны.

Исходники модели, представления и LFM-диалога находятся в каталоге `SQLdb`.

## Что рекомендуется добавить до уровня SCADA

Следующие функции полезно реализовывать по приоритету:

1. Панорамирование, масштабирование колёсиком и кнопки «назад/вперёд» по времени.
2. Один и два измерительных курсора: время, значение, разность времени и значений.
3. Полосы качества данных: good/bad/uncertain, разрывы линии при отсутствии данных.
4. Маркеры событий и тревог с фильтром важности и переходом к журналу событий.
5. Маркеры связанных файлов: осциллограмм, спектров, орбит; открытие файла по клику.
6. Серверная агрегация для больших интервалов: min/max/mean/envelope на пиксель.
7. Автомасштаб осей, логарифмическая шкала, единицы измерения и несколько шкал Y.
8. Быстрые интервалы: 15 минут, час, смена, сутки, неделя, произвольный диапазон.
9. Сравнение периодов и синхронное отображение нескольких объектов/регистраций.
10. Экспорт видимого диапазона в CSV/Excel и изображения с заголовком объекта.
11. Сохранённые шаблоны тренда и права доступа к каналам/объектам.
12. Отображение часового пояса пользователя при сохранении внутреннего времени UTC.

Для производственной эксплуатации первыми стоит делать серверную агрегацию,
качество данных, курсоры и события: они сильнее всего влияют на диагностическую
ценность и скорость исторического тренда.
