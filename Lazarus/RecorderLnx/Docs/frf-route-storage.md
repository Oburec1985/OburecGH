# FRF: конфигурация маршрута и результаты

Маршрут принадлежит проекту, а сохранённые измерения — выбранному объекту БД
или ручному каталогу результатов. Эти пути независимы.

- `TRecorderFrfRoute.ConfigFileName` задаётся проектом:
  `<project>/frf-routes/<hex component ID>/route.ini`.
- Активный каталог предоставляет `RecorderProjectConfigurationDirectory`,
  устанавливаемый главным окном и загрузчиком/сохранением GUI. Сохранённый
  default-проект не является runtime-контекстом: изолированный виджет без
  явного контекста не должен писать в пользовательский проект.
- `Directory` задаёт только корень результатов; `PointDirectory` добавляет
  стабильную папку шага. MERA хранится в `<step>/frf/session.mera`.
- Версия конфигурации 3 хранит шаги, подписи, identity и привязки; не хранит
  `Captured` и `Current`. Сохранённость определяется по MERA в текущем объекте,
  текущий шаг остаётся состоянием интерфейса.
- `Save(resultsDirectory)` не создаёт route.ini в папке результатов. Если
  проект ещё не назначил `ConfigFileName`, маршрут остаётся в памяти.
- `Load(resultsDirectory)` сначала читает проектный файл, затем старый
  `<results>/route.ini`. Такой импорт сам по себе ничего не записывает.
  Следующее сохранение пишет только проектный файл, не удаляя старый файл
  или измерения.
- `HasManifest(resultsDirectory)` учитывает оба источника. Проверки прямого
  наличия `<results>/route.ini` в интерфейсе использовать нельзя.

При смене объекта меняется `Directory`, пересчитываются отметки MERA и
сбрасывается дисковый просмотр. Конфигурация маршрута и несохранённые замеры
в оперативной памяти не должны исчезать.

Проверка: `Tests/RecorderTests/FrfRoute/FrfRouteTest.lpi`: config/results
separation, no Current/Captured, read-only legacy migration, object A/B/A.
