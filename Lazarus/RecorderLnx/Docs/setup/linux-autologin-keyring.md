# Fly-DM autologin и GNOME Keyring

## Инвариант

Если на Linux-ПК включён автоматический вход Fly-DM и используется защищённая связка GNOME Keyring, три значения должны совпадать:

1. пароль локального пользователя (`/etc/shadow`);
2. `AutoLoginPass` в `/etc/X11/fly-dm/fly-dmrc`;
3. master-password `~/.local/share/keyrings/login.keyring`.

Файл Fly-DM с открытым паролем обязан принадлежать `root:root` и иметь режим `0600`. Включать синхронизацию можно только после явного предупреждения пользователя.

## LinuxSetupManager

В GUI откройте «Пользователи и права», выберите пользователя и нажмите «Пароль…». Пароль вводится дважды. Галочка синхронизации Fly-DM обновляет `AutoLoginPass`; без неё меняется только Unix-пароль.

CLI:

```text
LinuxSetupManagerCli password USER [--sync-flydm]
```

CLI читает две строки stdin: пароль и подтверждение. Секрет запрещено передавать аргументом или сохранять в журнал. При CRLF удаляется ровно один завершающий `CR`.

GNOME Keyring утилита намеренно не перепароливает: у используемой версии нет надёжного headless rekey. Если пароль связки неизвестен, сначала сохранить резервную копию `login.keyring`, затем с явного согласия пересоздать связку; сохранённые в ней секреты потребуется ввести заново.

## Обязательная проверка

После изменения выполнить реальную перезагрузку и подтвердить:

- Fly-DM автоматически вошёл под нужным пользователем;
- Secret Service показывает `locked=false` для связки «Вход»;
- в `journalctl -b` нет `starting password prompt`;
- `fly-dmrc` имеет владельца `root:root` и режим `0600`;
- пароль отсутствует в argv процессов и диагностических журналах.
