# Файлообмен между компьютерами Astra Linux через Samba

## Назначение

Методичка описывает настройку собственной общей папки на каждом компьютере
Astra Linux. После настройки она открывается с Linux и Windows по адресу вида
`\\192.168.9.66\Obmen`.

Пример рассчитан на Astra Linux 1.8 x86-64, пользователя `user`, локальную сеть
`192.168.0.0/20`, каталог `/home/user/Обмен` и сетевое имя `Obmen`. Команды
выполняются на каждом ПК отдельно. Одна конфигурация подходит всем узлам.

## Требования и безопасность

Нужны работающая сеть и пользователь с правом `sudo`. Используйте отдельный
пароль Samba. Не храните пароли прокси и Samba в общедоступных текстовых файлах.
TCP-порты 139 и 445 разрешайте только в доверенной локальной сети, не в интернет.

Посмотрите текущие адреса и маршруты:

```bash
ip -4 address
ip -4 route
```

## 1. Доступ к репозиторию через локальный прокси

Если прямого доступа к репозиториям нет, проверьте имя прокси:

```bash
getent hosts prox.mera.local
```

В рассматриваемой сети прокси имеет адрес `10.5.0.248`, порт `3128`, а маршрут
к нему проходит через шлюз `192.168.0.254`. Найдите имя проводного интерфейса:

```bash
ip -4 route get 192.168.0.254
```

Добавьте временный маршрут, подставив своё имя интерфейса (`enp3s0`, `eno1`):

```bash
sudo ip route replace 10.5.0.248/32 via 192.168.0.254 dev enp3s0
ip route get 10.5.0.248
```

Проверьте прокси, указав свои учётные данные:

```bash
curl -I --max-time 20 \
  -x http://prox.mera.local:3128 \
  -U 'ЛОГИН:ПАРОЛЬ' \
  https://download.astralinux.ru/
```

Ответ `HTTP 200` означает, что маршрут и прокси работают.

Для сохранения маршрута после перезагрузки найдите активное подключение и
добавьте маршрут в его профиль:

```bash
nmcli -t -f NAME,DEVICE connection show --active

sudo nmcli connection modify 'Проводное соединение 1' \
  +ipv4.routes '10.5.0.248/32 192.168.0.254'

nmcli -g ipv4.routes connection show 'Проводное соединение 1'
```

Повторно добавлять уже существующий маршрут не нужно.

## 2. Установка Samba

Передавайте прокси только процессу `apt`, заменив логин и пароль:

```bash
sudo env \
  http_proxy='http://ЛОГИН:ПАРОЛЬ@prox.mera.local:3128' \
  https_proxy='http://ЛОГИН:ПАРОЛЬ@prox.mera.local:3128' \
  apt-get update

sudo env \
  http_proxy='http://ЛОГИН:ПАРОЛЬ@prox.mera.local:3128' \
  https_proxy='http://ЛОГИН:ПАРОЛЬ@prox.mera.local:3128' \
  DEBIAN_FRONTEND=noninteractive \
  apt-get install -y samba smbclient
```

Если `prox.mera.local` не разрешается, временно замените имя адресом
`10.5.0.248`. Не сохраняйте пароль в `/etc/apt/apt.conf` без необходимости и
ограничения прав на файл.

## 3. Создание папки обмена

Выполните от имени обычного пользователя:

```bash
mkdir -p /home/user/Обмен
chmod 0770 /home/user/Обмен
```

Права `0770` закрывают каталог для посторонних локальных пользователей.

## 4. Настройка сетевого ресурса

Сохраните исходную конфигурацию:

```bash
sudo cp -n /etc/samba/smb.conf /etc/samba/smb.conf.before-obmen
```

Добавьте в конец `/etc/samba/smb.conf`:

```ini
[Obmen]
   comment = File exchange
   path = /home/user/Обмен
   browseable = yes
   read only = no
   valid users = user
   force user = user
   create mask = 0660
   directory mask = 0770
```

| Параметр | Назначение |
|---|---|
| `path` | Публикуемая локальная папка. |
| `browseable` | Показывает ресурс при просмотре сервера. |
| `read only = no` | Разрешает запись и удаление файлов. |
| `valid users` | Ограничивает вход указанным пользователем Samba. |
| `force user` | Создаёт файлы от имени локального пользователя. |
| `create mask` | Ограничивает права новых файлов значением `0660`. |
| `directory mask` | Ограничивает права новых каталогов значением `0770`. |

Проверьте синтаксис:

```bash
sudo testparm -s
```

Ожидаемое сообщение: `Loaded services file OK`.

## 5. Пользователь Samba и служба

Локальный пользователь должен уже существовать. Создайте ему пароль Samba:

```bash
sudo smbpasswd -a user
```

Введите пароль дважды, затем запустите службу:

```bash
sudo systemctl enable --now smbd
sudo systemctl restart smbd
systemctl is-active smbd
```

Ожидаемый результат — `active`.

## 6. Проверка доступа

На сервере:

```bash
smbclient //127.0.0.1/Obmen -U user -c 'ls'
```

С другого Linux-ПК:

```bash
smbclient //192.168.9.66/Obmen -U user -c 'ls'
```

Проверка TCP-порта без авторизации:

```bash
timeout 5 bash -c '</dev/tcp/192.168.9.66/445' \
  && echo SMB_OK || echo SMB_FAIL
```

В Windows введите в адресную строку Проводника:

```text
\\192.168.9.66\Obmen
```

При запросе укажите `user` и пароль Samba.

## 7. Несколько компьютеров

Повторите настройку на каждом узле. Для стенда используются адреса:

```text
\\192.168.9.17\Obmen
\\192.168.9.45\Obmen
\\192.168.9.66\Obmen
\\192.168.9.85\Obmen
\\192.168.9.200\Obmen
\\192.168.9.92\Obmen
```

Это независимые папки: файл, скопированный на один адрес, автоматически не
появляется на остальных.

## 8. Типовые неисправности

### Нет маршрута до репозитория

```bash
ip route get 10.5.0.248
curl -I --max-time 10 -x http://10.5.0.248:3128 http://example.com
```

Проверьте правильность шлюза, интерфейса, адреса и порта прокси.

### Не разрешается имя прокси

При сообщении `Временная ошибка при разрешении prox.mera.local` проверьте
`/etc/resolv.conf`. Для разовой установки можно использовать IP прокси.

### Samba активна, но ресурс недоступен

```bash
sudo ss -ltnp | grep -E ':(139|445) '
```

Если включён firewall, разрешите TCP 445 только из `192.168.0.0/20`. Команда
зависит от используемого фильтра (`nftables`, `iptables` или `ufw`).

### Ошибка авторизации

```bash
sudo smbpasswd -a user
sudo pdbedit -L | grep '^user:'
```

Также удалите сохранённые старые сетевые учётные данные Windows и войдите снова.

### Длинное NetBIOS-имя

NetBIOS допускает не более 15 символов. При доступе по IP предупреждение не
мешает работе. Для доступа по имени задайте короткое уникальное `netbios name`
в секции `[global]`, затем повторите `testparm`.

## 9. Остановка и восстановление

Временно остановить публикацию:

```bash
sudo systemctl stop smbd
```

Вернуть исходную конфигурацию:

```bash
sudo cp /etc/samba/smb.conf.before-obmen /etc/samba/smb.conf
sudo testparm -s
sudo systemctl restart smbd
```

Восстановление `smb.conf` не удаляет и не восстанавливает пользовательские
файлы. Перед удалением `/home/user/Обмен` отдельно сохраните нужные данные.
