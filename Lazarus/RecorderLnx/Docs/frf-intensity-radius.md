# Радиус интенсивности FRF

В «Отображение FRF» есть опция «Логарифмический радиус». Ручного диапазона
дБ нет: обе границы определяются по измеренным точкам на текущей частоте.
Старые конфигурации без log-флага остаются линейными.

Для положительных конечных значений A после Gain/Abs:

`D = 20 * (log10(Amax) - log10(Amin))`

`r = (log10(A) - log10(Amin)) / (log10(Amax) - log10(Amin))`

Это доля радиуса, не площади. Минимум/максимум берутся среди enabled-точек,
успешно измеренных на выбранной частоте. Перемещение частотного курсора
изменяет и значения, и границы; preset-диапазон осей для log не используется.

Пример для текущих точек 0,1; 1; 10; 100:

| Амплитуда | Доля максимального радиуса |
| --- | --- |
| 0,1 | 0 |
| 1 | 1/3 |
| 10 | 2/3 |
| 100 | 1 |

Ноль имеет нулевой радиус и не входит в логарифмическую нижнюю границу;
невалидные/отсутствующие значения исключаются. Если все положительные
значения равны (в том числе одна измеренная точка), их радиус максимальный.
Если все значения нулевые, радиусы нулевые. Поэтому размер единственной
положительной точки при этой нормировке не меняется с частотой.

Линейная шкала сохраняет прежнюю нормировку по максимуму в преднастроенном
частотном диапазоне. Числовые значения, цвета и последующая анимационная
модуляция не меняются. Диапазон log определяется одним проходом по готовым
отсчётам точек, без дополнительного сканирования частотных спектров.

IntensityLogScale проходит model → route/live bindings → 3D/project codec.
Ошибочно добавленные старые ключи IntensityLogRangeDb при чтении игнорируются
и больше не записываются. Причина уточнения и проверка:
[расследование](../errors/2026-10-30-frf-log-radius-normalization.md).
