# Конфигурация RecorderLnx и rcPanel

Имя испытательной конфигурации — имя её каталога. Новые проекты сохраняются
в этот каталог с постоянными именами:

| Файл | Назначение |
| --- | --- |
| `config.json` | Каналы, теги, источники, расчёты и параметры испытания. |
| `gui.ini` | Страницы и компоненты интерфейса проекта. |
| `run-control.ini` | Условия запуска, останова и записи проекта. |
| `sql-db.ini` | Выбор записываемых сигналов, период и метаданные испытания. |

`app.ini` принадлежит установке RecorderLnx, а не испытанию. В нём находятся
в том числе соединение SQL (`SQLdbConnection`), выбранный локальный сетевой
интерфейс (`Network/BindAddress`) и подробный журнал устройств
(`Diagnostics/DeviceLogEnabled`). Настройки координатора остаются в
`coordinator-client.ini`, очередь событий — в отдельном JSON. Реальные
абсолютные пути зависят от `RecorderLnx.paths.ini` и параметров запуска.

Рабочий каталог Mera Files хранится в `storage.ini` рядом с `app.ini`.
При первом штатном запуске он переносится из активного старого проекта; выбор
другого проекта больше не меняет его. `RecorderLnx.paths.ini` остаётся
загрузочным указателем, позволяющим найти `app.ini` и `storage.ini`: он может
отличаться от рабочего каталога. При ошибке существующего `storage.ini`
приложение не подставляет молча старый проектный путь. rcPanel читает тот же
рабочий путь; до появления `storage.ini` — путь активного старого проекта.

Старые `default.config.json`, `default.gui.ini` и
`default.run-control.ini` читаются для совместимости. Если рядом находятся
различающиеся старый `run-control.ini` и ранее активный
`default.run-control.ini`, до сохранения приоритет у последнего. При сохранении
старые данные сохраняются с суффиксом `.legacy-backup`, при повторных
конфликтах добавляется номер. Это резервные копии, а не активная конфигурация.
Миграция производится при сохранении проекта; предварительно созданные копии
не удаляются. Сохранение нескольких файлов не является единой транзакцией.

Сетевой интерфейс из прежнего JSON переносится в приложение при штатном
открытии начального проекта только если локальная настройка отсутствует.
Недоступный сейчас адрес сохраняется; фактический маршрут может временно
выбираться ОС. При отсутствии права записать приложение прежний параметр
остаётся в проекте и перенос откладывается. Прямое чтение проекта без режима
миграции не изменяет app.ini.

Старые параметры SQL-подключения в `sql-db.ini` читаются как fallback, если
соответствующие значения не заданы в приложении; при сохранении проекта
дублирующие поля убираются. Учётные данные старого PostgreSQL пока сохраняются
в прежнем защищаемом проектном файле — общий защищённый хранилищный механизм
для них не реализован. Сохранение app.ini и SQL-файла — отдельные операции.

rcPanel хранит собственную конфигурацию в `RecorderCoordinator.ini`, а общий
адрес SQL берёт из конфигурации RecorderLnx. Для обычного `app.ini` проектный
`sql-db.ini` определяется по выбранному каталогу проекта при старте панели.
Произвольные явно заданные пути к SQL-конфигурации сохраняют совместимость.
Открытая панель пока не отслеживает смену проекта автоматически.

Имя сетевого ресурса записи остаётся в run-control: оно связано с выбранным
для конкретного испытания каталогом записи. Настройки приложения и рабочего
каталога записываются отдельно, общей транзакции для обоих файлов нет;
ошибка применения может оставить часть настроек сохранённой.
