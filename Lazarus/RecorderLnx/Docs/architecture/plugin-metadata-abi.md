# Плагины RecorderLnx: поэтапный контракт

RecorderLnx хранит список подключённых плагинов и снимок их метаданных в
глобальном файле настроек приложения `app.ini`, а
библиотеки — в каталоге `plugins` рядом с исполняемым файлом (`*.dll` / `*.so`).
На вкладке «Плагины» кнопка «Добавить» выбирает библиотеку, читает её
`GetPluginInfo` и показывает подтверждение с названием, описанием, автором и
версией. При подтверждении файл копируется в `plugins` (если выбран в другом
каталоге), а запись с метаданными немедленно сохраняется в `app.ini` без
нажатия «Применить»/«OK» и без сохранения конфигурации проекта.
Повторное открытие списка читает сохранённые строки из INI без загрузки DLL/so.
«Удалить» немедленно убирает запись из `app.ini`, но оставляет файл на диске.
Если найден прежний проектный `plugins.ini`, его записи однократно переносятся
в глобальный список без удаления исходного файла. Изменения
загрузки и выгрузки кода вступают в силу после перезапуска RecorderLnx;
действующий экземпляр плагина не выгружается из-под созданных компонентов.

## Совместимый контракт

Общий исходник SDK — `Plugins/SDK/uRecorderPluginApi.pas`. Библиотека
экспортирует `GetPluginInfo(var AInfo: TRecorderPluginInfo); cdecl` и может
экспортировать оригинальные `GetPluginType: LongInt; cdecl` и
`GetPluginDescription: PAnsiChar; cdecl`. Имена экспортов совпадают с Recorder.
`PLUGININFO` сохраняет три фиксированных массива AnsiChar размером 101, 201 и
201 байт, затем четыре `SmallInt` версии. Структура не `packed`, размер на
целевых ABI — 512 байт. Новые библиотеки записывают строки в UTF-8 и завершают
нулём. Загрузчик заранее обнуляет структуру, поэтому два отсутствующих поля
версии старых Delphi-плагинов остаются нулевыми.

## Исполняемый этап и фабрика

Для подключённых библиотек загрузчик вызывает `CreatePluginClass`,
`PluginCreate`, `PluginNotify`, `PluginClose`, `DestroyPluginClass` через
`DynLibs`. Оригинальные имена методов `_Create`, `Config`, `Edit`, `Execute`,
`Suspend`, `Resume`, `Notify`, `GetName`, `GetProperty`, `SetProperty`,
`CanClose`, `Close`, а также `AddPlgEvent`/`RemovePlgEvent`/`CallPlgEvents`
показаны в тестовом `SampleInfoPlugin/PluginClass.pas`. Поддержанные хостом
уведомления используют исходные номера `PN_*` для загрузки/сохранения проекта,
входа/выхода из настроек, старта/остановки записи и обновления данных.

Через границу DLL/so проходят только фиксированные записи, целые числа, строки
UTF-8 с нулём и непрозрачные указатели. Плагин регистрирует callback фабрики
`sample.oscillogram`; хост создаёт собственную модель осциллограммы и
размещает кнопку в группе «Графики». Фабрики не публикуются, пока
`PluginCreate` не завершился успешно. Код плагина выгружается после моделей
и фабрик. Неподдержанные операции демонстрационного класса возвращают `False`.

Это совместимость переносимого исходного кода и выбранных имён, **не** двоичная
совместимость с Delphi COM `IRecorderPlugin` или запуск Windows DLL под Linux.
Просмотр информации выполняет инициализацию DLL/so при `LoadLibrary`, поэтому
добавлять следует только доверенные библиотеки. Формы LCL и объекты Pascal
между процессом и библиотекой не передаются.

## Сборка и проверка

Открыть `Plugins/plugins.lpg` в Lazarus и выполнить «Собрать всё»: тестовый
плагин окажется непосредственно в соседнем с RecorderLnx каталоге `plugins`.
Плагин также включён в основную `group.lpg`. Один исходник `.lpr` собирается
без правок под Windows и Linux. Консольный `Tests/PluginInfo/PluginInfoProbe`
проверяет размер ABI, загрузку библиотеки, тип и версию; итог —
`RESULT PluginInfo passed`, лог пишется рядом с тестовой программой.
`Plugins/SampleInfoPlugin/Tests/SamplePluginProbe` отдельно проверяет полный
цикл flat ABI и callback создания; итог — `RESULT sample-plugin passed`.

Эталон для сравнения: `windev-v3.9/rc_guisrv/setup/loadplg.cpp`,
`windev-v3.9/mr/iface/rcplugin.h` и `recorder/plgEvalFRF/plgEvalFRF.dpr`.
