# Привязка аппаратных соединений к сетевому интерфейсу

В Windows список формируется через `GetAdaptersAddresses`: отображаются только
адаптеры с состоянием `Up` в виде `Имя адаптера [IPv4]`. В конфигурации и при
вызове `bind()` используется только IPv4 из выбранной строки.

Вкладка **Настройка → Аппаратные свойства** содержит общий выбор локального
IPv4-адреса для аппаратных TCP-соединений RecorderLnx.

- **Автоматически (метрика ОС)** — сокет не привязывается локально; маршрут и
  интерфейс выбирает операционная система по таблице маршрутизации и метрикам.
- Конкретный IPv4 — перед `connect()` выполняется `bind()` к этому локальному
  адресу. Режим применяется к MIC-140, MIC-183/185 и MC-032/MC-201.

Выбор сохраняется в `project.json` как `networkBindAddress`. Пустая строка
означает автоматический режим. Изменение действует при следующем подключении
приборов; уже открытые сокеты не перепривязываются.

Если адрес исчез (адаптер отключён или IP изменён), он остаётся видимым в
списке для диагностики, а подключение завершается понятной ошибкой `bind`.
# Проверка пути до прибора

На вкладке «Аппаратные свойства» рядом с выбором сетевого интерфейса находятся поля адреса и TCP-порта и кнопка «TCP-пинг». Проверка сразу применяет текущий выбор интерфейса, создает TCP-сокет, привязывает его к IPv4 выбранного адаптера и подключается к указанному адресу. Это проверяет реальный путь RecorderLnx до порта прибора, а не только ICMP ping.

Адрес `192.168.9.142`, используемый по умолчанию для MIC-183/185, является программным адресом по умолчанию и сам по себе не означает успешного обнаружения устройства.
# Автоматическое обнаружение приборов

Поиск выполняется через выбранный в аппаратных настройках активный сетевой
адаптер. В режиме «Автоматически (метрика ОС)» используются активные IPv4-сети,
выбранные операционной системой.

Алгоритм двухступенчатый:

1. Отправляются штатные broadcast-запросы оригинального Recorder: современный
   MebiusDAQ (`UDP 4400/4401`) и совместимый Ethernet81 (`UDP 4001/4002`). Ответ
   содержит IP, тип и серийный номер, поэтому найденный таким способом прибор
   добавляется без `TestLink`.
2. Для приборов, не ответивших на broadcast, перебираются адреса реальной
   подсети выбранного адаптера. Сначала коротко проверяется TCP/4000, затем
   только для открытых адресов последовательно выполняется идентификация
   MIC183/185, MIC-140 и MC-032.

Адрес `192.168.9.142` не является встроенным участником поиска: это лишь старое
значение по умолчанию в диалоге ручного добавления MIC183/185.
