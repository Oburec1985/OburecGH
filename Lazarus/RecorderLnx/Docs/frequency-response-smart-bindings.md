# АФЧХ: узлы, линии и источники частоты

Редактор задаёт узлы АЧХ / Фаза / FRF. Узел содержит ось Y и тип всех
вложенных линий. Групповое перетаскивание справа добавляет все выделенные
теги в выбранный узел. Справа показаны только имя и частота опроса;
поиск использует также адрес и описание и фильтрует селекторы тегов.

Диапазон X берётся из настройки оси компонента, диапазон Y — выбранного
узла. Оба логарифмических переключателя сохраняются и реально участвуют
в проекции. Для логарифмической оси нижняя граница должна быть положительной.

`RecorderResolveFrequencyResponseBinding` разрешает настройки только при
Configure или редактировании. Результат — прямые ссылки на Y/X, способ чтения
частоты, признак блокировки и пояснение. Обработчик данных не ищет имена,
не разбирает конфигурации и не создаёт алгоритмы.

- Скалярная частота: последнее значение.
- Вектор: готовая оценка МО; существующий выход главной гармоники спектра;
  либо выход уже назначенного этому входу алгоритма Tacho.
- АЧХ исходного вектора: при наличии полосового RMS выбирается его расчётный
  тег. Следящая полоса имеет приоритет перед абсолютной.
- У следящей полосы `1 * тacho` частотный вход берётся из её формулы,
  показывается в подсказке и блокируется. Главная гармоника полосы `f1` не
  подменяет её опорный тахо. Сложные многосоставные формулы не объявляются
  автоматически однозначным тахо-входом.
- При отсутствии готового спектрального/тахо результата выводится подсказка,
  а не создаётся скрытый FFT/алгоритм. Случайный первый глобальный тахо
  не используется.

Обновление X меняет только частоту. Точка записывается при обновлении Y,
чтобы новое X со старым Y не загрязняло усреднение/максимум. Отдельные
расчётные теги не имеют общего frame ID: при Y используется последнее
доступное X, аппаратная синхронность этой парой не заявляется.

Формат GUI добавляет `FrLogFrequency`, `FrAxisNKind` и
`FrLineNFrequencyMode`. Старый тип узла восстанавливается по первой
вложенной линии; Assign сохраняет новые поля. Разрешённые автоматические
теги в форме остаются display-only и не превращаются в явные привязки от OK.

Проверки: FrequencyResponseUiSmoke (таблица/поиск/drag/тип/оси/Cancel/OK)
и FormModel/FrequencyResponseBindingTest (RMS/тахо/МО/спектр, Assign,
сохранение/миграция, runtime-пары и отсутствие точек от X-only).

Прообраз: plgControlCyclogram/forms/uControlWarnFrm.pas, TWrkPoint.getValue
(чтение готовых оценок X/Y). В этой реализации оценки принадлежат тегам,
а не форме настройки.
