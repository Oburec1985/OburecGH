## 1. Термины и определения

| Термин | Определение и связь с другими объектами |
|---|---|
| Проект | Набор конфигурационных файлов RecorderLnx: источники, теги, формуляры, компоненты, параметры записи и SQL. Имя каталога проекта показывается в заголовке главного окна. |
| Источник данных | Поставщик исходных отсчётов: физический прибор MIC-140, MIC183/185, модуль MCbus либо программный источник. Один источник создаёт один или несколько аппаратных каналов. |
| Канал устройства | Физический измерительный вход. Его диапазон, коммутация, питание датчика и аппаратная ГХ задаются в настройках конкретного прибора. |
| Тег | Именованная точка данных RecorderLnx. Тег связывает адрес канала с частотой опроса, единицами, диапазоном, ГХ и уставками. Формуляры и SQL работают с тегами, а не напрямую с драйверами. |
| Аппаратная ГХ | Преобразование, определяемое режимом источника/устройства. Например, MIC-185 может выдавать мВ, Ом или мкстрн. При автоматических единицах результат аппаратной ГХ задаёт входные единицы следующего узла. |
| Канальная ГХ | Одна или несколько пользовательских характеристик тега, применяемых после аппаратной ГХ. Порядок ГХ влияет на результат и конечные физические единицы. |
| Оценка | Производная величина сигнала, например текущее значение, Mean, RMS или Max. Компонент отображения и SQL-запись могут использовать разные оценки одного тега. |
| Формуляр | Страница отображения. Может содержать цифровые индикаторы, осциллограммы, тренды, картинки, кнопки и измерительные сечения. |
| Preview | Просмотр данных без основной записи измерительного файла. Используется для проверки связи, единиц, диапазонов и отображения. |
| Record | Сбор с записью по настроенным правилам. Может дополнительно записывать выбранные оценки в SQL БД. |

## 2. Назначение и состав RecorderLnx

RecorderLnx предназначен для подготовки измерительной системы, оперативного
просмотра, регистрации сигналов и последующего анализа. Настройки разделены по
уровням, потому что каждый уровень отвечает за свою часть тракта:

| Раздел настройки | Что находится в разделе | На что влияет |
|---|---|---|
| Настройка регистратора | Частота обновления интерфейса, длина отображаемого буфера, испытание, изделие, каталоги, предыстория, условия старта и останова | Общий цикл просмотра и записи всего проекта; не изменяет электрический режим отдельного входа |
| Источники данных | Состав приборов, сетевые адреса, включение источника, сброс, автопоиск, свойства устройства | Подключение, жизненный цикл и перечень доступных аппаратных каналов |
| Каналы устройств | Диапазон, коммутация, питание, фильтры, аппаратный баланс, режим мВ/Ом/мкстрн | То, какие исходные значения и единицы выдаёт устройство |
| Каналы/теги | Имя, адрес, частота, единицы, диапазон, аппаратная и канальные ГХ, уставки | Представление канала внутри RecorderLnx и данные для всех компонентов/записи |
| Формуляры | Страницы, фон и размещение компонентов | Только представление; не должны менять режим физического прибора |
| Компоненты | Привязка к тегу и оценке, подписи, шрифты, оси, цвета | Способ показа уже сформированных данных тега |
| SQL БД | Подключение, период, управляющий тег, перечень оценок | Параллельную долговременную запись и исторические SQL-тренды |

Главное правило: сначала настраивается источник и его физический канал, затем
тег и цепочка ГХ, после этого - компонент отображения и запись. Изменение
компонента не должно перепрограммировать прибор; изменение аппаратного режима,
наоборот, может изменить доступный диапазон и автоматические единицы тега.

## 3. Путь измерительных данных

```text
Прибор или программный источник
  -> аппаратный канал и аппаратная ГХ
  -> тег RecorderLnx
  -> канальная ГХ1 -> ... -> канальная ГХn
  -> оценки (текущее, Mean, RMS, Max и др.)
  -> формуляр / осциллограмма / тренд / файл записи / SQL БД
```

Если у тега включены автоматические единицы, они берутся с конечного узла этой
цепочки. Если аппаратная ГХ включена одна, тег получает единицы, выбранные в
устройстве. При ручных единицах RecorderLnx показывает введённую пользователем
строку и не заменяет её при переключении ГХ.

## 4. Быстрый старт

1. Запустите RecorderLnx и проверьте в заголовке каталог проекта.
2. Откройте **Настройка -> Аппаратные свойства** и проверьте состав источников.
3. Для сетевого прибора проверьте IP, порт и связь; при необходимости выполните автопоиск.
4. Откройте свойства каналов прибора и задайте электрический режим, диапазон и коммутацию.
5. Откройте настройку тегов и проверьте адрес, частоту, единицы и ГХ.
6. Перейдите в **Preview**. Проверьте значения, единицы, диапазоны графиков и отсутствие аппаратных ошибок.
7. При необходимости настройте формуляры и SQL-запись.
8. Перейдите в **Record**. Перед отключением прибора или изменением аппаратных свойств вернитесь в **Stop**.

Основные состояния: **Stop** - сбор остановлен; **Preview** - данные отображаются
без основной записи; **Record** - выполняется запись. Жёлтый фон состояния
соответствует просмотру/подготовке, зелёный - записи, серый - останову.

## 5. Интерфейс пользователя

### Общая логика работы

Главное окно делится на три рабочие области: страницы отображения, панель
состояния/команд и журнал. Страницы не управляют прибором напрямую: они только
показывают уже подготовленные теги и их оценки. Команды **Preview**, **Record**
и **Stop** управляют жизненным циклом сбора, а настройки источников и тегов
задают, какие данные вообще доступны для отображения.

В таблицах ниже колонка **Характерные действия** описывает только действия,
которые важны именно для этого элемента RecorderLnx: например обратный zoom
мышью у графика, двойной щелчок по компоненту, drag-and-drop или опасное
удаление. Обычные системные переходы между полями клавишами не перечисляются.

Номера на снимках нанесены только в копию изображения и не изменяют интерфейс
программы.

## 6. Настройка RecorderLnx

Окно **Настройка** открывается кнопкой с инструментом на главной панели. Оно
является верхней точкой настройки проекта и разделено на вкладки:

- **Рекордер** - общие параметры просмотра, записи, каталогов и автоматики;
- **Аппаратные свойства** - дерево источников данных и приборов;
- **Каналы** - точка перехода к настройкам тегов проекта;
- **Плагины** - расширения источников и обработки, когда они зарегистрированы.

Параметры вкладки **Рекордер** применяются ко всему проекту. Электрические
режимы отдельных каналов находятся в свойствах приборов, а единицы и ГХ - в
настройке тегов. Это разделение предотвращает случайное перепрограммирование
оборудования при изменении отображения.

### Автоматическое подключение к Coordinator/rcPanel

RecorderLnx и Coordinator/rcPanel могут найти друг друга автоматически, если
они запущены на разных компьютерах одного broadcast-домена. Обнаружение выполняется
через UDP Broadcast, после чего регистрация RecorderLnx, передача состояния и
команд продолжаются через штатный HTTP API Coordinator. Через broadcast не
передаются команды управления, токены доступа и пути к файлам измерений.

Типовой сценарий:

- Запустите Coordinator/rcPanel и включите его HTTP-сервис.
- Запустите RecorderLnx на одном или нескольких компьютерах той же локальной
  сети.
- Дождитесь появления RecorderLnx в списке хостов rcPanel. Опрос выполняется
  периодически, поэтому появление может занять несколько секунд. Дополнительный
  ручной ввод адреса при разрешённом broadcast не требуется.
- Перед групповым запуском проверьте состояние и имя каждого найденного хоста.

Если в RecorderLnx уже сохранён адрес Coordinator, сначала проверяется именно
он. Рабочий ручной адрес не заменяется результатом автопоиска. Переход на
найденный адрес происходит только тогда, когда настроенный HTTP endpoint не
отвечает. Это позволяет сохранить предсказуемое подключение в сети с несколькими
экземплярами rcPanel.

| Назначение | Протокол и порт | Где разрешить входящее подключение |
|---|---|---|
| Поиск Coordinator/rcPanel | UDP `38765` | На компьютере с rcPanel |
| Поиск RecorderLnx | UDP `38766` | На каждом компьютере с RecorderLnx |
| Дальнейшее управление | TCP `8765` либо порт из настройки rcPanel | На компьютере с rcPanel |

Установщик RecorderLnx для Windows создаёт правило для UDP `38766` в профилях
**Частная** и **Доменная** сеть. Для вручную установленного rcPanel разрешите
приложение `RecorderCoordinator.exe` в Windows Firewall либо создайте входящее
правило для UDP `38765`. В Linux разрешите те же UDP-порты и настроенный TCP-порт
в используемом системном брандмауэре. Профиль Windows **Общедоступная сеть**
установщиком не открывается. HTTP-сервис rcPanel должен слушать сетевой интерфейс,
доступный другим компьютерам; для всех интерфейсов обычно задают адрес `0.0.0.0`.

Broadcast обычно не проходит через маршрутизаторы, VPN и изолированные VLAN.
Если программы находятся в разных подсетях, задайте адрес Coordinator вручную
либо настройте сетевую инфраструктуру для прохождения discovery-трафика.

## 10. Формуляры, мнемосхемы и компоненты

Формуляр - это пользовательская страница отображения. Он не является источником
данных и не программирует прибор: формуляр только размещает компоненты, которые
читают уже существующие теги, оценки и исторические данные. Поэтому порядок
работы такой: сначала настроить источник и теги, затем открыть Preview и
проверить значения, после этого раскладывать компоненты по мнемосхемам.

Пользовательские страницы можно создавать, удалять, переименовывать и
отцеплять в отдельное окно. Отцепленное окно удобно для второго монитора:
положение, размер и состояние окна сохраняются в GUI-конфигурации проекта.
Если страница удалена, её компоненты удаляются из GUI-конфигурации, но сами
теги и измерительные данные не удаляются.

### 10.1. Работа с мнемосхемой

Мнемосхема редактируется в режиме конструктора. В этом режиме доступен тулбар
с типами компонентов; выбранный тип кладётся на рабочее поле, затем его можно
переместить, изменить размер и открыть настройки. Фон страницы задаётся
отдельно: можно выбрать картинку, режим растяжения/обрезки/сохранения
пропорций и цвет фона. Фон помогает привязать индикаторы к реальному объекту,
но не участвует в расчётах.

| Действие | Что делает | Важно помнить |
|---|---|---|
| Создать страницу | Добавляет новую пользовательскую мнемосхему в проект | Страница сохраняется в GUI-конфигурации, а не в файле измерений |
| Переименовать страницу | Меняет подпись вкладки/окна | Привязки тегов внутри компонентов не меняются |
| Удалить страницу | Удаляет компоненты этой страницы | Теги проекта и записанные данные остаются |
| Отцепить страницу | Открывает мнемосхему в отдельном окне | Удобно для второго монитора; положение окна сохраняется |
| Выбрать фон | Назначает картинку или цвет мнемосхемы | Для схем объекта обычно включают сохранение пропорций |
| Переместить компонент | Меняет положение на странице | Это только визуальная настройка, прибор не перепрограммируется |
| Изменить размер | Меняет область отображения компонента | Для графиков размер влияет на читаемость осей и легенды |
| Открыть свойства | Открывает настройку выбранного компонента | В свойствах выбираются тег, оценка, цвета, оси и подписи |

### 10.2. Типы компонентов тулбара

Компоненты выбираются с тулбара редактора мнемосхемы. Иконки берутся из общего

| Тип компонента | Что показывает или делает | Характерные действия |

## 12. Графики

Графические компоненты используют теги и их оценки, но предназначены для
разных задач. Осциллограмма показывает форму быстрого сигнала, оперативный
тренд - изменение текущих оценок во время сеанса, SQL-тренд - исторические
точки из базы. Поэтому одинаковый жест может иметь разные ограничения по X.

### 12.1. Общие обозначения и действия графиков

| Элемент/действие | Назначение | Описание как работает |
|---|---|---|
| Заголовок линии | Идентификация сигнала | Показывает имя тега, выбранную оценку и вспомогательные значения компонента. Цвет соответствует линии/легенде. |
| Ось Y | Масштаб величины | Каждая линия назначается оси. Несколько линий можно объединять только при совместимых величинах и единицах. |
| `dY` | Текущий размах | Показывает `Ymax - Ymin` выбранной оси, то есть видимый размах, а не амплитуду конкретного сигнала. Меняется при zoom/антизуме. |
| Протаскивание вправо и вниз | Прямой zoom | Рамка определяет новый видимый диапазон X и Y. Жест внутри области построения масштабирует обе оси. |
| Протаскивание в обратном направлении | Антизум | Расширяет текущий диапазон относительно рамки. Компонент ограничивает результат доступными данными/полной шкалой. |
| Жест ниже оси X | Только X | Zoom или антизум изменяет временную ось, сохраняя ручной масштаб Y. |
| Жест слева от оси Y | Только Y | Zoom или антизум изменяет выбранную ось Y, не сдвигая временной интервал. |

### 12.2. Осциллограмма

![Осциллограмма с измерительным сигналом](screens/user-annotated/user-oscillogram.png)

Осциллограмма предназначена для векторного тега и показывает последовательность
отсчётов текущего блока. Она нужна для оценки формы сигнала, выбросов, смещения
и быстрого процесса, а не для долговременной истории.

| Действие пользователя | Результат | Ограничения и взаимосвязи |
|---|---|---|
| Выбор основного тега в настройке | Назначает временную сетку и основной сигнал осциллограммы | Частота и размер блока берутся из тега/источника; смена Fs меняет шкалу X |
| Добавление линий | Накладывает связанные сигналы на тот же временной интервал | Линии должны иметь согласованное время; ось/единицы задаются настройкой компонента |
| Двойной щелчок по графику | Нормализует вид: полный доступный X и данные по Y с запасом 20% | Это единственное действие двойного щелчка; предустановленный максимальный Y через секунду не восстанавливается |
| Прямой zoom рамкой | Увеличивает выбранный фрагмент сигнала | По X нельзя выйти за полный диапазон текущего блока |
| Обратный zoom | Возвращает более широкий диапазон | X ограничивается началом и концом доступной осциллограммы, пустые области не добавляются |
| Переход Stop -> Preview/Record | Начинает новый сеанс отображения | Старые линии и индексы очищаются, чтобы точки предыдущего запуска не соединялись с новым блоком |

### 12.3. Оперативный тренд

![Оперативный тренд](screens/user-annotated/user-live-trend.png)

Оперативный тренд строится по текущим оценкам тегов во время Preview или Record.
Например, вместо всех высокочастотных отсчётов он может показывать Mean, RMS или
Max с периодом обновления данных.

| Действие пользователя | Результат | Ограничения и взаимосвязи |
|---|---|---|
| Выбор тега и оценки | Создаёт линию текущей оценки | Доступные оценки определяются типом тега и его настройками расчёта |
| Выбор оси Y | Делает ось активной для zoom и `dY` | Линия должна быть назначена этой оси в настройке тренда |
| Zoom/антизум рамкой | Меняет видимый интервал и масштаб выбранной оси | Жест ниже X или слева Y ограничивает действие одной осью |
| Многократный Preview/Record | Каждый запуск рисуется с начала | При `StopToView` и `StopToRecord` точки, линии и текущие индексы очищаются |
| Автопрокрутка | Сдвигает X вслед за новыми точками | Ручной масштаб Y пользователя не должен сбрасываться при добавлении точки |

### 12.4. SQL-тренд

![SQL-тренд с историческими линиями](screens/user-annotated/user-sql-trend.png)

SQL-тренд читает сохранённые оценки из БД и не зависит от наличия текущего
высокочастотного блока. Его линии, отображения и оси задаются в форме
**SQL-тренд: исторические данные**.

| Действие пользователя | Результат | Ограничения и взаимосвязи |
|---|---|---|
| Выбор линии в легенде | Выбирает линию и автоматически активирует назначенную ей ось Y | Последующие Y-zoom и `dY` относятся к этой оси |
| Двойной щелчок по сигналу легенды | Выставляет Y выбранной оси так, чтобы данные линии целиком поместились | Масштабируются данные текущего временного окна, X не меняется |
| Прямой zoom рамкой | Сужает исторический диапазон | Внутри поля меняются X/Y; ниже X - только время; слева Y - только выбранная ось |
| Обратный zoom | Расширяет диапазон | Правая граница X не может перейти за текущую дату/время; левая ограничена доступной историей |
| Флажок **Текущая дата** | Делает правую границу равной текущему времени | Тренд дочитывает БД с периодом SQL-записи и продвигает только X |
| Поступление новой SQL-точки | Добавляет точку и сдвигает временное окно | Пользовательский Y не сбрасывается; число точек ограничено настройкой компонента |
| **Весь диапазон** | Показывает интервал от первой до последней доступной записи | Может загрузить большой период, но количество отрисовываемых точек ограничивается `Макс. точек на линию` |
| **Удалить интервал в БД** | Удаляет точки выбранного времени | Операция необратима и относится к данным БД, а не только к линии компонента |

### 12.5. Спектр

![Спектральный компонент](screens/user-annotated/user-spectrum.png)

Спектральный компонент рассчитывает частотное представление выбранных векторных
тегов. Диапазон X означает частоту, а Y - амплитуду выбранного результата.

| Действие/настройка | Результат | Ограничения и взаимосвязи |
|---|---|---|
| Выбор тегов | Добавляет сигналы в спектральный расчёт | Fs и длина входного блока определяют доступный частотный диапазон и разрешение |
| Диапазон X/Y | Ограничивает видимую область спектра | Логарифмическая шкала требует положительных значений соответствующей оси |
| Тип результата | Выбирает амплитуду, мощность или поддерживаемую спектральную оценку | Меняет физический смысл и единицы Y |
| Тахоканал | Связывает спектр с частотой вращения для порядкового анализа | Требует корректного тега оборотов/импульсов |
| Тревоги, предупреждения, профиль | Накладывает контрольные границы и эталон | Эти данные не изменяют измеренный спектр, а только помогают оценить состояние |

## 13. Диагностика и типовые ошибки

| Сообщение/симптом | Причина | Действие |
|---|---|---|
| `Can not load ... libfbclient` | Нет клиентской библиотеки Firebird | Установить комплект Firebird RecorderLnx либо добавить каталог библиотеки в путь запуска |
| `user name and password are not defined` | Не переданы учётные данные Firebird | Проверить пользователя/пароль в конфигурации SQL RecorderLnx |
| `Database schema ... is newer` | Программа старее схемы БД | Использовать сборку с поддержкой этой версии схемы; не понижать БД вручную |
| Нет устройства | Прибор отключён или недоступен по сети | Проверить питание, IP/порт, сеть и выполнить проверку связи |
| RecorderLnx не появился в rcPanel автоматически | UDP Broadcast заблокирован брандмауэром, компьютеры находятся в разных подсетях либо HTTP-сервис rcPanel остановлен | Проверить, что сервис rcPanel запущен; разрешить UDP `38765` на rcPanel, UDP `38766` на RecorderLnx и TCP-порт HTTP API; для разных подсетей задать адрес вручную |
| RecorderLnx продолжает подключаться по старому адресу rcPanel | Сохранённый ручной HTTP endpoint доступен и имеет приоритет над автопоиском | Оставить адрес как есть либо изменить сохранённую настройку Coordinator; автопоиск заменяет её только после ошибки связи |
| Неверные единицы | Ручной режим либо неверная конечная ГХ | Проверить `Авто`, аппаратную и канальные ГХ |
| График пуст | Нет данных, линия скрыта или неверная ось | Проверить состояние Preview/Record, тег, видимость и диапазон оси |

## 14. Автоматическое обновление снимков

Режим предназначен для разработчика документации и не включается при обычном запуске:

```text
RecorderLnx.exe --capture-user-guide "--guide-output=D:\works\OburecGH\Lazarus\RecorderLnx\Docs\Руководство пользователя\screens"
```

RecorderLnx последовательно создаёт пользовательские формы, наносит номера активных элементов только на PNG, сохраняет `*.elements.md` с картой элементов и завершает работу. Общий результат находится в [индексе снимков](screens/index.md).

Для снимков, сделанных оператором вручную, используется отдельный безопасный процесс:

1. Положить заполненные оригиналы в `screens/юзер`; эти файлы считаются исходниками и не редактируются.
2. Запустить `Tools/annotate_manual_user_screens.py` из корня проекта.
3. Получить подписанные копии и карты элементов в `screens/user-annotated`.
4. Проверить `source-sha256.txt`: скрипт сравнивает SHA-256 до и после обработки и останавливается, если изменился хотя бы один оригинал.
5. В Markdown и Word включать PNG из `user-annotated`, а назначение номеров брать из одноимённых `*.elements.md`.

При добавлении новой формы сначала дополните словарь `SCREENS` в скрипте: задайте имя исходника, имя копии, координаты маркеров, назначение, взаимосвязи и клавиши. Нумерация изображения и таблицы является единым контрактом и должна проверяться вместе.

## 15. Сохранность данных

Перед изменением проекта сохраните резервную копию каталога конфигурации. Не удаляйте интервалы SQL БД без резервной копии: эта операция изменяет исторические данные. После изменения устройства или ГХ обязательно проверьте единицы и диапазоны в Preview до запуска записи.
