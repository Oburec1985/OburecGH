# АКА: приведение к частоте дискретизации отклика

## Ручная порция для установившегося воздействия

По уточнению пользователя кнопка «Снять порцию» снимает уже накопленные
данные всех кольцевых буферов, объединяя их блоки в хронологическом порядке.
Это не ожидание будущих отсчётов. Показывается фактически доступная история,
даже если она короче настроенной порции. Старые замеры и глобальные кольца
источников не изменяются. Сохранение относится к этому новому снимку, а не
предыдущей runtime-реализации.

Один полный секундный буфер при Fs содержит Fs отсчётов, не Fs+1:
длительность дискретной порции N/Fs, последний отсчёт расположен в (N−1)/Fs.
Нельзя объявлять такую порцию неполной из-за отсутствия точки ровно в 1с.
Настройки окон автоматически не меняются.

Основной путь использует явное преобразование времени устройства в общие
монотонные секунды Recorder и обратно (`uRecorderBlockClock`). Привязка
создаётся для каждого запуска устройства; паузы ЦАП между запусками не
склеиваются в непрерывный счётчик. Метаданные блока фиксируются при выдаче,
не при отложенной доставке зеркала. MX-248 сохраняет шаг приборных отсчётов,
а задержка прихода блока не меняет его временную привязку.

Host-привязка не означает аппаратной фазовой синхронизации: задержка
аудиовывода и аппаратного запуска оценивается, но драйвер не предоставляет
общий тактовый генератор/точный момент выхода каждого отсчёта.

По явному разрешению пользователя при невозможности совместить интервалы
или при разрывах используются последние блоки каждого входа, зафиксированные
на нажатии. Только временные копии для DSP обнуляются независимо. Исходные
метки сохранены, статус и SessionId отмечают отсутствие синхронизации фазы;
это предупреждение восстанавливается при чтении сохранённого шага.
Относительное начало осциллограмм не изменяет данные источников.

Старый API TryCapturePortion для будущего post-click захвата сохранён отдельно
для совместимости и тестов; UI вызывает TryCaptureRingPortion. Триггерный
режим сохраняет собственную логику захвата.

## Частоты и обработка

Шаг сохраняется только в `<каталог шага>/frf/session.mera` и бинарные R8
`.dat/.x`. Дополнительный `curve.frf` больше не записывается и не читается;
просмотр загружает временные реализации и характеристики из MERA, не заменяя
несохранённые удары в оперативной памяти. Старые MERA в папке `aka` доступны
для чтения, новые сохранения используют `frf` (JSON fallback отсутствует).
Имена каналов: `<имя тега>_<номер с 1>_<тип>`; `exc` — воздействие,
`time` — временной отклик, `frf`, `ph`, `coh`, `spm` — характеристики;
`exc_spm` — спектр воздействия. Технические метаданные сохраняют исходные
имена тегов и идентификаторы отдельно от безопасных файловых имён.

Для каждой пары воздействия и отклика расчёт выполняется на Fs отклика,
не на меньшей Fs и не обязательно на общей Fs всех откликов. Метаданные
частоты канала имеют приоритет. При их отсутствии Fs можно определить только
из равномерных временных отметок; средняя по серии с пропусками не означает
новую частоту. Для нерегулярных старых записей остаётся настроенная Fs.

Длительность захвата и окон задаётся в секундах и не изменяется. Число
расчётных отсчётов, FFT и Welch согласуются с Fs соответствующего отклика;
каждая кривая сохраняет собственную частотную ось. Глобальная SampleRateHz
снимка остаётся совместимым параметром захвата, а не заменой per-curve оси.

Пересчёт использует исходные timestamps, общий StartSeconds и центрированный
windowed-sinc без групповой задержки. При понижении Fs применяется low-pass;
при повышении Fs интерполируется доступная полоса воздействия. Срез 0.45 от
меньшей Fs оставляет переходную полосу до Найквиста. Частоты выше Найквиста
исходного воздействия физически не восстанавливаются. На границах захвата
ядро обрезается и нормируется; экстраполяции за записанные данные нет.
При совпадающих Fs (с учётом малого clock jitter) сохраняется прежняя линейная
интерполяция по времени.

Исходные временные реализации не изменяются. Ёмкость raw-банков заранее
считается по максимальной Fs входных тегов, чтобы более быстрый канал не
прореживался до расчёта. Фильтрация/FFT выполняются после захвата рабочим
потоком, не обработчиком отдельного поступившего отсчёта. Все пути повторного
расчёта используют ту же подготовку пар.

Проверки: ImpactHammerTest — phase/gain, down/up/fractional resampling,
alias rejection и отсутствие экстраполяции; ImpactHammerServiceTest
--response-fs-only — воздействие64/отклики32+128, перестановка, одинаковые Fs,
native timestamps/counts, повторное окно; --route-point-only — сохранённые
шаги и RAM. Пересчёт1с57.6→14.4кГц: 31–47мс на тестовой Windows-машине.
