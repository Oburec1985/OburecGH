# Правила разработки RecorderLnx

## Формы LFM и короткие имена

- Каждые `TForm` и `TFrame` оформлять отдельным соседним `.lfm` с тем же базовым
  именем и `{$R *.lfm}`. Статическую иерархию, размеры, привязки, подписи и
  события задавать в `.lfm`, чтобы форма открывалась и правилась в Lazarus Designer.
- Не создавать рабочие формы через `CreateNew`/`BuildUi`; в Pascal оставлять поведение, состояние
  и динамические данные.
- При изменении структуры LFM обновлять проверки формы в smoke-тестах; GUI
  test runner обязан ловить ошибки на верхнем уровне и завершаться ненулевым
  кодом без модального окна. Запускать такие тесты с ограничением времени и
  проверять отсутствие оставшихся процессов. История:
  `errors/2026-10-06-impact-model-test-popup.md`.
- В новых и изменяемых именах использовать короткие однозначные сокращения:
  `Recorder -> Rc`, `Frequency -> Freq`, `Response -> Resp`, `Dialog -> Dlg`, `Buffer -> Buf`.
  Не сокращать имя до непонятной одной буквы; для коротких локальных циклов однобуквенные
  индексы допустимы.

## Единый набор иконок

- Все иконки RecorderLnx добавлять в единый `TImageList` `ilCommandButtons`,
  хранящийся в `UI/uMainForm.lfm` и доступный для просмотра в Lazarus Designer.
  Не создавать отдельные наборы иконок для новых форм или компонентов.
- Каждой иконке назначать именованную константу индекса в
  `Components/Editor/uRcIconIds.pas`. В коде не использовать числовые `ImageIndex` без имени.
- Индекс в `uRcIconIds.pas` обязан совпадать с позицией иконки в
  `ilCommandButtons`; после добавления, удаления или перестановки иконок проверять оба места.
- Runtime-код не загружает `.ico`/`.bmp`, не дорисовывает и не дополняет
  `ilCommandButtons`. При старте разрешена только проверка числа встроенных
  изображений. Подготовка новых пиктограмм выполняется отдельным инструментом,
  после чего результат сохраняется непосредственно в `uMainForm.lfm`.
- Диалоги и компоненты получают ссылку на общий `ilCommandButtons`; локальные
  `TImageList`, копирование списков и локальные числовые таблицы индексов запрещены.

## Единицы и цепочка ГХ

- Чувствительность датчика имеет размерность `вход/физическая величина` и
  задаёт делитель: `physical = input / sensitivity`. Хранимый `Scale` — это
  обратный множитель `выход/вход`, применяемый как `output = input * Scale`.
  В интерфейсе эти две величины нельзя называть одинаково или менять местами.
- Исходная единица канала хранится отдельно от автоматической выходной единицы
  тега. Перед свёрткой pipeline в итоговый коэффициент `RebuildScales` один раз
  добавляет переход `SourceUnit -> UnitIn` каждой ступени через
  `RecorderUnitManager`; runtime не обходит pipeline на каждом отсчёте.
- AutoUnit определяется по `UnitOut` последней включённой канальной ГХ; если
  канальной ГХ нет, используется `UnitOut` включённой аппаратной ГХ.
- AutoUnit управляет только выбором единицы результата и никогда не включает
  или не выключает ступени ГХ. В ручном режиме разрешены единицы категории
  `UnitOut` последней включённой ступени, а переход к выбранной единице входит
  в один заранее собранный итоговый коэффициент.
- Обнаружение, загрузка и привязка аппаратной ГХ выполняются независимо от
  флага её применения. Флаг аппаратной ГХ управляет только включением уже
  загруженной ступени в расчёт; снятая галка не должна скрывать файл ГХ от тега.
- Общий флаг канальной ГХ хранится у тега и показывается только во внешнем
  диалоге настройки тега. Редактор pipeline управляет включением отдельных
  ступеней. Определение UnitOut, сквозной чувствительности и итогового масштаба
  пропускает выключенные ступени и целиком игнорирует pipeline при снятом общем
  флаге.
- Соседние звенья цепочки согласуются только через `RecorderUnitManager`.
  Устройство не должно иметь собственную дублирующую логику AutoUnit.
- При изменении единиц, коэффициентов, порядка, состава или флагов ГХ нужно
  инвалидировать собранный коэффициент тега и вызвать `RebuildScales` во время
  reconfigure. При валидном флаге повторная сборка обязана быть no-op; runtime
  использует готовый коэффициент без обхода цепочки.
- Импортированная из БДГХ калибровка хранит связь с источником на самом
  объекте (`SdbKey` и путь файла). Любой редактор работает с черновиком и до
  commit обязан записать связанную запись через единый метод с обратной
  проверкой чтением. Имя ГХ нельзя использовать для повторного поиска файла.
  Только явное создание локальной копии снимает связь с БДГХ.
- Представление ГХ выбирается по сохранённому `Kind`, а не по наличию точек в
  CSV: `scale` и `linear` показываются как формула, табличные типы — таблицей.

Актуальный документ перенесен в тематический раздел:
[architecture/development-rules.md](architecture/development-rules.md).

Этот файл оставлен как стабильная точка входа для инструментов и навыков,
которые ожидают `Docs/development-rules.md`.
## SQL БД: единый источник конфигурации и сетевое создание

- Все потребители SQL БД активного проекта обязаны читать один `sql-db.ini`
  рядом с GUI-конфигурацией проекта; сохранённые абсолютные ссылки на другой
  SQL-конфиг не использовать.
- Для Firebird одни и те же централизованные реквизиты применяются к `Open` и
  `CreateDB`. Удалённую БД создавать только после явной ошибки сервера об
  отсутствии файла; ошибки сети и авторизации не трактовать как отсутствие БД.
- Проверка: открыть существующую сетевую БД и отдельно создать отсутствующую;
  в диагностике обоих сценариев должны совпадать host, port, database и user.
# Дочерние процессы с перенаправленным выводом

Если `TProcess` запущен с `poUsePipes` и команда способна вывести больше
буфера канала (например, `apt-get`), читать `Output`/`Stderr` нужно во время
работы процесса. Нельзя сначала вызывать `WaitOnExit`, а потом читать вывод:
дочерний процесс может навсегда остановиться на заполненном pipe. Проверка —
запуск команды с объёмным выводом завершается, GUI продолжает обрабатывать
события, а полный вывод доступен после завершения.

## Пользовательский viewport и фоновые обновления

- После явного изменения X-viewport пользователем — рамочного zoom, pan,
  кнопки сброса масштаба или двойного щелчка — фоновая догрузка данных не
  изменяет видимый диапазон.
- Auto-follow включать только при первичной настройке/перезагрузке компонента
  или отдельной явной команде.
- Проверка: выбранный диапазон остаётся неизменным минимум после двух циклов
  live reload. История:
  `errors/2026-09-22-sql-trend-live-reload-resets-zoom.md`.
- В OGLChart рамочный zoom внутри поля графика требует Ctrl. Если drag начат
  в полосе оси, Ctrl не нужен: полоса X изменяет только X, полоса Y — только Y;
  обратное направление drag использует тот же осевой zoom-out.
- При обратном zoom ограничивать X сохранённым Preset только когда у страницы
  установлен `HasPresetXRange`; иначе отдалять от текущего диапазона. Проверять
  на странице без Preset после предварительного zoom-in: X не должен сбрасываться
  к исходным 0…1. История: `errors/2026-10-06-impact-chart-viewport-and-stipple.md`.
- Декоративный пунктир курсора или порога задавать через `GL_LINE_STIPPLE` в
  экранных пикселях, а не серией отрезков в координатах данных. Проверять
  одинаковую длину штриха при двух масштабах и сохранение OpenGL line-state.
- При фоновом пересчёте ударного FRF не блокировать навигацию по уже сохранённым
  ударам и не отдавать пустой снимок: временные буферы выбранного удара должны
  оставаться доступными в RAM. Проверять переход между двумя ударами с разными
  массивами во время пересчёта фильтра.
- Если UI-команда меняет выбранный снимок или график без нового блока данных,
  обновлять вид непосредственно после команды, не ожидая общего data-dirty
  repaint. Проверять кнопками после остановки потока: подпись и линии должны
  переключаться в том же обработчике. История:
  `errors/2026-10-06-impact-navigation-during-filter.md`.
- Команда возврата вида компонента восстанавливает его сохранённые Preset
  диапазоны. Автоподбор по текущим данным допустим только для компонентов,
  которые явно включили `AutoScaleOnZoomReset`. Флаг автоматического масштаба
  при обычном обновлении не должен подменять сохранённый Y max при явном
  двойном щелчке. Проверять X и Y отдельно: после искусственного zoom
  оба предела должны вернуться к значениям настройки.
- Если XY-компонент синхронизирует два сигнала интерполяцией одного сигнала в
  timestamps другого, выходной буфер выделять по числу отсчётов опорного
  сигнала, а не по минимуму двух входных размеров. Проверка обязана включать
  разные частоты X/Y и подтверждать отсутствие выхода за границы буфера.
- Компонент со специальной семантикой двойного щелчка (например, Лиссажу)
  выполняет fit по собственным данным и не использует общий reset всего chart.
- При переносе инженерного геометрического показателя из старого Recorder
  сохранять его математическое определение. Для главного диаметра Лиссажу это
  максимальная хорда выпуклой оболочки, а PCA является отдельной быстрой
  оценкой главного направления и не должен молча подменять диаметр.

## Сетевой preflight SQL и состояние интерфейса

- Отрицательный TCP-preflight SQL-сервера всегда передавать из фонового
  загрузчика в интерфейс как явное состояние недоступности. Нельзя подавлять
  доставку результата и оставлять на экране устаревшие данные без пояснения.
- Ошибки авторизации, конфигурации, схемы и SQL-запроса не называть
  недоступностью сервера: для них сохранять исходную диагностику.
- После восстановления связи очередная фоновая загрузка должна автоматически
  убрать сообщение и показать актуальные данные.
- Проверка: закрытый SQL-порт показывает сообщение о недоступном сервере;
  повторное открытие порта восстанавливает тренд без перезапуска программы.

## Зависимая 3D-геометрия при интерактивном transform

- Если transform callback изменяет helper/bone, все зависимые геометрические
  evaluators применяются в том же callback до перерисовки. Нельзя откладывать
  Skin только до `OK`, `Configure` или следующего tag refresh.
- В drag-path использовать уже подготовленные ссылки и bind matrices; не
  выполнять повторный configure, поиск тегов или смену bind pose на каждом
  `MouseMove`.
- Плоские render-corners не являются пользовательскими вершинами. Генератор
  обязан хранить `LogicalVertices`, объединяющие совпадающие углы граней, а
  Skin/editor работают только со stable logical ID.
- Проверка: два последовательных движения helper меняют все corner-копии одной
  logical vertex без reconfigure и drift; возврат к bind pose точно возвращает
  исходную геометрию. История:
  `errors/2026-10-05-3d-skin-live-move-and-lighting.md`.

## Экранные подписи и handles поверх OpenGL

- Не использовать графические дочерние LCL-контролы (`TLabel` и аналоги) как
  overlay внутри `TOpenGLControl`: `SwapBuffers` может стереть их независимо от
  порядка LCL paint-сообщений. Экранный overlay рисовать на поверхности viewport
  после представления OpenGL-кадра либо внутри последнего OpenGL overlay-pass.
- Данные подписи кэшировать при изменении значения/геометрии; в Paint выполнять
  только проекцию и вывод. Размер шрифта задавать в экранных единицах.
- Круговой rotation handle вычисляет угол через разность `atan2`, а drag вне
  handle обязан явно сбрасывать осевое ограничение в свободное вращение.
- Проверка: подпись не исчезает после повторных repaint; полный обход кольца не
  меняет знак рывками; drag фона после выбора X/Y/Z остаётся свободным.
- История: `errors/2026-10-06-3d-value-label-overlay-and-camera-rotate.md`.
### Узловые и камерные преобразования 3D

- Runtime-положение камеры и узлов хранить как матрицу/ортонормированный pose;
  Euler допустим только как формат совместимости, но не в цикле drag/update.
- Любое преобразование относительно другого узла выполнять через общий
  `u3dTransforms`: world→frame, операция в frame, frame→world.
- При смене мишени орбитальной камеры сохранять мировую позицию камеры.
- Не добавлять частное умножение 4×4: использовать `ComposeMatrices` с
  AVX/SSE2/scalar runtime-dispatch и эталонными тестами.

## Снимки компонентов для Undo и Copy/Paste

- Любой настраиваемый визуальный компонент обязан иметь глубокий контракт
  копирования всего принадлежащего ему состояния. Одного копирования базовых
  `Id`, `Name`, тега и `Bounds` недостаточно.
- При добавлении нового типа компонента его глубокое копирование нужно сразу
  подключить к `TFormEditorController.CopyComponentState`: этот путь общий для
  Undo и Copy/Paste.
- Вложенные коллекции, матрицы, привязки и модели нельзя разделять между
  исходным компонентом и снимком по ссылке.
- Минимальная регрессия: удалить настроенный компонент, выполнить Ctrl+Z и
  проверить восстановление всех настроек; затем отдельно проверить Copy/Paste.
- История: `errors/2026-07-13-preview-offline-and-form-editor-lag.md`.
# Windows BAT и встроенный PowerShell

В BAT-файле не экранировать `|` как `^|` внутри уже заключённого в двойные
кавычки аргумента `powershell.exe -Command`; иначе caret может попасть в текст
PowerShell и дать runtime syntax error. Перед передачей проверять извлечённые
PowerShell-команды через `System.Management.Automation.Language.Parser` и
оставлять диагностический лог рядом со standalone BAT.
