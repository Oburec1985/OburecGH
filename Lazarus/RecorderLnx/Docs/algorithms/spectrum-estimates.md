# Спектральные оценки и выходные теги

Алгоритмические юниты спектров вынесены в `Algs`:

- `uRecorderSpectrumEngine.pas` — настройки, FFT-планы, окна, интегрирование и расчёт кадра;
- `uRecorderFrequencyBands.pas` — модель абсолютных и формульных частотных полос.

`Algs/uRecorderSpectrumRuntime.pas` находится рядом с менеджером и спектральным движком: это runtime-часть алгоритма, включая очередь входов, расчёт оценок и публикацию результата. Универсальные реестр тегов и EventBus остаются в `Core`.

## Настройка

На вкладке «Каналы» у спектрального алгоритма доступны флаги:

- «СКЗ в полосах»;
- «Максимум в полосах»;
- «Частота максимума»;
- «Создать теги».

Если выбран дочерний канал алгоритма, изменения сохраняются в его `TRecorderSpectrumTagBinding` с `UseOwnSettings=True`. Если выбран родительский узел спектра, настройки остаются общими для всех наследующих каналов.

Флаги хранятся в строке `TRecorderSpectrumSettings.AsString`, поэтому старые конфигурации совместимы: отсутствующие поля получают значение `False`.

## Семантика расчёта

Для каждой настроенной частотной полосы рассчитываются только включённые оценки:

- `RMS = sqrt(sum(A[i]^2))` по спектральным отсчётам полосы;
- `Max` — максимальная амплитуда в полосе;
- `FMax` — частота спектрального отсчёта с максимальной амплитудой.

Если включено однократное или двукратное интегрирование, оценки вычисляются по итоговому интегрированному спектру, а не по исходному спектру ускорения.

При включённом флаге записи runtime заранее, во время `PrepareConfiguration`, создаёт теги:

`<OutputPrefix>_<BandName>_rms`, `<OutputPrefix>_<BandName>_max`, `<OutputPrefix>_<BandName>_f1`.

В потоковом обработчике новые теги не создаются. Значения публикуются с временем конца спектрального кадра. Суффикс `f1` обозначает частоту максимума, единица — `Hz`; единицы амплитудных оценок наследуются по смыслу от итогового спектра. Старые автоматически созданные теги с суффиксом `fmax` при подготовке конфигурации переименовываются в `f1` с сохранением `TagId`.

## Правила дальнейшей доработки

1. Математические алгоритмы без зависимостей от UI и реестра размещать в `Algs`.
2. Создавать производные теги и выделять долговременную память при загрузке или переконфигурировании, не на Start/Stop и не в обработчике кадра.
3. Новые поля `TRecorderSpectrumSettings` обязательно добавлять одновременно в `SetDefaults`, `AsString`, `FromString`, UI и тест обратной совместимости.
4. Для каждой публикуемой оценки проверять тестом и само вычисленное значение, и появление значения в выходном теге.
5. Кнопки «Применить» и OK сначала обязаны сохранить редактируемые поля выбранного узла в модель, затем вызвать `PrepareConfiguration` и только после этого обновлять таблицы тегов. Иначе флаг «Создать теги» будет сохранён, но производные теги не появятся до повторной загрузки конфигурации.

## Границы полос и частотная сетка

- В полосу входят только FFT-бины, центральная частота которых находится внутри заданного включительного диапазона `[F1, F2]`.
- Нижний индекс вычисляется как `Ceil(F1 / df)`, верхний — как `Floor(F2 / df)`, где `df = SampleRateHz / FFTSize`. Округлять обе границы к ближайшему бину нельзя: например, при `df=7,03125 Гц` полоса от `10 Гц` должна начинаться с бина `14,0625 Гц`, а не с `7,03125 Гц`.
- Частота дискретизации является свойством конкретного входного тега. Для каждой привязки runtime берёт `PollFrequencyHz` её тега и строит собственную частотную сетку. Поэтому один узел спектра может содержать каналы с разными частотами дискретизации; FFTSize, окно и описание полос остаются общими, но индексы полос вычисляются отдельно для каждого канала.
- СКЗ, максимум и частота максимума используют один и тот же рассчитанный диапазон бинов.

После нажатия внутренней или общей кнопки «Применить» выходные теги создаются немедленно и становятся видны в списке выбранных каналов текущего диалога. Для каждой настроенной полосы создаются только теги включённых оценок.
