# MIC-140 ProtocolDebug UI stand: Recorder ref match

## Symptom
- The standalone `Mic140ProtocolDebug.lpi` UI stand reads MIC-140 packets, but the visible accepted block counter can stay at zero.
- Latest UI log before this note: `read=14`, `readGaps=0`, `corruptRead=0`, `mdpResync=0`, but `published=0` because ADC-code acceptance rejects every block starting around CH25 and TIn is missing/zero.
- This is not a hard MIC-140 hang. The device connected, programmed, started, read blocks, stopped and disconnected normally.

## Acceptance Target
- Keep the debug project usable as a UI stand, not only a CLI runner.
- The UI must show live measured codes and deltas against Recorder reference even when the block fails acceptance, so commutator/protocol hypotheses can be checked without a frozen screen.
- Main RecorderLnx behavior must not be changed while working on this isolated debug stand.
- Isolation (2026-06-30): experimental scan hooks live only in `Tests/Mic140ProtocolDebug/Driver/` shadow units (`uRecorderMic140v2Scan.pas`, `uRecorderMic140v2Device.pas`). Both `Mic140ProtocolDebug*.lpi` put `Driver` before `Device/MIC140v2` in unit search path; main `Device/MIC140v2` no longer exports debug setters.
- Recorder ADC-code rule is textual, not image-only:
  - AIn1..48 and TIn1..3 references are stored in `Data/mic140_adc_reference.txt`.
  - Every published value must match the Recorder reference within +/-20 ADC codes.
  - The current Recorder snapshot includes AIn29=6074, AIn30=13499, TIn1=8844, TIn2=9019.
  - TIn3 remains 18328 until a clearer Recorder value is captured; it is still checked with the same +/-20 tolerance.

## Actions
- Created this debug-project-local journal so repeated MIC-140 UI stand investigations are not mixed with the main RecorderLnx driver journal.
- D1 code action: `uMic140AcquireThread.pas` now notifies the form for every decommutated block before strict acceptance filtering. `Published` remains the strict accepted-block counter; `Read` remains the live block counter.
- D2 code action: `uMic140DebugForm.pas` now parses CLI-style parameters in the GUI executable, and closes automatically after an auto run.
- D2 follow-up: `Mic140ProtocolDebug.lpr` routes `--auto` to the same auto runner and `uMic140AutoRunner.pas` now parses `--range` and `--commut`, so UI and CLI-style runs use the same executable.
- D4 code action: `uMic140DebugReference.pas` defaults now match `Data/mic140_adc_reference.txt`, and all AIn/TIn tolerances are +/-20 codes.
- D11 code action: added `Bank2RangeIndex` and CLI/UI argument `--bank2-range N`; kept default `-1` so normal debug runs use the same range on both banks unless explicitly overridden.
- D13 code action: added `Bank2DelayMul` and CLI/UI argument `--bank2-delay-mul N`; kept default `1`.
- D14 code action: 24-bit ME048 packing is now available only as an explicit diagnostic via environment variable `MIC140_DEBUG_ME048_V2=1`; default debug runs keep the stable old packing.
- D15 code action: added `ChanDumpCount` to the standalone debug config and command-line parser. Use `--chan-dump-count 51` together with `--tin-slots 3` to test the user's `48+3` row hypothesis with `m_ChanDump[2]=51`.
- D23 code action: `Mic140v2ApplyRecorderWireProfile`, CLI `--recorder-wire`, `MIC140_DEBUG_RECORDER_PROFILE=1`, `Mic140v2SetDebugFifoSamples`. Device skips `RefreshAuxFromDm` when `stride>48`.
- D25 code action: default auto profile remains **fifo=48** for stable acceptance; Recorder wire is explicit opt-in.
- D26 (2026-07-01): production scan `tin=0`, 48 BIOS slots, val=60 — стабильный поток (~120 blk/25s). CH01–24 PASS ±50; CH25–48 систематически расходятся с эталоном (не только прогрев). `tin-slots=3` ломает 2-й банк.
