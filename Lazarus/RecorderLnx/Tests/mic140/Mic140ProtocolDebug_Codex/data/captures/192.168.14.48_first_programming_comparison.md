# MIC-140 192.168.14.48: сравнение первого программирования

Сравнены дампы:

- `192.168.14.48_original_recorder_20260723_122408_packets.csv`;
- `192.168.14.48_recorderlnx_test_20260723_121611_packets.csv`.

## Подтверждённые различия

| Стадия | Original Recorder | Старый тестовый EXE |
|---|---|---|
| Проверка готовности | `TEST_LOAD(7)`, 32 нулевых аргумента | отсутствует |
| Аппаратный reset | `RESET(10)` | `RESET(10)` |
| Ожидание BIOS | первый `RESETSCANMAIN` через 59 мс, второй через 4,962 с | единственный `RESETSCANMAIN` через 218 мс после ответа на reset |
| Очистка перед config | `RESETSCANMAIN`, `STOPSCANMAIN` | `STOPSCANMAIN`, `STOPSCANMAIN`, `RESETSCANMAIN` |
| Полное программирование scan | три прохода | один проход |
| Завершение каждого прохода | `CONFIG_MESSAGE(90)`, `CONFIG_SYNC_START(79)`, `SET_TIMEOUTSTARTTIMER(98)`, `START_TRIGGERSTARTADC(85)`, `SET_TIMEOUTSTARTTIMER(98)` | отсутствует |
| Запуск | `STARTSCANMAIN(80)` через 4,189 с после третьего config | `STARTSCANMAIN(80)` через 107 мс после последнего `SETSTATESCAN` |

Первый проход Original Recorder начинается на отметке `5103,414 мс`, второй —
`5318,818 мс`, третий — `5535,417 мс`. `STARTSCANMAIN` отправлен на отметке
`9732,082 мс`.

## Что совпадает

Основные таблицы scan у старого теста были сформированы согласованно:

- таймер: `type=12`, divider `5000`, context `0x0800`;
- FIFO: `0x0522`, ready `110`, capacity `220`;
- измерительные дескрипторы совпадают после учёта режима заземления;
- потоковый payload имеет размер 250 байт и период около 200 мс.

Разница `scan_id=1` у Original Recorder и `scan_id=0` у теста сама по себе не
является ошибкой, если один и тот же id последовательно применяется ко всем
командам и проверяется в заголовках входного потока.

## Вывод

Старый тестовый EXE действительно выполняет меньше операций, чем Original
Recorder. Пользователь проверил вариант из бэкапа `008` после перезагрузки
прибора: первая инициализация на нём также сбоит. После подготовки прибора
Original Recorder последующие запуски теста работают.

Поэтому предположение «тест не завершает первое программирование»
**подтверждено аппаратным поведением**. Таблицы scan и разбор устойчивого потока
в `008` можно сохранить, но его холодный Init нельзя считать эталоном.

Наиболее раннее доказанное расхождение находится до программирования таблиц:
`008` не выполняет `TEST_LOAD` и начинает config примерно через 0,9 секунды,
тогда как Original Recorder очищает командный автомат, выполняет reset scan до
и после пятисекундной готовности BIOS и лишь затем конфигурирует scan.

Три прохода config в дампе оригинала остаются вызовами верхнего уровня
приложения: дублировать весь Config внутри драйвера без отдельного доказательства
нельзя. Однако arm-окончание каждого прохода не является случайным повтором:
оно присутствует во всех трёх проходах и запускает АЦП. В автономный стенд
перенесены `CONFIG_MESSAGE`, `CONFIG_SYNC_START`, оба
`SET_TIMEOUTSTARTTIMER`, `START_TRIGGERSTARTADC` и выдержка 4,2 с перед Play.

Также стенд приведён к точным признакам дампа: `scan_id=1`, два одинаковых
`CONFIGSCANMAIN`, отсутствие лишнего `STOP+RESET` между холодным Init и первым
Config. Аппаратное подтверждение после перезагрузки прибора ещё обязательно;
успешная сборка не считается подтверждением протокола.

## Состояние тестового проекта

Тест намеренно возвращён пользователем на старую реализацию `MIC140v2`, потому
что более новая реализация не обеспечивала устойчивый поток. Поэтому эталоном
для исправления служит именно этот вариант. В рабочем дереве исходный каталог
`Device\MIC140v2` отсутствует, но сохранились его PPU; для воспроизводимой
чистой сборки исходники этой версии надо вернуть из выбранного бэкапа.

Исполняемый файл теста восстановлен побайтно из бэкапа `008` (SHA-256
совпадает). Следующий дамп исправленного теста должен проверить:

1. `TEST_LOAD → REPLY → RESET → REPLY`;
2. два `RESETSCANMAIN` с паузой около 5 секунд и последующий `STOPSCANMAIN`;
3. сохранение таблиц scan из `008`;
4. отсутствие лишнего reset/config после первого потокового блока;
5. поступление не менее 40 последовательных блоков с периодом 200 мс.
