# Эталонные сетевые захваты MIC-140

Здесь хранятся полные сетевые циклы оригинального Recorder и тестового
приложения. Имя файла всегда начинается с IP физического прибора.

Подтверждённый стенд:

- `192.168.14.48:4000`;
- `MIC-140-48v3`;
- аппаратная ревизия `14.1`, BIOS `8.1`;
- серийный номер аппаратной конфигурации `329`.

## Запись оригинального Recorder

Запустить PowerShell:

```powershell
.\Tools\capture_mic140_traffic.ps1 `
  -DeviceIp 192.168.14.48 `
  -Scenario original_recorder `
  -LaunchRecorder
```

Скрипт сам запросит права администратора, включит фильтр и запустит
оригинальный Recorder. В Recorder выполнить полный цикл:

```text
Connect -> Init -> Config -> Play -> несколько секунд данных -> Stop -> Disconnect
```

После Stop закрыть Recorder. Захват остановится автоматически только после
завершения процесса Recorder; нажимать Enter в этом режиме не требуется.
В окне PowerShell раз в секунду выводится `[CAPTURING]` с прошедшим временем,
PID Recorder и состоянием ETL. После закрытия видны стадии `[STOPPING]`,
`[CONVERTING]`, `[PARSING]` и итоговая `[DONE]`.

## Запись тестового приложения

Сначала запустить захват:

```powershell
.\Tools\capture_mic140_traffic.ps1 `
  -DeviceIp 192.168.14.48 `
  -Scenario recorderlnx_test
```

Затем вручную запустить единственный тестовый проект
`Mic140ProtocolDebug_Codex.exe`, выполнить тот же цикл и нажать Enter в окне
захвата.

## Артефакты одного прогона

- `.etl` — исходный системный дамп Windows;
- `.pcapng` — полный переносимый дамп;
- `_packets.csv` — время, направление, endpoints, размер, TCP seq/ack/flags,
  длина и hex TCP payload каждого пакета;
- `_timeline.txt` — компактная последовательность и интервалы;
- `_pktmon.txt` — системная расшифровка pktmon с hex;
- `_README.md` — условия конкретного прогона.

Сравнивать следует два захвата одного прибора и одинакового сценария. Особое
внимание: порядок соединений, паузы между командами, размеры payload,
повторные передачи, содержимое запросов программирования и момент появления
потоковых пакетов.
