# Переносимый захват трафика MIC-185

Папку `Mic185TrafficCapture` можно целиком скопировать на другой Windows-компьютер.
Для захвата нужны только PowerShell от администратора и штатный `pktmon` (Windows 10/11).
Wireshark не требуется. Python необязателен: без него сохраняются исходные ETL, PCAPNG и
полный текстовый hex-дамп; CSV можно получить позднее на компьютере с Python.

Оригинальный Recorder не выбирает адаптер сам и использует таблицу маршрутизации Windows.
Захват выполняется на всех сетевых картах, затем фильтруется по IP прибора. Файл `_route.txt`
фиксирует выбранный Windows интерфейс, его индекс и адреса. Утилита не меняет метрики и маршруты,
поэтому не искажает сравниваемый обмен.

## Что фиксируется

- только TCP-трафик выбранного IP и порта;
- точное время, направление, размер, TCP seq/ack и полный payload;
- Mebius-заголовок, task id, IOCTL-код и распознанная стадия;
- автоматическая сборка TCP-потока и распознавание инициализации, конфигурации, сброса/переподключения, старта, данных, служебных команд и останова;
- каждый запуск создаёт отдельный каталог `captures\IP_client_run_YYYYMMDD_HHMMSS_mmm`;
- все артефакты одного захвата находятся только внутри его каталога.

## Запись RecorderLnx

Самый простой запуск: дважды щёлкнуть `Start-Capture.bat` и подтвердить запрос прав
администратора. По умолчанию записывается `192.168.9.155:4000`. Другой IP можно передать
первым аргументом BAT-файла.

Утилита не задаёт вопросов. Имена отслеживаемых программ читаются из файла
`Mic185TrafficCapture.ini`, лежащего рядом со скриптом:

```ini
[Clients]
ProcessNames=RecorderLnx,Recorder
```

Расширение `.exe` можно не указывать. После начала захвата утилита ищет запущенный процесс по
этому списку. Если найдено несколько экземпляров, приоритет получает владелец TCP-соединения с
прибором. PID не хранится в настройках: он запоминается только для найденного экземпляра и нужен,
чтобы завершить захват при закрытии именно этой программы. Затем ETL автоматически преобразуется
в PCAPNG, CSV и отчёт стадий.

Перед первым рабочим прогоном можно запустить `SelfTest-Capture.bat`. Он открывает и сразу закрывает
тестовое TCP-соединение с прибором, записывает пять секунд и должен завершиться строкой
`SELF-TEST OK`. Recorder в это время должен быть закрыт. При ошибке отправить целиком самый
новый каталог из `captures`.

Альтернативный запуск из PowerShell:

```powershell
.\Capture-Mic185.ps1 -DeviceIp 192.168.9.155 -Client recorderlnx -RunName full_cycle
```

После старта выполнить нужные действия в RecorderLnx и закрыть приложение. Нажимать клавиши для
определения стадий или завершения не нужно: стадии восстанавливаются из Mebius-заголовков и
IOCTL-кодов, а финализация начинается после остановки процесса клиента.

## Запись оригинального Recorder

После восстановления прибора повторить тот же сценарий той же утилитой:

```powershell
.\Capture-Mic185.ps1 -DeviceIp 192.168.9.155 -Client original -RunName full_cycle
```

Для корректного сравнения использовать один прибор, одинаковую конфигурацию каналов и
одинаковый порядок действий. Остальные приборы могут работать: фильтр оставит только выбранный IP.

## Сравнение

На компьютере с Python:

```powershell
.\Compare-Mic185.ps1 `
  -ReferenceCsv .\captures\192.168.9.155_original_full_cycle_...\*_packets.csv `
  -ActualCsv .\captures\192.168.9.155_recorderlnx_full_cycle_...\*_packets.csv
```

Отчёт группирует команды по стадиям и показывает порядок соединений, IOCTL, размеры,
интервалы потока данных, повторы и первое расхождение исходящих payload.
