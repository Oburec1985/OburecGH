# RecorderCoordinator

## Резервное копирование RecorderLnx

Кнопка «Резервная копия» открывает диалог выбора каталога, рабочих мест и
состава: конфигурации, плагины, исполняемый файл. Подготовленные источники
отмечены заранее; остальные рабочие места видны с указанием, что источник не
настроен. Копирование выполняется в фоне, после него показывается результат
для каждого рабочего места.

Снимки размещаются как `<назначение>/<имя рабочего места>/<дата-UUID>/`;
повторное копирование не заменяет предыдущие снимки. Помимо файлов проекта и
настроек программы, в составе конфигураций сохраняются каталоги Calibr и SDB
и сведения об источниках. Неудачный снимок содержит `.backup-incomplete`.
На KIP1–4 изменение активного каталога проекта и Mera Files автоматически
обновляет read-only экспорты источников. rcPanel проверяет поколения и при
устаревшем CIFS-подключении ожидает переподключения; изменение источника во
время копирования приводит к ошибке. Внешние ресурсы вне опубликованных
каталогов не копируются. Межфайловая атомарность копии не гарантируется.

На Linux источники подключены в `~/.local/share/rcpanel-backup-sources/<IP>/`;
для используемых машин настроено отключение простаивающих монтирований через
10 секунд. На АРМ каталог назначения на NTFS сервера доступен как
`/home/user/Сеть/RecorderBackups`. NTFS и CIFS поддерживаются с правами,
заданными монтированием и сервером; программа выводит предупреждение, если
не может обеспечить приватные права POSIX. Копии могут содержать секреты.
Существующая конфигурация диска сервера допускает чтение другими локальными
пользователями. Новая версия запущенной панели применяется после перезапуска.
На других установках нужны настроенные экспорты Samba и включённые unit-файлы
`recorder-backup-exports.path` и `.timer`; пакет их доставляет, но автоматически
не настраивает уже существующие Samba-ресурсы.

## Черновик редактора хоста

Автоматическое обновление статусов не должно менять несохранённые адрес и
имя. Изменение поля отмечает черновик независимо от фокуса; программное
перезаполнение таблицы не является выбором пользователя. Проверка обязана
охватывать пустой список, несколько таймеров, смену фокуса, обнаружение нового
хоста и явное переключение строки. Подробности исправления:
`errors/2026-10-30-host-editor-draft-erased-by-refresh.md`.

## Версия приложения

Единственный источник версии rcPanel — `Core/uCoordinatorVersion.pas`.
Заголовок главной формы получает номер из этого модуля. Каждая функциональная
итерация, изменяющая код, LFM, конфигурацию или поведение rcPanel, обязана
увеличивать как минимум patch-компонент версии и завершаться forced-сборкой.

Утилита управления RecorderLnx и файловыми хранилищами. Один executable
работает как GUI, CLI или постоянный HTTP-сервис.

## Запуск

```text
RecorderCoordinator.exe
RecorderCoordinator.exe --serve --listen=0.0.0.0 --port=8765
RecorderCoordinator.exe --cli --status
RecorderCoordinator.exe --cli --list-hosts
RecorderCoordinator.exe --cli --command=start --host=<instance-id>
```

Настройки сохраняются рядом с executable в `RecorderCoordinator.ini`. Для SMB
на Windows допустим UNC-путь, на Linux — смонтированный CIFS-каталог. Пароли в
INI не сохраняются. SFTP предусмотрен моделью конфигурации, но транспортный
адаптер пока не подключён.

## HTTP API v1

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| GET | `/api/v1/status` | Состояние сервиса |
| GET | `/api/v1/hosts` | Список RecorderLnx |
| POST | `/api/v1/clients/hello` | Регистрация экземпляра |
| POST | `/api/v1/clients/heartbeat` | Состояние и путь текущего замера |
| POST | `/api/v1/events` | Старт/изменение события записи |
| GET | `/api/v1/events` | События записи |
| POST | `/api/v1/commands` | Поставить команду хосту |
| GET | `/api/v1/commands/next?instance_id=...` | Long-poll/poll команды |
| POST | `/api/v1/commands/result` | Результат команды |
| GET | `/api/v1/recordings/current?instance_id=...` | Путь текущего замера |

Перед синхронизацией RCPanel ставит каждому RecorderLnx команду `config.get`.
Ответ команды содержит необязательное поле `mera_files_path`; Coordinator
сохраняет полученный фактический путь и возвращает его в `/api/v1/hosts`.
Heartbeat остаётся сообщением только оперативного состояния.

Ожидаемые ошибки возвращаются JSON-кодом `result_code`; HTTP 400 используется
для невалидного JSON, HTTP 404 — для неизвестного endpoint.

## Автоматическое обнаружение в локальной сети

Coordinator/rcPanel и RecorderLnx обнаруживают друг друга через UDP broadcast,
после чего продолжают работу через штатный HTTP API. Coordinator принимает
discovery на UDP `38765`, RecorderLnx — на UDP `38766`; HTTP остаётся на TCP
`8765` (либо на порту из настройки Coordinator). Адрес в UDP-пакете не
доверяется: URL собирается из фактического IP отправителя и объявленного порта.

Полное описание протокола v1, жизненного цикла, диагностики и поведения при
сбоях: [LAN discovery](../RecorderLnx/Docs/setup/lan-discovery.md).

## Захват Recorder любой панелью

RCPanel 0.1.29 обнаруживает Recorder независимо от того, какая панель им
управляет. Выберите строку и нажмите **Захватить**. Состояние «подключён»
появится только после реального HTTP hello/heartbeat Recorder. Для занятого
Recorder кнопка называется **Перехватить** и требует подтверждения: прежняя
панель потеряет управление. **Освободить** завершает текущий захват. Запуск
Recorder через HostAgent также запрашивает захват; если процесс запускается
не сразу, панель повторяет запрос ограниченное число раз.

Идентификатор панели сохраняется в `[coordinator] instance_id` её INI.
Захват и его идентификатор являются runtime-состоянием, а не привязкой Recorder
к адресу панели. При наличии общего токена `[coordinator] auth_token` он должен
совпадать с AuthToken Recorder. Входящие объявления UDP сами по себе не дают
права отправлять команды. Каждая команда принадлежит конкретному захвату;
запросы старого захвата не выполняются после смены владельца.

Проверка этого контракта: `Tests/CoordinatorClaimSessionTest.pas` (чужой
владелец, смена сессии, отмена старых команд, постоянный ID панели).

## Связанные состояния доступности

Если проверка подтверждает недоступность всего компьютера, все runtime-службы
на этом хосте немедленно считаются недоступными. В частности, RCPanel обязан
одним обновлением выставить `pc_connection_state=unreachable` и состояние
Recorder `offline`; оставлять прежнее `recording/stopped` нельзя. Обратный
переход выполняется только по фактическому ответу соответствующей службы, а не
по одному успешному ping. Проверка закрепляется модельным тестом обоих полей.

В Windows Firewall для частных и доменных сетей должны быть разрешены входящие
подключения к соответствующим приложениям: UDP `38765` для rcPanel и UDP
`38766` для RecorderLnx. Для вручную запускаемой Windows-сборки rcPanel правило
можно создать от администратора:

```powershell
netsh advfirewall firewall add rule name="Mera rcPanel discovery" dir=in action=allow program="C:\path\to\RecorderCoordinator.exe" protocol=UDP localport=38765 profile=domain,private enable=yes
```
