# Пустой TCP preflight останавливал HostAgent в отладчике

## Симптом

После команды запуска RecorderLnx отладчик HostAgent показывал
`EHTTP: No REQUEST_METHOD passed from server`.

## Причина

Debugger-safe проверка доступности порта rcPanel выполняла TCP connect и сразу
закрывала сокет. `TFPHTTPServer` принял соединение, но не получил HTTP request
line и поднял ожидаемое для повреждённого запроса исключение.

## Исправление

Preflight после небросающего connect отправляет полный
`GET /api/v1/status HTTP/1.1` с `Host` и `Connection: close`, ограниченно ждёт
ответ и принимает только строку, начинающуюся с `HTTP/`.

## Проверка

RecorderCoordinator forced build Win64 — OK; пустого TCP connect в клиенте
больше нет. Полный стендовый клик проверяется после перезапуска обоих EXE.

## Повторная ошибка: второй connect

Первоначальная защита делала небросающий preflight, а затем открывала второе
соединение через `TFPHTTPClient`. Между этими действиями состояние порта могло
измениться, либо второе соединение могло истечь по тайм-ауту. В таком случае
`TFPHTTPClient` поднимал `ESocketError`; обработчик переводил его в callback,
но Lazarus всё равно показывал first-chance exception.

Клиент переведён на одну низкоуровневую HTTP-транзакцию: тот же неблокирующий
сокет подключается, отправляет GET/POST и читает ответ. Недоступность и тайм-аут
теперь формируются как строка ошибки без создания объекта исключения.
