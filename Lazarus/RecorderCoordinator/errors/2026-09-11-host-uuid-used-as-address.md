# 2026-09-11 — UUID Recorder использовался как сетевой адрес

## Дополнение: поздно появившийся адресный alias

Даже после очистки UUID из поля адреса дубль сохранялся, если UUID-строка
загружалась раньше, а строка `192.168.9.85 / kip4` регистрировалась позже.
Причина: слияние по одинаковому имени выполнялось только внутри загрузки
реестра. Теперь то же строгое правило применяется после hello/discovery:
одинаковое непустое имя, одна UUID identity без валидного адреса и одна запись
с валидным адресом. Регрессионный `CheckLateNamedAddressAliasMerges` — OK.

## Симптом

После ручного назначения `kip4` адреса `192.168.9.86` RCPanel при следующем
старте снова показывал UUID в поле адреса, а строка с IP исчезала или
появлялась повторно.

## Причина

- `RegisterHello` копировал `instance_id` в `Address`, когда endpoint не был
  передан. Для UUID это смешивало идентичность Recorder и сетевой адрес.
- При загрузке ручной строки с IP её адресный `instance_id` мог заменить уже
  известный UUID. Следующий heartbeat выполнял обратную замену.
- Поиск по адресу безусловно сравнивал запрос с `InstanceId`, включая UUID.

## Исправление

- UUID-подобные значения запрещены как сетевой адрес и больше не попадают в
  ping/HostAgent targets.
- UUID имеет приоритет над адресным alias и остаётся стабильным InstanceId.
- Добавлен `SetHostAddress`: меняет только адрес выбранной идентичности,
  объединяет существующий адресный alias и сохраняет реестр.
- Старые сохранённые UUID/address-дубли с одинаковым явным именем мигрируют в
  одну строку; сведения взаимно дополняются.

## Проверка

- `CoordinatorHostIdentityTest`: сценарий UUID без endpoint → ручной IP →
  сохранение → новый экземпляр модели → загрузка configured IP; после рестарта
  остаётся одна строка с исходным UUID и `192.168.9.86` — OK.
- Forced build `RecorderCoordinator.lpi` — OK.
