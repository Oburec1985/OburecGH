# RCPanel оставлял активное состояние Recorder у недоступного ПК

## Симптом

После отрицательной проверки доступности компьютера колонка связи показывала
`нет связи`, но состояние Recorder могло временно оставаться `recording`,
`stopped` или другим ранее полученным значением.

## Причина

`ApplyPcReachability` обновлял только `PcConnectionState`. Сохранённое runtime-
состояние Recorder не менялось до отдельного таймаута или сетевого обновления.

## Исправление

При подтверждённом отрицательном ping модель сразу устанавливает `State =
offline`. Поэтому одинаковое состояние получают таблица RCPanel и её HTTP API.
Положительный ping сам по себе не восстанавливает прежнее состояние: его должен
прислать реально запущенный Recorder.

## Проверка

- `CoordinatorHostIdentityTest` проверяет `pc_connection_state`, `state` и
  `recorder_state` — OK.
- Forced-сборка `RecorderCoordinator.lpi` — exit code 0.
