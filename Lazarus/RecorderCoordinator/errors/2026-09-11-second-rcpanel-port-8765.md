# Второй RCPanel сообщает, что TCP/8765 занят

## Симптом

При запуске RCPanel показывал диалог `TCP port 8765 is already in use`, после
закрытия диалога оставалась открыта ещё одна форма, внешне похожая на рабочую.

## Подтверждённые факты

- GUI вызывает `TCoordinatorHttpServer.Start` один раз из `FormCreate`.
- Проверка порта выполняется до создания listener-потока, поэтому собственный
  listener этого процесса ещё не может занимать порт.
- При занятом порте `Start` не создаёт listener, но прежний код всё равно
  оставлял вторую форму открытой.

## Причина

Запущен второй процесс RCPanel. HTTP API остаётся у первого процесса, а форма
второго процесса не имеет работающего входящего API и создаёт ложное ощущение,
что после предупреждения всё исправно.

## Исправление

До создания формы GUI получает межпроцессную блокировку `Mera.RCPanel`:
именованный mutex на Windows и неблокирующий `flock` на Linux. Если блокировка
уже принадлежит первому экземпляру, второй процесс пишет диагностическую строку
и завершается без формы и без попытки занять TCP/8765. CLI-команды блокировкой
не ограничиваются.

`WaitFor` и ожидание событий не используются.

## Проверка

- Forced-сборка RecorderCoordinator Win64 — OK.
- При последовательном запуске двух Win64 EXE второй завершился, активным
  остался ровно один процесс; в журнале записано
  `GUI start skipped: RCPanel is already running`.
