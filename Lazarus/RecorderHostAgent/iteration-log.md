## 2026-09-11 — диагностика выключения хоста 192.168.9.85

**Запрос:** проверить, почему установленный Linux HostAgent не выключает ПК,
не выполняя реальное выключение.

**Сделано:** по SSH подтверждены пакет 0.1.1, `allow_shutdown=1`, helper и
sudoers; обнаружено, что HostAgent отсутствует, а его порт 8766 унаследован
RecorderLnx. Для 0.1.2 дескрипторы дополнительно помечаются `FD_CLOEXEC` до
запуска дочернего процесса.

**Проверка:** `sudo -n -l` разрешает штатный helper; `/status` на захваченном
порту воспроизводимо зависает; forced Win64 build HostAgent — OK. Linux ELF
0.1.2 не собран: на проверяемом ПК нет `fpc/lazbuild`.

**Статус:** частично; закрыть удерживающий порт RecorderLnx, перезапустить
HostAgent и после Linux-сборки установить DEB 0.1.2.

## 2026-09-11 — RecorderLnx не наследует HTTP-сокеты агента

**Запрос:** устранить наследование listener и клиентских сокетов HostAgent
запускаемыми процессами RecorderLnx в Linux.

**Сделано:** перед Unix `exec` дочерняя ветка `TProcess` закрывает снимок всех
открытых дескрипторов, кроме stdin/stdout/stderr; родительский HostAgent
сохраняет владение listener. `WaitFor` не добавлялся.

**Проверка:** forced-сборка `RecorderHostAgent.lpi` Win64 — успешно. Linux
нужно пересобрать и проверить через `/proc/<pid>/fd` или `ss -lntp`.

**Статус:** частично: код готов, требуется проверка новым Linux ELF.

**Запрос:** второй запуск агента или занятый TCP 8766 не должен показывать необработанное `ESocketError` и crash-dialog.

**Сделано:** перед запуском HTTP-сервера добавлена небросающая проверка bind; занятый endpoint записывается в `RecorderHostAgent.log`, второй экземпляр штатно завершается с кодом 2. Редкая ошибка между проверкой и фактическим запуском также перехватывается на границе запуска.

**Проверка:** forced-сборка Win64; при работающем первом экземпляре второй завершился с code 2, остался ровно один процесс, `/api/v1/status` первого вернул HTTP 200, причина записана в лог.

**Статус:** готово.

## 2026-09-11 11:19 — запуск Linux-агента сразу после установки

**Запрос:** Найти причину, почему установленный в Linux launcher не запускает RecorderLnx и не сообщает об ошибке.

**Сделано:** установлено, что DEB включал user-unit только для следующего входа в систему. Postinst теперь запускает unit во всех уже активных пользовательских сессиях; unit пишет stdout/stderr в journal и содержит единый graphical-session lifecycle. Автономный install-linux.sh выводит команды запуска и диагностики.

**Проверка:** `build_deb.py` проходит `py_compile`; Linux DEB пересобран штатным `build-installer.bat`, ELF обоих приложений проверены упаковщиком.

**Статус:** готово; фактический запуск unit проверить после установки нового DEB на Linux.

## 2026-09-11 — Linux shutdown больше не даёт ложный успех

root-owned helper, точное sudoers-разрешение desktop-пользователю и проверка
exit status/output. `allow_shutdown` включается только после успешной настройки
этих прав. Версия HostAgent и DEB поднята до 0.1.1.

**Проверка:** forced Win64 build HostAgent, Python compile/generation postinst и
diff-check — OK; фактическое выключение намеренно не выполнялось.

**Статус:** код готов; Linux ELF и DEB 0.1.1 надо собрать и установить.
