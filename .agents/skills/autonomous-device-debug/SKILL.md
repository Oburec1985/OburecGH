# Автономная отладка устройств

Доводить аппаратный сценарий до наблюдаемого результата самостоятельно.

1. До изменения кода зафиксировать критерий готовности и фактический сбой.
2. Самому запускать и останавливать приложение, пробник, логирование и узкие
   диагностические команды. Не просить пользователя нажимать кнопки, закрывать
   приложение или пересказывать лог, если это можно выполнить доступными
   инструментами.
3. Для сетевого протокола сохранять стадию, endpoint, длительность, код ответа
   и полный текст ошибки. Пустая ошибка недопустима.
4. Делать одну причинную правку за итерацию. После неё повторять тот же сценарий
   и сравнивать результат с исходным.
5. Продолжать цикл `воспроизвести → собрать доказательства → исправить → собрать
   → запустить → проверить`, пока критерий готовности не выполнен.
6. Если GUI нельзя автоматизировать, использовать тот же production-клиент из
   минимального CLI-пробника; не писать альтернативную реализацию протокола.
7. При обрывах проверять восстановление: потеря связи, ограниченный backoff,
   повторное создание транспорта/сессии, повторная конфигурация и возврат
   данных без перезапуска приложения.
8. Остановиться только при доказанном внешнем блокере: недоступное питание,
   закрытый порт, требуемое физическое действие или отсутствие разрешения.
   Указать проведённые проверки и точное условие продолжения.
9. Перед сдачей закрыть временные процессы, выполнить обязательные сборки и
   записать в журнал фактическую проверку, а не только компиляцию.

Соблюдать границы разрешённой задачи: самостоятельная проверка не разрешает
перезагрузку или перенастройку чужого оборудования без явного согласия.
