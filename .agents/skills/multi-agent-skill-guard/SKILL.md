# Мультиагентный контроль skills

Основной агент остаётся владельцем задачи и кода. Отдельный агент-аудитор
проверяет процесс, но не подменяет реализацию и не редактирует те же файлы.
Когда он выполняет роль Тыжпрограммиста по `dreamteam`, основной агент может
выделить ему отдельный проход для правки только аннотаций в назначенных модулях
без параллельной записи этих файлов; аудит рабочего кода остаётся независимым.

## Обязательный порядок

1. Основной агент определяет применимые skills и полностью читает их сам.
2. До существенных правок он запускает ровно одного отдельного аудитора,
   передаёт список skills, цель и границы задачи. Редактирование файлов
   запрещено, кроме согласованного прохода аннотаций по `dreamteam`.
3. Аудитор сам полностью читает skills и проектные инструкции, формирует
   короткий список инвариантов и сообщает нарушения с `file:line`, риском и
   минимальным исправлением.
4. Основной агент делает работу. После правок он передаёт тому же аудитору diff
   или список изменённых файлов для повторной проверки.
5. Перед ответом основной агент исправляет подтверждённые нарушения либо явно
   обосновывает неприменимость правила.

Только основной агент создаёт аудитора. Аудитор не применяет этот skill к себе,
не создаёт агентов и не делегирует работу. На пользовательскую итерацию допустим
один аудитор; повторные проверки идут сообщениями ему же. Если слот недоступен,
основной агент выполняет чек-лист сам, фиксирует fallback и не зависает в
ожидании.

## Жёсткий контроль runtime-кода

В повторяющемся рабочем цикле запрещены строковый поиск и сопоставление
(`IndexOf`, `Contains`, `Find` по имени, обход списка со сравнением имён), разбор
NodeId/конфигурации и линейный поиск уже связанного объекта. При
`Init`/`Configure` имена один раз разрешаются в прямые ссылки, числовые ID или
индексы и предвыделенные таблицы. Runtime использует только их. Даже словарный
поиск по строке считается нарушением, если его можно заменить сохранённой
ссылкой или числовым ключом.

Аудитор также подтверждает:

- в цикле нет `Create`, изменения размеров массивов и других выделений памяти;
- сетевые данные читаются, обрабатываются и публикуются блоками;
- успешные элементы не логируются по одному: применяются счётчики и редкие
  агрегированные сообщения;
- измерены длительность и загрузка конкретного потока до и после изменения;
- новые потоки не используются для маскировки медленного алгоритма.

При нарушении задача не считается готовой без исправления или явно
зафиксированного внешнего ограничения.

## Границы

Аудит не расширяет запрос пользователя и не даёт новых разрешений. Независимые
реализации можно делегировать другим агентам лишь при непересекающихся файлах и
явных проектных основаниях.
