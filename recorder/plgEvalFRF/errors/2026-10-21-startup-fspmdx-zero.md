# 2026-10-21 Падение плагина при старте: деление на fspmdx = 0

## Симптом

Плагин plgEvalFRF падает при старте Recorder (до любых измерений).
Стек: `PluginClass3218.TplgEvalFrf.Notify` -> `cFRFFactory.doRecorderInit` ->
`cFRFFactory.CreateBands`, точка останова на строке
`b.m_f1i := trunc(b.m_f1 / t.cfg.fspmdx) + 1;`.

## Воспроизводимый сценарий

1. Сборка Debug, запуск Recorder с плагином.
2. Плагин инициализирует форму FRF и читает сохранённые настройки (gui_file).
3. `doRecorderInit` вызывает `CreateBands`, где и происходит исключение.

## Подтверждённые факты

- Строка деления находится внутри `if t <> nil then`, то есть `t` не nil.
- `cSRSTaho.getCfg` возвращает nil только при пустом списке конфигураций; если бы
  cfg был nil, раньше упал бы `t.cfg.SRSCount` в том же `doRecorderInit`.
- Значит cfg существует, а `fspmdx = 0`: `TFRFFrm.UpdateBlocks` считает его как
  `lt.WorkFreq / c.m_fftCount`, и при неразрешённом тахо-теге (`getTagByName` = nil,
  тег из сохранённых настроек отсутствует в базе) `WorkFreq = 0`.
- Delphi (CW = $1332) не маскирует деление на ноль, поэтому `x / 0` даёт EZeroDivide,
  а не Inf. Исключение выходит из DLL-плагина как необработанное.
- Та же незащищённая схема была ещё в трёх местах: `GetSelectValue` (курсор по
  графику), обработчик курсора (`trunc(x1 / s.cfg.fspmdx)`) и сохранение отчёта
  (`saveHeader(ifile, 1 / c.fspmdx, ...)`).

## Отвергнутые гипотезы

- «cfg = nil»: противоречит тому, что предыдущий обход `t.cfg.SRSCount` прошёл.
- «Ошибка в CreateBands при добавлении полос»: полосы добавляются до деления,
  исключение возникает именно на делении.

## Первопричина

Разрешение спектра `fspmdx` вычисляется как `WorkFreq / m_fftCount` без проверки
исходных значений. При незаданной/ненайденной частоте тахо оно равно 0, а код
делит на него без проверки (в CreateBands, GetSelectValue, обработчике курсора,
сохранении отчёта).

## Исправление

- `TFRFFrm.UpdateBlocks`: выход при `lt = nil` / `cfg = nil`; `fspmdx` считается
  только при `m_fftCount > 0` и `WorkFreq > 0`, иначе 0; FFT-план — только при
  `m_fftCount > 0`.
- `cFRFFactory.CreateBands`: обход сигналов только при `t.cfg <> nil`; индексы полосы
  считаются только при `fspmdx > 0`, иначе 0 (реальные индексы пересчитываются при
  отрисовке через `GetLowInd` в `TFRFFrm.UpdateBandNames`).
- `TFRFFrm.GetSelectValue` и обработчик курсора: не делить при `fspmdx <= 0`.
- `saveHeader(ifile, SpmStep(c.fspmdx), ...)`: новая функция `SpmStep` возвращает
  0 вместо деления на ноль.

## Перепривязка тегов (корневая причина fspmdx = 0)

На момент `LoadSettings` теги Recorder ещё не созданы, поэтому `m_tag.tag` у тахо и
у сигналов остаётся nil, `WorkTag` = nil, `WorkFreq` = 0, `fspmdx` = 0.

Добавлено:

- `procedure RebindTag(tag: ctag)` — перепоиск по имени. Принудительно присваивает
  `tag.tagname := tag.tagname`, чтобы сработал `cTag.settagname` и заново нашёл тег.
  Вызывается только если тег уже есть в базе (`getTagByName <> nil`): иначе сеттер
  при непустом `tag` пытается ПЕРЕИМЕНОВАТЬ старый тег.
- `TFRFFrm.RebindTags` — проходит по `m_TahoList`, для каждого тахо привязывает
  `m_tag`, затем по всем его конфигурациям (`CfgCount`/`getCfg`) и их сигналам
  (`SRSCount`/`GetSrs`). Идемпотентна: уже привязанные теги сеттер пропускает.
- В `cFRFFactory.doRecorderInit` вместо ручного `tag := getTagByName(...)` вызывается
  `TFRFFrm(Frm).RebindTags`, после чего при наличии тахо — `UpdateBlocks`

## Остаточный риск

- Проверено структурно (баланс begin/end, разбор диффа); полная сборка плагина
  выполняется в IDE и здесь не воспроизводилась.
- Если частота тахо не определяется, графики спектра остаются без шага по частоте
  (индексы полос = 0), пока тег не будет сопоставлен в настройках прибора.
- Привязка выполняется один раз в doRecorderInit. Если тег появляется в базе позже,   нужен повторный вызов `RebindTags` (например, при смене состояния Recorder) -   метод идемпотентен и пригоден для повторного вызова.
